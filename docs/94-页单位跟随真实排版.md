# 94 · 页单位跟随真实排版（屏幕侧自适应）

## 需求

「这个功能能自动适配显示器吗」——查下来，点显器侧早就是驱动上报的方数（`numTextCells`，真机 30 方），但**屏幕侧写死**：`DEFAULT_CELLS = 40`、`LINES_PER_PAGE = 20`，页单位恒为 800 格，既不跟屏幕宽窄，也不跟「字号」按钮、横竖屏联动。结果同一本书两套口径：屏幕页码 4,895 页（≈798 字/页），点显器一屏却只有 30 方。

## 改动

`brailleback/.../compose/BrailleReaderScreen.kt`

- 正文区挂 `Modifier.onSizeChanged` 拿到实际可用像素宽高。
- 用 `rememberTextMeasurer()` 在当前字号下量一个汉字"汉"的宽与行高（`MaterialTheme.typography.bodyLarge.copy(fontSize = uiState.fontSizeSp.sp)`）。
- `LaunchedEffect(textArea, fontSizeSp)` 里算出「一行能排几个字」「能排几行」，夹到 8–400 字 / 2–80 行后通过 `onTextMetrics` 回调交给 Activity。字号、横竖屏、分屏变化都会自然重测。

`brailleback/.../BrailleReaderActivity.kt`

- 新增 `onScreenTextMetrics(charsPerLine, linesPerPage)`：
  - 明眼原文（`ReaderSourceKind.TEXT`，屏显是汉字）→ `cells = 字数 × CELLS_PER_SOURCE_CHAR(2.5)`，因为通用盲文一个汉字平均占约 2.5 方，这样屏幕刚好被一页正文铺满；
  - 盲文源（BRF/BDO，屏显是点字）→ 一字一方，直接用字数；
  - 夹到 `8..1000` 方 / `5..80` 行；
  - 与现值不同才动作：写回 `mCellsPerLine` / `mLinesPerPage`，`rebuildPageOffsets(keepPosition = true)` 重建页表（**阅读位置不动**），再 `showPage()`。
- 日志 `screen metrics: chars=… lines=… -> cells=… lines=… unit=…`。

## 验证（真机 2,400×1,080）

```
16:51:25 screen metrics: chars=18 lines=30 -> cells=18 lines=30 unit=540   # 打开前，盲文源口径
16:51:27 screen metrics: chars=18 lines=30 -> cells=45 lines=30 unit=1350  # 载入 txt，TEXT 口径 ×2.5
16:51:27 screen metrics: chars=18 lines=22 -> cells=45 lines=22 unit=990   # 按钮区排好后收到 22 行
16:53:59 translate end: paragraphs=12169 chars=3907921 invalidCells=0
16:53:59 translate done: paragraphs=12169 failedAt=0 units=3954
```

- 竖屏判定 18 字 × 22 行 → 每页 990 方（约 396 汉字），整本 **3,954 页**；改之前是 800 方 / 4,895 页。
- 转横屏实测 `chars=42 lines=12 -> cells=105 lines=12 unit=1260`（横屏可排 42 字一行）。
- 阅读位置（进度记忆 3216）在重建页表前后不变。
- 全量单测 `brailleback 955 例 / service 226 例` 全过。

## 取舍与未做

- `CELLS_PER_SOURCE_CHAR = 2.5` 是经验值（这本书实测 3,907,921 方 / 1,545,748 字 = 2.53）；现行盲文（2 方/字）的书会显得页偏大，屏幕少显示几行。
- 极窄/极矮布局（横屏分屏只剩三四行）兜到 5 行，宁可屏幕少显示几行，也不让页码涨到一两万页。
- 页单位变化会让总页数、目录分组变化，但当前位置保持。
- **仍未自动**：多行点显器的行数（`BrailleDisplayProperties` 只有 `numTextCells`，行数只能从驱动 HID 协议/厂商字段读）；同一次连接内驱动改方数（缩放）不一定有回调。
