# 26-裸线程与执行器收编

> 日期：2026-11-15
> 目标：把「直接 `new` 线程」的地方收成协程，同时记录三项候选里为什么只有这一项能落地
> 结果：`Thread(` 命中 14 → **12**，`Executors.` 1 → **0**

---

## 先记三次否决（免得下次又从头摸）

| 候选 | 结论 | 原因 |
|:---|:---|:---|
| `Log.x` → `Timber`（163 处） | **不做** | `Timber` 走 `LogUtils`，而 `LogUtils` 有 `sLogLevel` 过滤，debug 包最低 INFO。`Log.d` 换过去会被静默吞掉；另外 `LogUtils` 用 `String.format`，文案里带 `%` 会格式坏。要统一得先改日志级别策略，那是另一个决定 |
| `synchronized` → `Mutex`（45 处） | **不做** | 其中大半是 Kotlin 自己的 `synchronized(lock) {}` 内联函数（`RefreshGate`、`DisplayClient` 等），不是 Java 写法；剩下要换 `Mutex` 必须在 suspend 上下文，非 suspend 老代码里换不了 |
| `Thread(` → 协程（14 处命中） | **只做 2 处** | 多数命中是类名与构造：`ReadThread : Thread()`、`DriverThread(...)`、`HandlerThread("DriverTrhead"/"DisplayManager")`。`ReadThread` 是架构性的独立读线程；`DisplayManager` 的 telemetry 线程被契约锁着（display 线程卡死时它仍要出日志） |

---

## 改了什么

### 1. `CustomLabelManager`：单线程执行器 → `limitedParallelism(1)`

原来是一个 `Executors.newSingleThreadExecutor` 加裸线程工厂，再 `asCoroutineDispatcher()`：

```kotlin
private val mLabelExecutor = Executors.newSingleThreadExecutor { runnable ->
    Thread(runnable, "custom-label").apply { isDaemon = true }
}
private val mLabelDispatcher = mLabelExecutor.asCoroutineDispatcher()
private val mLabelScope = CoroutineScope(SupervisorJob() + mLabelDispatcher)
```

现在：

```kotlin
private val mLabelScope = CoroutineScope(SupervisorJob() + Dispatchers.IO.limitedParallelism(1))
```

串行语义不变（`limitedParallelism(1)` 保证同一时刻只有一个任务），
省掉一个 `Executor`、一个裸线程和两个中间字段；回调仍在 `withContext(Dispatchers.Main)` 投递。
`shutdown()` 走的是 `mShouldShutdownClient` + `mRunningTasks` 计数，本来就没依赖执行器的 `shutdown()`。

### 2. `UsbDisplayConnection.disconnect()`：停机线程 → 协程

`DriverThread.stop()` 要 join 最多 1 秒，不能在主线程做。原来临时起一个 `Thread("UsbDriverStop")`：

```kotlin
Thread(object : Runnable {
    override fun run() {
        dt.stop()
        notifyDisconnected()
    }
}, "UsbDriverStop").start()
```

现在走类内的 scope：

```kotlin
private val mScope = CoroutineScope(SupervisorJob() + Dispatchers.IO)
...
mScope.launch {
    dt.stop()
    notifyDisconnected()
}
```

`notifyDisconnected()` 内部仍然 `mHandler.post` 回主线程，回调线程不变。

---

## 没动的

- `ReadThread : Thread()`：它自带 `HandlerThread` 与驱动线程，是「独立读线程」的设计，不是临时起线程
- `DriverThread` 与 `DisplayManager` 的 `HandlerThread`：需要自己的 `Looper`，且 telemetry 线程有契约保护
- `CustomLabelManager` 的线程名 `custom-label` 随执行器一起去掉了；它只影响线程 dump 里的名字
