# 30 · 电子书格式支持

> 2026-11-15。阅读器从「只收盲文与纯文本」扩到能直接打开 EPUB / HTML / Markdown，
> 统一走现有的「明眼文字 → 盲文」翻译链路。

## 1. 改动前的边界

| 格式 | 之前 | 说明 |
|:---|:---|:---|
| `.bdo` / `.bdoc` | 支持 | Bword 二进制盲文，`BdoCArchiveParser` 结构化解码 |
| `.brf` / `.brl` / `.txt` | 支持 | 文本解码 + ASCII 盲文转换 / 明眼文字翻译 |
| `.epub` | **不支持** | 在 `UNSUPPORTED_EXT` 里，直接打开会提示「不支持」 |
| `.pdf` / `.doc(x)` / `.mobi` / `.azw3` | 不支持 | 仍需外部工具先转盲文 |

EPUB 是 zip 容器，按文本直接解码只会得到二进制乱码，所以之前只能一刀切拦掉。

## 2. 新增的三种格式

新文件 `EbookTextExtractor.kt`（纯 Kotlin，无 Android 依赖）：

| 后缀 | 处理方式 |
|:---|:---|
| `.epub` | 解 zip → `META-INF/container.xml` → OPF → 按 spine 顺序取各章 XHTML → 纯文字 |
| `.html` / `.htm` / `.xhtml` / `.xht` | 去标签、解码实体、按块级元素断行 |
| `.md` / `.markdown` | 原样作为文字（保留空行） |

阅读器 `loadBytes()` 里先分派：

```
EbookTextExtractor.supports(name)
  ├─ 是 → extract() 取文字 → detectKind() → 明眼文字走翻译链路
  └─ 否 → BrailleFileDecoder.decodeDocument()（bdo 二进制 / brf 文本）
```

EPUB 与 HTML 提取出的都是明眼文字，后面的翻译、分页、点显器输出与原 txt 电子书
完全同一条路，没有第二套排版代码。

## 3. EPUB 解析细节

1. **只读需要的条目**：`ZipInputStream` 顺序读，单条上限 16 MB、整本上限 128 MB，
   超限直接返回 `TooLarge`，防 zip 炸弹。
2. **容器入口**：`META-INF/container.xml` 里第一个 `rootfile` 的 `full-path`；
   缺失时退而找任意 `.opf`，再找不到才算无效 EPUB。
3. **OPF 用属性正则解析，不用 DOM**：
   `item`（id / href / media-type）与 `itemref`（idref）都是机器生成的简单标签。
   用正则 `<[\w:]*item\b[^>]*>` 取标签、再按属性名抓值，避免 `getElementsByTagNameNS`
   在命名空间/解析器实现上的差异（第一次实现用 DOM 时单测直接拿到空清单）。
4. **路径归一化**：href 去 `#fragment`、百分号解码、按 OPF 所在目录拼相对路径，
   再折叠 `./` 与 `../`。
5. **章节顺序**：优先按 spine；spine 为空时退回清单里所有 HTML 条目。
6. **HTML 清洗**：删注释、`script`/`style`/`head` 整块删除；`br`、`p`、`div`、
   `li`、`tr`、`h1-h6` 等块级标签换算行；去剩余标签；解码 `&lt; &gt; &quot; &apos;
   &nbsp; &amp;` 与 `&#xNN;` 数字实体；连续 3 个以上换行压成 2 个。
7. **编码**：zip 条目文字复用 `BrailleFileDecoder.decode()`——BOM → 严格 UTF-8 →
   GBK 回退，中文 EPUB 不会整篇乱码。

## 4. 用户听到的失败提示

失败原因是 sealed 类型，阅读器分别播报，不是一句笼统的「打开失败」：

| 原因 | 文案 |
|:---|:---|
| `EmptyFile` | 这个文件是空的 |
| `NotEpub` | 不是有效的 EPUB 电子书（缺少 container.xml 或 OPF 清单） |
| `NoText` | 这本电子书里没有可读的文字（可能只有图片） |
| `TooLarge` | 电子书体积过大，已停止解压（上限 128 MB） |

书架列表也补了三种类型标签：EPUB 电子书 / 网页文档 / Markdown 文档。

## 7. 边界与后续

- 有 DRM/加密的 EPUB 解不出文字，会报 `NotEpub`（zip 结构在、章节内容加密）；
- EPUB 里的图片、公式图片、固定版式（PDF 转出的 EPUB）不还原，只取文字；
- EPUB3 的 nav 文档若在 spine 里，目录页文字会跟正文一起出现（可后续按 `properties="nav"` 跳过）；
- `pdf` / `doc(x)` / `mobi` / `azw3` 仍在 `UNSUPPORTED_EXT`，需要外部转换；
- 整本书一次性翻译，超大长篇的开卷耗时会随字数增长（与 txt 电子书一致）。
