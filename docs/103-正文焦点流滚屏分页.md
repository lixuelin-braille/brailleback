# 103 - 正文改成焦点流：滚屏即分页

## 需求

读屏焦点一段一段往下滑（正文每段一个焦点）。滑到本页最后一段时希望**继续滑就是下一页**——
不要额外的「下一页」焦点节点，也不要双击。

## 硬约束（先说清楚，免得再试一轮）

- Compose **没有读屏焦点回调**：`onFocusChanged` 只响应输入焦点，TalkBack 移动焦点不触发，
  所以无法在「焦点停在最后一段」那一刻被动感知。
- 也没有 API 能让读屏焦点在翻页后程序化跳到新页第一段。

推论：只要正文里「最后一页的最后一段之后没有节点」，焦点就必然停死在那里。
唯一确定有效的办法是**让后面本来就有节点**——即把正文做成一整条可滚动的焦点流。

## 做法

1. **正文换成 `LazyColumn`**（Compose 里的 RecyclerView）：一段一项、一项一个焦点，
   只有可见项参与组合与测量，长书不会一次铺出上百个节点。
   `itemsIndexed(segments, key = { index, _ -> index })`——窗口是往后续的，已有项下标不变。
2. **窗口 = 本屏 + 后面两页**（`WINDOW_PAGES = 3`）。第一页从**视口首行**（`viewStart`）起，
   保证硬件键逐行 / 长按翻页仍是「整屏上移一行」；后面各页从各自页首起，各段带 `pageIndex`。
   `ReaderSegment(text, pageIndex)`。
3. **滚屏即分页**：`snapshotFlow { listState.firstVisibleItemIndex }` → `onTopSegment(index)`
   → 段所属 `pageIndex` 与当前页不同时，`mOffset` 切到那一页页首、重算本页行表、
   更新页码/播报/点显器/进度。**不重建段落**，否则滚动位置会被顶回去、跟手指抢。
4. **窗口续装**：首可见项离已加载末尾不到 4 项时 → `onNeedMoreSegments()` 再补一页。
   焦点于是可以一直滑下去，页码一路前进，到全书末尾自然停住。
5. **`scrollToken`**：只有用户显式换页/跳行/换字号（`showPage(resetScroll = true)`，默认就是 true）
   才让列表 `scrollToItem(0)`。滚屏自己的页号变化不碰 token。

## 踩过的坑

- **不能给 `pointerInput` / `items` 之外的 key 漏掉**：`ComposeListKeyContractTest` 钉死「每个
  `items` 必须显式 key」，漏了会直接抛 `Key was already used` 崩屏。
- **页表随翻译推进重建 → 窗口重铺 → 列表 index 错位**：一开始窗口重铺时不回顶，列表按 index
  保持位置，而 index 0 对应的页已经从 29 变成 26，于是 `onTopSegment` 把页号往回拽，
  日志里出现 `scroll page: unit=26` / `unit=28` 这种自发跳页。改成重铺一律回顶（窗口首项
  就是当前视口首行，回顶视觉上不跳）后消失。

## 代价（已知、明确的）

- 滚动时「第 N 行 / 共 M 行」里的 N 不再逐行跟随：滚屏只按页走，换页后行号归 1。
  行滑块本身仍能拖、仍能把视口切到该行。
- 点显器推送跟着「页」走（页首 offset），不再按屏幕行粒度推。
- 一页的行数仍是 19 行（一屏），但屏幕可滚动的正文比一屏略多（多出来的是后面页的段）。

## 验收方式

真机上：打开的正文滑到最后一段后继续往下滑/下一个焦点 → 内容接着往下走，
页码跟着变大（`scroll page: unit=…`），不再停在页末。
