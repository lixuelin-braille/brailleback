## 1. 先读：用户视角的排障顺序

接好点显器却连不上时，很多人第一反应是线坏了。实际顺序反过来更省事：

**先怀疑权限，再怀疑 OTG 和自动关闭，然后才是 USB 默认用途，最后才查线和供电。**

固定四步，按顺序走：

1. 应用权限与无障碍受限设置。
2. OTG 开关与闲置自动关闭。
3. USB 配置的默认用途。
4. 线材、转接头与供电。

一句话引子：**你这台机器，先怀疑供电、再怀疑转接头、最后才是权限。** 但排障动作从权限开始，因为权限问题最容易被绕过去，也最常被忽略。

## 2. Google 平台层：三条侧载限制

### 2.1 Play Protect 会直接拦截安装

对「从互联网侧载来源安装」、且声明了敏感权限的安装包，Play Protect 会直接拦截安装。这不是可以忽略的警告，是装不上去。

会被盯上的权限包括：`ACCESSIBILITY`、`NOTIFICATION_LISTENER`、`RECEIVE_SMS`、`READ_SMS`。

本应用是无障碍工具，必然声明无障碍相关权限；侧载时被 Play Protect 拦截属于已知路径，不代表安装包损坏。

来源：`developers.google.cn` 的 `android/play-protect/warning-dev-guidance`。

### 2.2 Android 13 起的 restricted settings（受限设置）

从 Android 13 开始，以非会话方式侧载的应用（不是商店或 `PackageInstaller` 会话装的），`ACCESS_RESTRICTED_SETTINGS` 初始为拒绝。

表现是：无障碍服务在系统设置里根本开不了，开关不响应。

开通路径：应用信息页 → 右上角三点 →「允许受限设置」，过完身份验证后，无障碍服务才允许被开启。

来源：esper.io 关于 Android 13 侧载限制的分析。

### 2.3 Android 开发者验证

按 Android 官方安排：

- 2026-09-30 起，在巴西、印尼、新加坡、泰国，由参与商店要求开发者注册。参与商店包括 Google Play、荣耀、OPPO、三星、传音、vivo、小米应用商店。
- 未注册的应用只能走 ADB，或走「高级流程」：一天等待 + 生物识别 + 7 天或永久开关。
- 2027 年起全球生效。

来源：`developer.android.google.cn/blog/posts/android-developer-verification-*` 与 `developer.android.com/developer-verification/guides`。

### 2.4 合规注意

`isAccessibilityTool="true"` 必须如实填写。本应用确实为残障用户服务，这个标注成立；若在不满足条件的应用上标成无障碍工具，会按「误导性无障碍工具」被拦。

## 3. 厂商层：分品牌要开的项

下面一条一个品牌，先写要开哪项，再写路径或可用的引导 Intent。厂商系统版本不同，菜单名可能略有出入。

### 小米 HyperOS

- 自启动默认关闭。需要手动允许自启动。
- 引导 Intent：`miui.intent.action.OP_AUTO_START`（官方 FAQ 提供）。
- 另有 OTG 开关；闲置约 10 分钟后会自动关闭 OTG，重插一次即可恢复。

### OPPO / 一加 / realme（ColorOS）

- 有「应用速冻」：后台约 5 分钟未使用就触发速冻。
- 「允许自启动」和「允许关联启动」开任意一个，就免于速冻；两个全关，速冻才生效。
- 另外还要开「允许后台运行」。

### 华为 / 荣耀

- 应用启动管理有三个开关：自启动、关联启动、后台活动。
- 电池策略分三档，按后台使用强度选。
- 长时间后台需要「长时任务」加常驻通知，两者一起才稳。

### vivo

- 开自启动。
- 加进后台高耗电白名单。

### 三星 One UI

- 接近原生，厂商限制少。
- 主要坑在「USB 配置默认用途」：连接后默认走了别的 USB 用途，点显器通道拿不到。

### 原生 AOSP

- 一次 USB 授权即可；授权时可勾选「默认打开此设备」，以后不再重复弹窗。

## 4. 给盲人用户的分步指引

每步一句话，可直接朗读。先权限、后 OTG、最后才查线与供电。

1. **先开权限。** 到应用信息页，看无障碍开关能不能开；被受限设置挡住时，走右上角三点 →「允许受限设置」，过完验证再回来开无障碍。
2. **再查 OTG。** 小米等机型先确认 OTG 开关是开的；闲置十分钟以上自动关了，重插一次。
3. **看 USB 默认用途。** 三星这类接近原生的机型，确认连接后 USB 配置没有默认跳到别的用途。
4. **最后查线和供电。** 换一根数据线，换一个转接头，换一个供电口；转接头是最常出问题的一环。

## 5. 为什么开不起来：四种成因与判定顺序（平台级，不按厂商）

判定只依赖两样信号：系统 API 级别 + 本地 `isEnabled` 历史（`everEnabled`）。**受限设置与厂商无关，是 Android 13 起的平台能力；厂商差异只体现在自启动 / 加锁 / OTG 这些步骤上。** 不允许按 `Build.MANUFACTURER` 分支去决定受限设置、被清理、高级保护这三类文案。

按下面四步判定，命中即停：

1. **服务从未开启（NEVER_ENABLED）**
   - 信号：`AccessibilityManager.getEnabledAccessibilityServiceList()` 里没有本服务，且用户当前不在无障碍设置页。
   - 动作：跳无障碍设置；文案「请开启本应用的盲文服务」。
2. **受限设置挡住（RESTRICTED_SETTINGS，Android 13+）**
   - 信号：刚从无障碍设置返回，`isEnabled` 仍为 false，系统 ≥ API 33。
   - 动作：跳应用信息页；文案必须含「右上角三点 → 允许受限设置 → 输入锁屏密码」。
3. **被系统清理 / 重启后关闭（CLEANED_BY_SYSTEM）**
   - 信号：本地记录过 `everEnabled=true` 的历史，之后读回 false。
   - 动作：文案「重启或清理后台后系统可能已把它关掉，请重新开启，并在多任务界面给本应用加锁」；华为、荣耀必出，其他家作为通用兜底。
4. **疑似高级保护模式（AAPM_SUSPECTED，Android 16+）**
   - 信号：API ≥ 36，且第 2 步反复失败（连续 ≥2 次）。侧载被拦、「安装未知应用」开关变灰、无障碍只放行「已验证的无障碍工具」都属于这类迹象。
   - 动作：App 无法程序化检测 AAPM，这一档只给文案并标 `UNKNOWN`，不许装成已知状态。

## 6. 功能状态：侧载自检与引导（已实现）

已在分支 `feat/oem-selfcheck` 落地：开机或连接失败时，应用自动检测当前状态，播报问题，并给出可点的跳转入口，用户不用自己在设置里翻路径。

覆盖项：无障碍服务（按第 5 节四成因判定）、USB 权限、自启动 / 后台、电池优化，以及厂商 Profile 声明的加锁 / OTG 步骤。各家候选组件、独有坑与不可直达步骤见《120 按厂商适配矩阵与跳转表》。

验收判据（写成可测）：判定顺序由单测锁死；七家 Profile 的 Intent 选择与全候选失败回落由单测覆盖；真机档位取证记录在 120。
