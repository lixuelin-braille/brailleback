# 78 · P2-2 多行三段式失败：定位与修复

> 日期：2026-11-24　提交：`8a9d28a`　环境：AVD `brailleback_api35`（Android 15 镜像，负载 ~10）
> 关联：[75](./75-模拟器全面功能测试报告.md) / [76](./76-模拟器补测与修复验证报告.md) 的 P2-2、[77](./77-项目总体方案-从离线全绿到真机可用.md) 阶段 1 第 1 条

## 1 结论

P2-2 是**三层叠加**的线程与启动问题，不是图形算法问题。修完后 40×4（8 点 / 6 点）、20×4 都能成书，
单行视口支路逐字节不变。真实点显器仍未验证。

## 2 三层根因

### 2.1 第一层：翻译客户端建在没有 Looper 的线程上

`TactileStripCaptionBridge` 原来在 `Dispatchers.IO` 线程里直接 `new TranslatorClient(...)`。
`TranslatorClient` 构造函数内部 `Handler()`，Android 会抛

```
Can't create handler inside thread Thread[DefaultDispatcher-worker-*,5,main]
that has not called Looper.prepare()
```

单行走 `buildViewport`，不碰翻译桥，所以「单行能出、多行必败」。这与 76 号文 §4.2 推断的
「封面 / 封底翻译桥在无翻译服务时抛错」方向一致，但真实异常类型是 Looper 缺失。

### 2.2 第二层：修了 Looper 后暴露自锁

改成自带 `HandlerThread` 后，`onInit` 仍然 10 s 超时。原因是 `TranslatorClient` 的 onInit 会
`post` 到**构造它的那条 Handler 线程**，而桥线程当时正阻塞在 `initLatch.await()` 上等 onInit
——回调排在阻塞任务之后，永远轮不到执行，形成自锁。

修法：等待移到**调用线程**（`awaitInit()`），桥线程只执行「解析表 + 翻译 + 销毁」，不等待。

### 2.3 第三层：翻译表每次冷启动全量重解压

`ZipResourceExtractor` 只有 `// TODO: Add versioning support`，没有版本校验：
`:service` 每次进程启动都把 `app_translator` 重写一遍（实测 486 个文件、20 MB）。
模拟器负载 ~10 时这一步约 13 s，`TranslatorService.onInit` 因此迟到，`setCallback` 只能挂在
`mPendingCallbacks` 里等解压结束。

修法：`app_translator/.extract-marker` 记 `versionCode:lastUpdateTime`。
同版本且目标文件尺寸与原条目相等 → 跳过重写，只走 zip 迭代；标记不一致或读不到版本 → 仍全量解压。
表内容随 APK 版本固定，跳过不改变输出字节。

## 3 改动清单

| 文件 | 改动 |
|:---|:---|
| `tactile/TactileStripCaptionBridge.kt` | 客户端创建 / 表查询 / 翻译 / 销毁全部在专用 HandlerThread；`awaitInit()` 在调用线程等 onInit；初始化超时 3 s → 10 s → **20 s**，单次翻译 5 s；`close()` 幂等 |
| `tactile/TactileStripSession.kt` | 封面 / 封底翻译失败降级为**空封面 / 空封底**，图形带照常成书；读图、解码、切片失败仍抛 |
| `utils/ZipResourceExtractor.kt` | 新增 `.extract-marker` 版本戳与同尺寸跳过；诊断日志（提交 / 完成 / 重写文件数） |
| `translate/TranslatorService.java` | 三行 I 级日志：`setCallback` 是否挂起、`onPostExecute` 结果、`callPendingOnInits` 挂起数 |

## 4 验证记录（安装后首次冷启动即测，不给服务预热）

| 版面 | 结果 | 页数构成 | 封面 / 封底 |
|:---|:---|:---|:---|
| 40×4，8 点 | `stage=book` | 6 页：封面 + 3 带 + 封底 | 均翻译成功 |
| 40×4，6 点 | `stage=book` | 7 页：4 带 | 均翻译成功 |

| 40×1，8 点 | `bind=viewport` | 单行视口 | 不涉及 |

- 解压标记生效后：`reuseExisting=true 重写文件=0`，init 从 13 s 降到 2 s 内。
- 单测：`brailleback` + `service` 1132 例，0 失败（14:10 重跑）。
- 未验证：真实点显器、TalkBack 朗读、触感边界、G1 封面分层在新链路下的表现。

## 5 残留

1. **每次 APK 更新后的第一次转换仍要等 13 s 左右**（全量解压）。要在产品层面消除，得让
   `TranslatorService` 在应用进程启动时就预热（现在只在首次需要翻译时才冷启动），属于阶段 3 的事。
2. 封面失败时用户只会看到「没有封面」，界面上没有任何提示；TTS 状态行仍会播报「第 N/M 带」。
   是否加一句「封面文字未翻译」需要产品定。
3. P1-2 阅读器逐格重复汉字（`ReaderSourceModel.kt`）未修，等你的授权。
