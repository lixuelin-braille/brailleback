# 连续滚屏：视口首行跟着光标走

## 想法

用户问：能不能在保留页码、章节的基础上做成滚屏。可以，而且不用动页表——
因为"页"本来就不是独立计数，而是由 offset 反查出来的。

关键事实（改动前就在代码里）：

- `currentUnit()` = `unitForOffset(mOffset)`，页号是页表里"不超过 offset 的最后一个页起点"，
  二分反查。offset 动，页号自动跟。
- `screenAt(stream, offset, cells, lines)` 本来就接受任意 offset，能从那一点起铺一屏。
- 进度保存存的是 offset（`KEY_OFFSET`），不是页号。
- 章节来自标题扫描，与页表无关。

所以滚屏只需要换一个东西：**屏幕从哪一行开始铺**。

## 改法：视口首行 = 光标所在行

`showPage()` 的顺序调整为：

1. `pageStart` = 本页页首，`pageEnd` = `nextOffset(pageStart, unit)`（截到词边界）；
2. `mPageLineStarts` = `lineStarts(pageStart, ..., pageEnd)`，本页每一行起点；
3. `lineIndex` = 不超过 `mOffset` 的最后一行；
4. `viewStart` = `mPageLineStarts[lineIndex]`，**视口从这一行起**；
5. `screenAt(mStream, viewStart, cells, lines)`——**不截页末**，允许越过页边界；
6. `count` / `ReaderSourceModel.build(offset = viewStart, ...)` 都换成视口口径。

效果：

- 光标停在页首 → 视口就是整页，和原来翻页的观感一模一样；
- 光标落在页内第 i 行 → 视口从第 i 行铺满一屏，屏底自然接上下一页开头的正文，
  于是"下移一行"看起来就是整屏向上滚一行；
- 页号、章节、进度、点显器推送口径全不变；页号仍由 `mOffset` 反查，
  滚过页边界时页码 +1。

副产品：屏幕首行和点显器推送起点从此是同一个 offset（以前屏从页首铺、点显器从光标推，
两边会错位）。

## 连带修掉的两个排版病

改滚屏时暴露出两个原本就存在的问题，一并修了：

1. **段间距把最后一行顶出容器**。正文是多个 Text（按段拆节点），段间原来有 8dp 间距，
   行数一多就攒出小半行，铺满时最后一行被裁掉半截。段间距改为 0，段落区分靠盲文自身的
   段首缩进与段间换行——屏幕行数严格等于"行高 × 行数"。
2. **行高按单字测量，行数偏多**。原来用 `measure("汉")` 的 height 当行高，
   而 Text 的实际行距由 style 的 lineHeight 决定，比单字高一截。改为测三行取平均，
   再留 2 行余量（多段 Text 每段首末行有 font padding）。真机结果：

```
screen metrics: chars=18 lines=28 -> cells=45 lines=28 unit=1260   // 排版未稳定
screen metrics: chars=18 lines=18 -> cells=45 lines=18 unit=810    // 稳定后 18 行
```

一页从 20 行变 18 行，页数相应变多，但每页正好铺满、最后一行不再被切。

## 验证

- `uiautomator dump`：行进度块仍是单节点 `android.widget.SeekBar`，
  `content-desc="第 4 行 / 共 18 行"`，没有新增焦点。
- 点滑轨到第 6、7 行：屏首行随之变成该行（`page line: -> 6 offset=174 -> 134`），
  页码不变；跨页时屏底接下一页正文，页码 +1。
- 单测全过（decoder 未改，只动 Activity 与 Compose）。

## 边界

- 视口允许跨页，所以页内"共 M 行"说的是本页行数，屏上可能含下一页若干行；
  这是滚屏的固有语义，不是错位。
- 未做真正的像素级平滑滚动（会引入可滚动容器节点，破坏"这一块只占一个焦点"）。
  滚屏是"翻一行 = 整屏上移一行"。
