## 1 角色契约

每个角色一句话：**管什么、只许写哪儿、必须交什么、禁入什么。**
「对外只有产品负责人一个出口」——所有对外结论走产品负责人，角色之间不直接对外。

### 1.1 PM（产品）

- **管**：需求卡、优先级、验收指标（一律盲用户视角，不写工程指标）。
- **写**：只写 `docs/`。本轮只写 `docs/127`。
- **交**：把 125 的三段排期拆成一张「可打勾的执行看板」，每条带判据、带负责人、带证据位置。N1/N3/N4/N2 四张验收卡要写成「用户能感知到什么」，不写实现细节。
- **禁**：不改代码、不碰 `docs/125`（那是产品负责人未提交的手稿）、不给工程方案下判断。

### 1.2 RESEARCH（调研）

- **管**：开源项目、竞品、国标规范、许可证边界。
- **写**：只写 `docs/`。本轮只写 `docs/131`。

## 2 工作区与分支占用（硬约束）

**一个 worktree 同一时刻只许一个角色动手。** 违反这条，多人改同一个工作树会互相踩掉未提交改动。

| 弧段 | 角色 | 工作区 | 分支 | 允许 git 操作 |
|:---|:---|:---|:---|:---|
| 主线 | ENGINE | `D:\软件\brailleback盲文` | `main` | merge / commit |
| 硬件 | HARD | `D:\bb-wt\sunshine` | `feat/sunshine-docx` | commit |
| 测试 | TEST | `D:\bb-wt\testbuild` | `test/build-all-20261126` | 只读 |
| 文档 | PM / RESEARCH | `main` 的 `docs/` | 不提交 | 无 git |

- 其余 worktree（`auto`/`diag`/`docs119`/`fix`/`metec`/`pages`/`perf`/`release`/`selfcheck`）本轮**冻结**，谁也不许进。
- 两个文档角色只在 `docs/` 下新建文件，**一律不执行 `git add` / `git commit` / `git checkout`**，三大目录的未跟踪文件由收口环节统一提交。

## 5 交付格式（六角色统一）

每次交活必须给这三段，缺一段视为没交：

```
状态：完成 / 部分完成 / 受阻（受阻写清卡在哪）
证据：绝对路径清单（verify/ 日志、截图、测试报告、文档）
结论三行：① 做了什么 ② 数字是什么（可核对） ③ 下一步归谁
```

给产品负责人的话一律：**结论前置、纯文本、少用宽表格、数字可核对**——他要靠读屏和点显器看。
