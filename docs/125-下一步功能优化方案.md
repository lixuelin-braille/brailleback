## 0 结论先看

1. **现在最贵的不是缺功能，是已完成的工作散在 8 个分支上没合并。** 主分支只到 117，118～124 七份文档、合计 40 个提交停在 `D:\bb-wt` 的 11 个 worktree 里，约占 4.5 GB。放得越久，合并回归越贵。
2. **第二贵的是质量闭环一直没开工。** 972 个用例里多数是「读源码文本断言」的契约测试，防重构、不防错译；一份导出译错了，测试全绿也发现不了。65 号定的 N1 体检单 / N3 打印预检 / N4 比对台全是 S 量、零风险，源码树里至今没有 `audit/`、`batch/`、`ocr/` 任何一个包。
3. **第三件是「做了但摸不到」的半成品，必须优先收尾：** 122 修的 Metec 42 格末两格、123 已解出阳光 PUA 正文却缺点位映射（推到点显器只会是空白方）。这类不补，前面的投入等于白花。
4. **四周内建议不开任何 50 号新功能卡。** 先把合并、回归、质量闭环、真机复核做完，把「秤」和「轨道」铺好，再谈课堂流、拍照即读、反向翻译。

## 2 第一段（第 1 周）：成果收口

目标：`main` 变成唯一可信基线，任何一条待合分支都能回到「能构建、测试全绿、模拟器能冒烟」的状态。

合并顺序（按风险从低到高，每合一条立刻回归，不合完不开始下一条）：

1. `perf/page-offsets-incremental`（118）：纯诊断 + 增量重建，2 提交，风险最低。
2. `fix/metec-cellcount`（122）：C 层 `setCellCount()` 向上取整。直接影响 42 格与 22 格设备能不能摸到末格，合完必须跑模块容量单测，有条件上真机确认第 41、42 格有输出。
3. `feat/sunshine-docx`（123）：屏幕侧已通，点显侧缺 `toDots` 的 `SUN_MIN..SUN_MAX` 映射。合完**立刻排 123.1 补这条映射**，否则阳光书在点显器上只有空白方。
4. `docs/119-sideload-oem` + `feat/oem-selfcheck`（119/120）：文档与自检引导为主，代码风险低。
5. `chore/release-readiness`（121）：发布工程与密钥保管。密钥身份需要你拍板，见 §7。
6. `feat/auto-connect`（124）：改了连接路由与默认选项卡，必须真机把 Auto / Bluetooth / Wired USB 三种连接各走一遍。
7. `test/build-all-20261126`（22 提交，体量最大）：单独一轮，合完做全量回归 + 模拟器 11 步冒烟。
8. 顺手结案：`KeyTableArchiveContractTest` 要么修掉，要么在 CI/lint 里显式标 expected-fail，不许再挂着。

每条合并的四条验收口径（全过才算收口）：

- `gradle :brailleback:assembleDebug --rerun-tasks` 成功；
- `:brailleback:testDebugUnitTest` 全绿（972+，新增用例必须同批带上）；

收口完成后同步做两件卫生：清根目录 `.tmp-*`（134 个），把已合并分支的 worktree 逐一 `worktree remove`，每个能收回约 0.4 GB。

## 3 第二段（第 2 周）：质量闭环（65 号 N1/N3/N4/N2）

为什么放在功能之前：没有「秤」，任何分词/排版优化都只能靠感觉判断，而主要用户不靠眼睛。

- **N1 转译体检单（S）**：导出后给一张可朗读清单——未覆盖字符、超宽行、避头尾点违例、缩写密度、末行孤字。落点新包 `brailleback/.../audit/`，纯函数读导出中间态，不改正文。
- **N3 打印预检（S）**：`PageGeometry` 旁新建 `PrintPreflight`，纯计算判「可打 / 需重排」：行宽越界、页数、装订边、点密度上限。
- **N4 桌面比对台（S）**：`tools/compare/` 的 Python 脚本，自研引擎 vs liblouis（zhcn-cbs）逐句 diff，输出 CSV 留人工判定列；不进 APK、不进构建产物。
- **N2 真值对语料（M）**：500 句「中文 → 点位」带人工判定，JUnit 驱动，失败打印首个差异格。这是把 972 例从「防重构」升级成「防错译」的唯一低成本路径，也是后面反向翻译的秤。

判据：体检单在一次真实导出上能列出 ≥3 类问题；预检能判出一次「需重排」；比对台跑通 50 句；N2 语料 CI 跑完 <60 秒、能抓出至少 5 个现存错译。攒不到 200 句有判定的语料就改「导出即标注」路线（App 内一键「这句译错了」）。

## 4 第三段（第 3–4 周）：真机复核与发布准备

- **115 B 场景真机长书复核**：真机 + 4500 段大书，翻页 20 次取 gfxinfo，用同环境冻结基线包对照。判据：janky% 与 >33ms 长帧不比基线差，且「翻译推进时不把列表拽回第 1 页」在手上可感知。
- **123.1 补 PUA → 点位映射**：补 `toDots` 的 PUA 分支。判据：阳光 docx 推到点显器能摸到实点，不再是空白方。
- **包体积与原生库**：`local.properties` 的 `ndk.dir` 从 NDK 29 回到 AGP 默认 28.2，让 `.so` 正常 strip；评估 ABI split（arm64 单发）压体积。注意：不要回退 07 号 S0 的 16KB page 对齐（四个库 `Align` 必须仍是 `0x4000`）。
- **发布**：121 的 keystore 身份定下来（一次性决定），release 不再用 debug 签名；targetSdk 37 已达标无需再动；版本号仍走 `gradle.properties` 的 `appVersionCode`（有 `VersionCatalogTest` 门禁）。

## 5 之后才是功能下注（第 2 个月起）

按「当前真机可用度 × 用户每天在用」排序，只挑三条，其余卡暂不动：

1. **50 号 #9 设备守护（S）**：电量、断连、重连、双设备热切换，指数退避。这是「断连恢复」红线的工程兑现，也是课堂线的前置。
2. **65 号 N6 用户规则覆盖（M，50 号 #6 升级）**：自定义分写/连写/缩写词条，优先级高于内置 1439 条，可导入导出。同时是「用户纠正即标注」的数据入口，等于给 N2 语料找免费来源。
3. **65 号 N9 拍照即读 v2（M，50 号 #2 升级）**：先只做「纯文字页 + 竖排/双栏」，表格走 N11。判据：识别后「摸得懂」≥4/5 页；低于 3/5 退回整页纯文字模式。
4. **押注项（注 1 反向翻译）**：最大空白，但工程上要先有 N2 的秤。建议 N2 攒到 200 句后再启动「50 句单句、一级盲文」最小验证，准确率 ≥90% 才往下做二级与缩写。

## 6 三条新门禁（沿用 50 号三层隔离，不新增例外）

- **分支不许长期漂**：任何 worktree 分支超过 7 天未合，就必须做决定——合，或删。不许无期限挂着占盘。
- **新功能一律 feature flag**：默认关，收在设置页「实验功能」；独立包/独立模块，核心文件（`DisplayManager`、`keymap/`、`BrailleIME`）只加一行钩子。
- **结论必须落盘**：每条真机/模拟器结论带日志、截图或数字，沿用 115 起形成的 `verify/` 取证习惯。

四条红线不改：盲文输出正确性、断连恢复、TalkBack 朗读语义、已支持点显器兼容性。

## 7 需要你拍板的三件事

1. **合并顺序**是否按 §2 走？我建议 Metec 与 sunshine 先合，因为这两条直接决定「摸不摸得到」。
