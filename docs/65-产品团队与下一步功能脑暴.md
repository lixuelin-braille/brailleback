## 0 结论先看

1. **电脑端开源盲文软件值得抄的不是算法，是工程方法学**：真值对语料测试、表文件版本化、翻译层与排版层分离。我们的 744 个用例里绝大多数是「源码契约测试」，防重构不防错译，这是真洞。
2. **「图片转盲文点」是三件事，不是一件**。目前被开源项目做烂的那一类（`U+2800–U+28FF` 点字画）对盲用户几乎没有使用价值；真有价值的是 **图片文字→OCR→盲文** 与 **图片→可压印点阵→打印**。
3. **我们已经有排版底座，缺的只是「闭环的检查与交付」**：`PageGeometry` 默认 30 方 × 25 行，正好等于 A4 纸 180 mm 可打印宽 × 257 mm 可打印高。纸面几何这一层是现成的，缺的是**打印预检**与**转译体检单**。
4. 因此下一批最该做的三条不是新功能，而是**质量闭环**：转译体检单、真值对语料、纸面预检。S 量、零风险、当天能验证。

## 1 智能体产品开发团队

一条产品线，六个角色。每个角色是一个独立智能体，同一套仓库、同一套红线；**对外只有产品负责人一个出口**，避免多头改代码互相打架。

| 角色 | 管什么 | 交付物（都必须落盘） | 主要输入 |
|:---|:---|:---|:---|
| **产品（PM）** | 需求卡、优先级、验收指标（盲用户视角，不用工程指标） | `docs/` 需求卡 + 验收清单 | 用户真实场景、本文与 50 号 |
| **调研（RESEARCH）** | 开源/竞品/国标规范、许可证边界 | 调研报告（含出处 URL） | 外部资料 |
| **引擎（ENGINE）** | 分词、规则、盲文表、反译、语料 | 纯 Kotlin 包 + 真值对语料 + 准确率数字 | `service` 现有引擎 |
| **安卓（ANDROID）** | Compose 界面、无障碍服务、点显器连接、导出 | 带 flag 的独立包 + 仪器测试 | `brailleback` 现有链路 |
| **硬件（HARD）** | 点显器协议、打印头、纸面几何、刻印机 | 协议文档 + 打印预检 + 实机打印样张 | 彗光固件分析（13 号）、BOM（11 号） |
| **测试（TEST）** | 真值对语料库、CI 门禁、回归基线 | 语料集 + 门禁脚本 + 失败 0 记录 | 全部角色产出 |

### 协作约定（沿用 50 号的三层隔离，不新增例外）

| 层 | 规则 |
|:---|:---|
| 新功能入口 | 一律 **feature flag**，默认关，收在设置页「实验功能」；关掉时零代码路径 |
| 新功能代码 | **独立包/独立模块**，核心文件只加一行钩子（`DisplayManager`、`keymap/`、`BrailleIME` 内部逻辑不动） |
| 契约测试 | 分两档：**已发布行为**（钉死不许破）/ **实验行为**（随迭代可重写） |

### 四条红线（任何角色都不许碰）

1. 盲文输出的**正确性**（点位、分词连写、避头尾点）
2. **断连恢复**（点显器停了 App 必须知道）
3. TalkBack **朗读语义**
4. **已支持点显器的兼容性**

破一条，用户当天就没法用手机。所以：**宁可慢，不许破。**

| **BrailleBlaster + Dotify**（APH，Java） | 桌面排版/校对软件，输出 PEF / 打印文件 | 排版层参考 | ① **翻译层与排版层分离**，中间表示（PEF/XML）承载分页、避头点、页码；② **逐行对照校对**界面；③ 打印前预检 | JavaFX 那套桌面壳（我们的交付面是手机 App） |

### 2.1 最省力的「参考」方式：搭一个桌面比对台

不必读它们的源码。用 **liblouis 官方 Python 绑定**在 PC 上搭一个比对台：

```
同一段中文  ──►  自研引擎（Kotlin 导出 CLI 或 JVM 调用）  ──►  点位串 A
            └──►  liblouis + zhcn-cbs 表（Python）        ──►  点位串 B
                         └─► diff ──► 差异清单 ──► 人工判定「谁错」──► 真值对语料
```

**价值**：这是**唯一**能低成本产生真值对语料的办法。语料一旦攒到 500 句，就能把「防重构」的测试变成「防错译」的测试。注意：liblouis 的中文表和我们自研引擎的分词口径不同，**差异不等于我们错**，所以必须人工判定，只把判定过错的收进错题库。

**风险与边界**：Python 侧只做离线分析工具，**不进 App、不进构建产物**，放 `tools/`（已有 `tools/` 目录与 PowerShell 脚本先例）。

## 3 把「图片转盲文点」拆成三种东西

同一个说法，三种完全不同的技术路径与产品价值。混在一起讨论一定会做错方向。

### 3.1 三类辨析

| 类型 | 输入 → 输出 | 开源代表 | 真实价值 | 结论 |
|:---|:---|:---|:---|:---|
| **A 点字画**（Unicode Braille Art） | 图片 → 2×4 像素块 → `U+2800–U+28FF` 字符 | `arTTY`、`img2braille`、`BraillePixel`、`ascii-forger` | **在终端里「看」图**，是给明眼人的终端玩具 | ⚠️ 对点显器用户**几乎无价值**，见 3.2 的算术 |
| **B 图上文字 → 盲文** | 拍照 → 端侧 OCR → 排序合并 → 分词 → 点显器 | 无成熟中文开源方案 | **高**：课本、讲义、作业题、通知单，全是图 | ✅ 主攻方向（50 号 #2「拍照即读」的升级） |
| **C 图 → 可压印点阵**（触觉图形） | 图片 → 二值/轮廓 → 按纸面点距重采样 → 点阵 → SVG/PLT/直驱打印头 | 无中文开源方案 | **高**：几何图、地图、电路图、化学结构式、表格框线 | ✅ 与硬件（彗光刻印机 / 便携打印头）强绑定 |

### 3.2 为什么 A 类对盲用户基本没用（算术）

- 点显器一行通常 **20 / 32 / 40 格**；点字画一行 40 格 = **80 像素宽**，也就是把一张照片压到 80×160 像素。
- 触觉辨认只对**粗轮廓、高对比、少细节**有效；照片级灰度在指腹上是一团。
- 所以 A 类只有一个真实用途：**调试与中间态可视化**——把点阵「画」到日志/聊天里，人眼快速判断程序对不对。做成开发者选项里的一个工具即可，**不做成用户功能**。

### 3.3 为什么 C 类必须做（纸面几何是现成的）

中文盲文纸面常见参数：点间距约 **2.5 mm**，方间距约 **6 mm**，行距约 **10 mm**，点径约 1.5 mm（以国标与设备实测为准）。于是：

- A4 宽 210 mm，左右各留 15 mm 边距 → **可打印宽 180 mm = 30 方 × 6 mm**
- A4 高 297 mm，上下各留 20 mm 边距 → **可打印高 257 mm ≈ 25 行 × 10 mm**

**这正好等于我们现在 `PageGeometry` 的默认 30 方 × 25 行**（提交 `33ddeed` 参数化、`c9e0af7` 默认 40→30）。也就是说：**版面数字已经对了，缺的是「把它和真实打印机对账」的那一步**。

C 类的最小闭环：

```
图片 → 灰度 → 自适应阈值（局部 OTSU）→ 形态学去噪 → 轮廓/连通域
     → 重采样到 2.5 mm 网格（可选 1.25 mm 半格以提高曲线精度）
     → 点阵（每格 1 点 / 半格补点）
     → 导出 SVG（离线人工看）     ┬─→ 打印预检（页数、边距、点密度上限）
     → 直驱打印头（ESC/P / PCL）  ┘
```

三个必须提前定的物理量：**点距**（2.5 mm）、**行距**（10 mm）、**点密度上限**（打印头每行压点次数决定，超了会糊或卡纸）。

## 5 开工顺序与判据

| 批次 | 内容 | 为什么这个顺序 | 判据（过/不过） |
|:---|:---|:---|:---|
| **本周** | N1 体检单 → N3 打印预检 → N4 比对台 | 全部 S、零风险、不改主链；一天能出一个可摸的证据 | 体检单能在一次真实导出上列出 ≥3 类问题；预检能判出「需重排」；比对台跑通 50 句 |
| **两周** | N2 真值对语料 500 句 | 语料是后面一切的秤；先有秤再谈优化 | CI 跑完 < 60 秒，能捕获至少 5 个现存错译 |
| **下月** | N6 用户规则覆盖 → N9 拍照即读 v2 | 课上最痛的是「课本是图」；用户纠正是最便宜的标注 | 自定义词条生效率 100%；纯文字页识别后「摸得懂」≥ 4/5 页 |
| **押注（与硬件并行）** | N10 图片→触觉图形 → N13 打印队列 | 这条是我们和所有手机 App 的差别所在，但依赖打印头实测 | 一张 A4 线稿打完：点距误差 ≤ 0.2 mm，纸面不糊不断线 |

### 失败即退（写死，别事后找理由）

- N9 识别后「摸得懂」低于 3/5 页 → 退回「只做整页纯文字，不做排版还原」。
- N2 攒不到 200 句有判定的语料 → 说明人工判定成本过高，改用「导出即标注」（在 App 里一键「这句译错了」）。
- N10 点距误差 > 0.5 mm 或纸面糊点 → 说明打印头分辨率不够做图形，只做「表格框线 / 简单几何」。

## 6 需要你拍板的三件事

1. **N10 走哪台机器**：先对齐彗光刻印机（13 号固件分析已有基础），还是先把便携打印头打通（自己那套）？两者协议不同，先做一台。
2. **N2 语料谁来判**：你自己判（最准、最慢），还是「比对台差异 + 你只判存疑项」（快、但需要信任工具的筛选）？
3. **N5 对照校对的定位**：只给你自己用（自查），还是要给明眼老师/同学用（那就得考虑他们看得懂盲文吗——可能改成「原文 + 语音核对」而不是盲文双栏）？

## 7 与 50 号的关系（避免重复立项）

- 50 号的 12 张卡**不撤销**，本文 N 组是它的**前置、升级与新增**：
  - 升级：#6→N6、#2→N9、#5→N11
  - 前置：50 号 #3 盲文笔记、#7 乐谱都依赖「语料 + 反译」，N2 是它们的秤
