# 双进度条：页一条、行一条

## 由来

用户要把「上一页 / 下一页」和「本页逐行切换」都做成进度条，一共两条。
所以这一块从「一个滑块」变成「上下两条」：

1. 上条管**页**：`第 N 页 共 M 页`，一格一页，拖就是跨页（替代原来的上一页/下一页按钮）；
2. 下条管**本页的行**：`第 N 行 / 共 M 行`，一格一行，拖就是页内换行
   （拖到第 i 行时视口就从第 i 行起铺，见 docs/98）。

两条各自是一个无障碍节点，互不影响；都是自绘 + 一次语义声明，
不用 M3 Slider（它会多造子节点、读屏念两遍）。

## 版式

```
第 12 段 / 共 25982 段          ← 小字，只画不念（invisibleToUser）
第 2 页 共 107 页 ────────●────
第 1 行 / 共 20 行 ────────●────
[ 目录 ] [ 书签 ]
[ 字号 ] [ 导出为盲文 ]
```

上一页/下一页按钮随之去掉（页滑块承担），跳页按钮早已去掉
（页码滑块双击就是「跳到第几页」，见 docs/99）。

## 这一轮踩到的三个坑

1. **小字塞进滑块内部会重叠**。原先把段号小字画在滑块的 Canvas 顶部，
   两行的行高测量一有偏差就压在一起。改成独立的一行 `Text`，
   用 `invisibleToUser()` 让它不产生可聚焦节点，朗读里也就没有它。
2. **Canvas 自绘文字必须取 `LocalContentColor`**。`MaterialTheme.colorScheme.onSurface`
   在深色主题下画出来明显偏暗（截图上几乎看不见），而旁边的正文 `Text` 用的是
   `LocalContentColor`。换过来之后两条滑块的字和正文同色。
3. **加了一条滑块，纵向就吃紧**：底部提示行被系统导航栏压住。
   root 加 `navigationBarsPadding()`、间距 12dp → 8dp、提示行改 `bodySmall`、
   文案压缩成一行（「长按翻页可逐行；双击滑块输页码」）。

另外行的 `rowHeight` 现在比文字高度多留 6dp：正好等于文字高度时，
字会被 Canvas 上下各切掉一点笔画。

## 验证

- `uiautomator dump` 里两个 `android.widget.SeekBar`：
  `'第 1 页 共 264 页'` 与 `'第 1 行 / 共 18 行'`，各自独立，没有多余节点。
- 段号那行没有出现在可聚焦节点里（`invisibleToUser` 生效）。
- 编译通过、单测全过。
- 未复核：`navigationBarsPadding` 之后底部提示行是否完整露出
  （改完时用户已切回聊天界面，没有抢前台去抓图）。
