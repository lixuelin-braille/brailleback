# 88 · 两键点显器的「换行」与边界播报

## 现象

用户说他的设备只有两个按键，一按图，屏上就播「左到头 / 右到头」，纵向完全走不动。

## 定位

只有两个键的设备把这两个键上报成 `CMD_NAV_PAN_LEFT`(5) / `CMD_NAV_PAN_RIGHT`(6)，也就是
82/81 号里说的「平移键」。视口页的映射本身没错（平移 → 横向），问题在于**横向到头就停住**：

- 图宽只有一个横向窗时（`colStarts.size == 1`，常见于 40 方屏配普通宽度的图），
  `panLeft()` / `panRight()` 立刻返回 `LEFT` / `RIGHT`，两个方向都是「到头」；
- 而纵向只能靠「上一行 / 下一行键」（`CMD_NAV_LINE_PREVIOUS/NEXT`）或手机按钮，
  这两样这台设备都没有。

也就是说：**键位映射对了，但换行路线断了**。两个键在横向撞墙之后没有「继续往下读」的路。

## 改动

横向到边不再是终点，而是按阅读顺序换行的入口：

- `TactileViewport.wrapRight()`：右平移到头 → 块内下一屏（横向窗复位到最左）；
  块末 → `nextBlock()`；整图末屏返回 false 并带 `LAST_BLOCK`。
- `TactileViewport.wrapLeft()`：对称。**反向换块要落在上一块的末屏**（`blockPageCount()-1`），
  不是它的第 1 屏——这一条是单测抓出来的：第一版写成 `prevBlock()` 直接返回，
  反向往回走时整块的中间几屏被跳过，20 屏只走了 7 步。
- 总览态同样换带：`px` 到边时把选择框移到下一带 / 上一带（`boxRow ± blockRows`，
  横向回到最左 / 最右）。
- `TactileStripActivity.vpNavigate()` 把「横向到边」接到上述换行，只有整图首 / 末屏才真的
  播报 `左到头` / `右到头`（此前的播报全部保留，只是不再拦路）。
- 视口按键说明文案补一句：到头会接着翻上一行 / 下一行，两键设备也能走完整张图。

阅读器侧补了一条同类问题：正文页两个键走逐行，到文首 / 文末时 `moveLine()` 原地钳住、
静默无反馈，用户会以为按键失灵。新增 `moveLineFromKey()`，位移没变化时播报
`braille_reader_at_start` / `braille_reader_at_end`（中英各一条）。

## 为什么是「到边换行」而不是加开关

判不出设备有几个键（`BrailleDisplayProperties` 只有方数，没有键数），所以不做「两键模式」
开关——那会变成又一个要用户猜的设置。到边换行对多键设备也无害：横向到头时人手本来就想
「往下读」，多给一个纵向动作比听一句「到头」有用。手机侧的上移 / 下移按钮仍原样保留。

## 验证

- 新增 4 例：`wrapRightWalksEveryScreenInReadingOrder`（80×80 / 40 方 8 点 = 20 屏，
  纯靠 `wrapRight` 正好 19 次到末屏，且末次报 `LAST_BLOCK`）、`wrapLeftReturnsToFirstScreen`
  （反向 19 次回首屏，再往前报 `FIRST_BLOCK`）、`singleHorizontalWindowStillScrollsDown`
  （单横向窗时 `panRight` 报 RIGHT，`wrapRight` 仍能下移一屏且横向窗归零）、
  `overviewWrapMovesBoxToNextBand`（总览到右端换到下一带）。
- 935 例单测 0 失败、`lintDebug` 0 error、`assembleDebug` 全绿，APK 已 `install -r`。
- **真机待验**：这台两键设备实际按下去是不是稳定上报 5 / 6（有的驱动会把长按报成别的命令码），
  以及换行后的播报内容是否够用，要接上设备逐下按一遍才能定。
