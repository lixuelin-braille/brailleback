## 现状概览

该 Activity 是触觉图形**导出页**：选图 → 收参数 → 后台线程转换（`TactilePipeline.imageToBmp`）→ 两条落盘通道（公共下载目录为主、SAF 另存为辅）→ 可选分享；每一步结果经 `showStatus` 进 live region / announce / Toast 三条播报路径。算法内核在同包 Pipeline / Rasterizer / Encoder，本类只做界面接线。

行数口径：总行数 / 非空行（去纯空白行），主仓库 `3ff9ebe` 实测。

## 共享状态矩阵

| 状态 | 写方 | 读方 | 交叉要点 |
|:---|:---|:---|:---|
| `converting` | 选图 `onImagePicked`、通道 A `onSaveDownloadsClicked`、通道 B `onExportUri`（**三处共写** true→false） | Compose Screen（按钮禁用态 `!converting`） | 选图流与两条落盘通道共用同一忙标志；单拆任一通道都会留另一处悬空写 |
| `sourceFile` | 选图 `onImagePicked` **唯一写**（复制到 `cacheDir` 临时文件，旧文件先删） | 通道 A、通道 B 转换时读 | 选图是唯一写源，两通道只读；选图流与落盘流靠这个字段衔接 |
| `status` | `showStatus` **单一漏斗**；来源五组：选图成功 / 解码失败 / 需先选图 / 导出中 / 成功（两通道）/ 失败分类 / 分享无应用 | Screen 状态区 + 三路径播报 | 状态写入口收敛在 `showStatus`，分叉在结果 sink（`renderOutcome`、`failureMessage`、`classify`） |
| `pendingSettings` / `pendingProfile` | `prepareParams()` **唯一写** | 两通道 `imageToBmp` 读 | 进落盘前把参数定死，后台线程只按这份设置编码 |
| `pendingFileName` | 通道 B `onSaveOtherClicked` 私有写 | `onExportUri` **跨 SAF 往返**读 | 仅通道 B 使用，但跨过 `CreateDocument` launcher 往返，状态不能随回调走 |
| `lastExportUri` / `lastExportName` | `renderOutcome` **两通道同写** | `onShareClicked` **只读** | 分享是纯消费者，不反向回写会话状态 |
| `sourceName` / `mode` / `threshold` / `landscape` | Compose 回调写（`mutableStateOf`） | Screen 渲染、`prepareParams` 读 | 纯 UI 状态，与 Compose 重组绑定 |

## 不采纳拆分的理由（R1–R6）

- **R1 双写入方**：`converting` 被选图与两条落盘通道三处共写；`pendingSettings/pendingProfile`、`lastExport*` 同样两通道共用。按通道分簇会把同一批共享字段拆到两个簇里，任一簇外拆都要回头放宽字段可见性并照顾另一处写入口。
- **R2 消除双写须连选图流一起搬**：要把状态收拢进独立 Session，必须连选图流（`onImagePicked` 复制缓存、`displayNameOf` 回查文件名）一起搬；而 Session 变量与 Compose `mutableStateOf` 会形成**双真源**，重组时机、状态回填要重新钉，超出纯重构范围。
- **R3 SAF 跨往返状态与 Activity 依赖**：`pendingFileName` 跨 `CreateDocument` launcher 往返；`lifecycleScope`、`contentResolver`、`cacheDir`、`getString`、`Toast` 全部绑 Activity。外拆后要显式传 Activity/Context 或回调接口，依赖面变大、生命周期归属变复杂。
- **R4 状态机薄、分叉在 sink**：转换与落盘走 `TactilePipeline` 纯函数，Activity 本身只是接线；真正分叉在结果 sink（成功/失败渲染、失败分类 `classify`、文案 `failureMessage`）。薄状态机里没有一块能独立成文件、又不与宿主交叉的内聚闭环。
- **R5 对上一批「分享需反向回写」判断的修正**：上一批曾判断分享环节需要从通道结果反向回写状态；本轮复核源码，`onShareClicked` 只读 `lastExportUri/lastExportName`、不回写任何会话状态，分享是纯消费者。外拆分享闭环并不消除双写，仍要把两通道写入口搬进 Session，收益不抵成本。
- **R6 生命周期属新增职责**：把 Activity 状态、launcher 注册、生命周期回调收进 Session，是在 Activity 之外新增一层生命周期编排，不属于「按数据流分簇、方法体逐字搬运」的纯重构；本批阈值与手法都不支持新增这一层。

## 两种被放弃的切法

| 切法 | 设想 | 放弃理由 |
|:---|:---|:---|
| Strip 式同包扩展分簇 | 参照 `TactileStripActivity` 六簇做法，把选图 / 参数 / 落盘 A / 落盘 B / 分享 / 文案扩成同包 `internal` 扩展函数 | 共享可变状态跨簇（`converting`、`sourceFile`、`pending*`、`lastExport*`），两通道簇都要碰同一批宿主字段；切缝比浏览页更碎，扩展函数要批量放宽 `private`→`internal`，可读性下降 |
| 纯类型下沉 | 把 `ExportOutcome` / `FailureKind` / `TactileLabels` 等纯数据类型抽成独立顶层文件 | 这些类型本就是文件内顶层 `private` 类型，行数占比小；下沉后 Activity 仍握全部状态与回调，行数减不到阈值，只增加文件跳转 |

## 将来越过 800 时的首选切法

若该文件将来非空行越过 800，首选以**导出 Session** 为核心：把会话状态、选图流与两条落盘通道收进一个持有 Activity 回调接口的 Session；Activity 只保留 launcher 注册、Compose 接线与文案；分享与结果播报作为 Session 的 sink。届时需同步处理双真源（Session 状态 ↔ Compose `mutableStateOf`）与 SAF 往返状态的归属。
