# 45 - 源码布局与工程结构现代化

> 2026-11-20。这是一次**纯结构改动**：一行业务逻辑没动，功能、包名、
> `applicationId`、AIDL 契约、native 库装配方式全部保持原样。
> 改的是仓库从 2013 年 Google eyes-free 时代沿用下来的目录约定，
> 以及当年为了绕开旧 AGP 限制而写的一批 `sourceSets` 覆写。

---

## 1. 改之前是什么样

11 个模块 + 仓库根都用旧式布局：源码直接挂在模块根的 `src/` 下（`src/com/googlecode/...`），
资源在模块根的 `res/`，清单在模块根的 `AndroidManifest.xml`，测试在 `test/` 与 `androidTest/`。
这是 Eclipse ADT → 早期 AGP 的约定，AGP 8/9 能跑，但每个模块都要靠手写覆写告诉它文件在哪：

```groovy
sourceSets {
    main {
        manifest.srcFile 'AndroidManifest.xml'
        java.srcDirs = ['src']
        kotlin.srcDirs = ['src']
        resources.srcDirs = ['src']
        aidl.srcDirs = ['src']
        res.srcDirs = ['res']
        assets.srcDirs = ['assets']
    }
    debug.setRoot('build-types/debug')     // Eclipse 时代的构建类型根，目录根本不存在
    release.setRoot('build-types/release')
}
```

副作用有三个：

1. **测试目录会被主源集吞掉**。`java.srcDirs = ['src']` 时 `src/test` 也算主源码，
   所以 `addon/brailleime` 只能把测试放在 `test/` 再单独覆写一遍（脚本里还写着注释解释这件事）。
2. `debug.setRoot('build-types/debug')` 指向的目录全仓都不存在，是纯历史残留。
3. 任何工具（detekt、ktlint、自定义脚本）都得单独记住这套非标准路径。

---

## 2. 改成了什么

标准 AGP 布局，**sourceSets 覆写从 11 处降到 1 处**：

| 内容 | 迁移前 | 迁移后 |
|:---|:---|:---|
| Kotlin + Java | `brailleback/src/com/...` | `brailleback/src/main/java/com/...` |
| AIDL（10 个） | `client/src/com/.../*.aidl` | `client/src/main/aidl/com/.../*.aidl` |
| 资源 | `brailleback/res/` | `brailleback/src/main/res/` |
| 资产（词表、盲文表） | `service/assets/` | `service/src/main/assets/` |
| 清单 | `brailleback/AndroidManifest.xml` | `brailleback/src/main/AndroidManifest.xml` |
| 单元测试 | `brailleback/test/{java,kotlin,resources}` | `brailleback/src/test/{java,kotlin,resources}` |
| 仪器测试 | `brailleback/androidTest/kotlin` | `brailleback/src/androidTest/java` |

Kotlin 与 Java 混放在 `src/main/java` 是 Android 工程的惯例（Android Studio 新建 Kotlin
工程就是这个布局），不另开 `src/main/kotlin`。这样所有"扫描整棵源码树"的工具只有一个根，
不用再维护两套路径。

**保留的两条覆写**（有明确理由，不是历史残留）：

```groovy
sourceSets {
    main { jniLibs.srcDirs = ['jniLibs'] }        // 预编译 .so 唯一入库位置，jni/ 下是本地编译产物
    test { assets.srcDirs = ['src/main/assets'] }  // 单测直接读 word 表，避免复制第二份词库后漂移
}
```

## 3. 连带改动：契约测试

这个仓库有一批**"源码契约测试"**——用文件路径去读源码，断言结构约束（例如
`DisplayManager` 不许回涨到 1500 行、`SettingsComponents` 必须复用组件基类）。
路径写死成 `brailleback/src/com/...` 的有 36 个测试文件，布局一迁全部报"找不到文件"。

改法不是加兼容层（那会让契约失效——布局回退了测试还照样绿），而是把断言指向新位置：

| 改动 | 数量 |
|:---|:---|
| 源码路径 `/src/com/` → `/src/main/java/com/` | 全部 36 个文件 |
| `res/` → `src/main/res/`（含 `../`、`../../` 前缀的跨模块引用） | 8 处 |
| `service/assets/` → `service/src/main/assets/` | 2 处 |
| `AndroidManifest.xml` → `src/main/AndroidManifest.xml` | 2 处 |
| 扫描整棵源码树的根 `"brailleback/src"` → `"brailleback/src/main/java"` | 3 个测试 |

第三类是最隐蔽的：以前测试在 `brailleback/test`，在 `brailleback/src` 之外，所以
"扫 `src` 找违规写法"不会扫到自己；迁移后测试进了 `src/test`，**在 `src` 之内**，
于是 `DisplaySplitContractTest` 把自己也扫进去、断言失败。把扫描根收到 `src/main/java` 才修好。

顺带更新的还有：根 `build.gradle` 的 detekt 输入路径（5 条）、`tools/dependency-probe`
的 ktlint/detekt 探针路径（2 条）。

## 4. 两个踩过的坑

### 4.1 AGP 增量资源合并的陈旧状态

把 `res/layout-v17/braille_ime.xml`（start/end 的 RTL 版）并进 `res/layout/`、删掉 `layout-v17`
之后，构建报：

```
e: BrailleIME.kt:278:51 Unresolved reference 'braille_ime'
```

文件明明在、XML 也合法、`processDebugResources` 还报成功。原因是增量资源合并缓存里
仍记着"这个布局来自 layout-v17"，删目录后没有重新产出 `R.layout.braille_ime`。
删 `build/intermediates/merged_res` 也没用（任务仍判 UP-TO-DATE）。
**`--rerun-tasks` 才刷新**。以后动布局目录结构，别相信一次普通 `assembleDebug`。

### 4.2 用相对路径长度去截绝对路径

批量搬文件时写了 `$_.FullName.Substring($k.Length)`，而 `$k` 是相对路径（`brailleback\src\main\kotlin`）。
长度对不上，189 个 Kotlin 文件被搬进 `src/main/java/back/src/main/kotlin/...`。
Kotlin 照样编译通过（包名对、路径不影响编译），但契约测试全部找不到文件才暴露出来。
教训：**截路径一律用绝对路径的长度**；搬完先核对每个模块的文件数与原数一致。

## 6. 故意没做的

- **`applicationId` 和包名没动**（`com.googlecode.eyesfree.brailleback`，338 个文件里出现 822 次）。
  改它就是发布另一个应用：升级链断、无障碍服务授权失效、点显器配置与偏好全丢，用户必须卸载重装。
- **`values-large/dimens.xml` 没动**。`large` 限定符没有被废弃（废弃的是 `iw/in/tl` 那批语言码，
  已在同批改掉），把它换成 `sw600dp` 会改变大屏手机的 overlay 尺寸，属于行为变更，不混进结构改动。
- **`android.overridePathCheck=true` 与 `android.enableResourceOptimizations=false` 保留**。
  前者是因为仓库路径含中文（`D:\软件\...`），后者是"发布包不做资源名混淆"的项目决定，
  两者都有构建期警告但都不是历史残留。
- **`client/.classpath`、`client/.project`** 是本地 Eclipse 残留且未入库，没删（属于用户本机文件）。
- **`WrapStrategy.java.bak-avoidhead`、`BrailleSegmenter.java.bak-math`** 是未跟踪的本地备份，
  跟着源目录一起搬到 `src/main/java` 同位置，没删也没改。
