# 93 · 换行与翻屏不劈字

## 现象

用户反馈「换行拆分字符」：读一段长文时，翻屏/换行处出现半个字——上一屏（或在屏/行尾）只剩一个汉字的前半方，后半方跑到下一屏（下一行）开头。

## 定位

通用盲文里一个汉字占 1–3 方、词内连续书写，可靠的边界只有词间空方 U+2800（缩进也用空方）和段间 `\n`。代码里有两处按「方数硬切」，边界一律不管：

1. `BrailleReaderActivity.moveLine(delta)`：`mOffset + delta * step`，`step` 就是点显器一屏方数（30）。实测 30 方步进有约 **74%** 的落点在一个词中间（同一份注释原本就写在 `nextOffset` 上，但只用于页表）。
2. `BrailleFileDecoder.screenAt()`：每行 `pos + (cellsPerLine - hang)` 直接切，行尾半字跑到下一行。
3. 顺带：`sendToDisplay()` 一律发 `mDisplayCells`（30）方，屏尾那第 30 方常常是半个字；`jumpToOffset()`、书签预览 `previewAt()` 也是硬切。

`nextOffset()` 早就做了「回退到词首、跳过段间换行、保留空方缩进」，只是被用在 `pageOffsets`（屏页表）上，点显器按键、屏幕折行、发屏、预览四路都绕过了它。

## 改动

`brailleback/.../BrailleFileDecoder.kt`

- 新增 `wordStartAtOrBefore(stream, offset)`：把偏移回退到所在词的词首（词首 = 前一方是空方或换行）。
- 新增 `prevOffset(stream, offset, unit)`：后退约 `unit` 方再对齐到词首，宁可少退几方也不让屏首落在词中间。
- 新增私有 `wrapEnd(stream, start, limit)`：行尾折行点回退到词边界；整行只有一个超长词（长数字串、乐谱长音型）才硬切。
- `screenAt()` 每行改用 `wrapEnd` 收尾。
- 新增 `cutAtBoundary(s, limit)`：预览一类的「取一截」也按词边界截断。

`brailleback/.../BrailleReaderActivity.kt`

- `moveLine()`：前进走 `nextOffset`，后退走 `prevOffset`，不再 `+delta*step` 硬挪；日志 `move: +30 offset=0 -> 30`。
- `sendToDisplay()`：发到 `nextOffset(mOffset, mDisplayCells)` 为止，屏尾不留半字；日志 `send: from=… to=… len=… display=…`。
- `showPage()` 的 `count` 改为「到下一处词边界为止」，屏显还原与点显器同口径，末行不露半个字。
- `jumpToOffset()`（书签落点）、`previewAt()`（书签预览）都改成按词首/词边界对齐。

## 验证

- 新增 `brailleback/src/test/kotlin/com/linxi/brailleback/BrailleWordWrapTest.kt`（8 例）：任意方数下每屏起点都落在词边界、屏内不劈词（只有词本身比一屏长才硬切）、`prevOffset` 不越过也不多退、`screenAt` 每行不超宽且不丢方、`cutAtBoundary` 按词截断、超长词硬切、段间换行被跳过。全量单测 `brailleback 955 例 / service 226 例` 全过。

- 真机（装包 → force-stop → 打开 3MB 小说 → 长按「上一页/下一页」逐行）：

```
move: +30 offset=0 -> 30
move: +30 offset=30 -> 59      # 30+30=60，回退 1 方到词首
move: +30 offset=59 -> 88
move: +30 offset=118 -> 146    # 回退 2 方
move: -30 offset=146 -> 109    # 后退 30 方再对齐词首
move: -30 offset=102 -> 66
send: from=36 to=66 len=30 display=30
```

每步不超过一屏方数、落点全部在词首；发到点显器的长度也跟着截到 26–30 方，屏尾不再有半个字。

## 取舍

- 每屏会少显示 0–8 方（回退的那部分留给下一屏，内容不丢），连续按「下一行」时步长不恒定，这是为了不劈字付的代价。
- 词本身长于一屏（超长数字串、英文单词、乐谱）只能硬切——没有别的锚点可用。
- 屏幕一行现在按词收尾，所以行尾可能带一个空方（缩进/词分界本身是内容）。
