# 77 · 项目总体方案：从「离线全绿」走到「真机可用」

> 日期：2026-11-24　依据：本轮只读查看仓库目录、`docs/00–76`、`.git` 提交记录与最近三份验收 / 测试报告（74、75、76）
> 本文只定方案，未改任何源码、未提交、未清理文件。

---

## 0 一句话结论

项目**离线层已经很扎实**（1204 例单测全绿、构建通过），但**真机层是零**：真实点显器、TalkBack 朗读、触感、8 点硬件，一项都没在设备上跑过。
所以下一阶段的方案不是继续加功能，而是：**先收口 → 修两个已知缺陷 → 打通一次真机验收 → 再补稳定性债 → 出一个能发给别人的正式包**。新功能冻结到真机反馈回来之后。

## 1 现状快照

### 1.1 目录层

- 位置 `D:\软件\brailleback盲文`，分支 `main`，HEAD `394da34`（11-24 提交，内容是触觉图独立校验脚本）。

- 根目录堆了**约 100 个 `.tmp-*` 构建日志**和若干 `.tmp-*` 目录、两份 `.so_backup_*`，`docs/README.md` 索引仍把项目方针写成「不增加新功能，以提高稳定性为主」，与实际做的事不一致。
- `发布/` 里只有两个 11-12、11-13 的旧诊断包；最新产物是 `brailleback/build/outputs/apk/debug/` 的 debug 包（65.7 MB，release 包 11-22 实测约 21 MB）。

### 1.2 代码与验证层

| 层 | 状态 |
|---|---|
| 单测 / 构建 | 通过：150 套件 1204 例，failures 0；`assembleDebug` 成功 |

### 1.3 已知缺陷（按对盲人用户的影响排序）

1. **多行三段式解码失败**（`TactileStripActivity.rebuild` 的 catch 兜底成「图片解码失败」，异常类型未落日志）。同一张图单行可解、多行必败，排除素材问题，指向 `TactileStripSession.build` 里多行独有的环节；最可疑的是封面 / 封底翻译桥 `wrapIntoScreens` 在无翻译服务时抛错且未逐行包裹。
2. **阅读器正文逐格重复汉字**（`ReaderSourceModel.kt:81–93`，`reconstructSource` 每格都 append 整个字的 `sourceText`）。已确认入库源文不重复，只是屏显还原层重复。属受保护链路，**改之前要你点头**。
3. **全角减号混合串解析失败**（`１／２＋－＝（）` 报 `Op(text=-)`），归一规则漏一种组合。
4. 数学：希腊 `ο/Ο` 与部分重音无表项（抛异常、不静默，行为正确但缺专项单测）；图例候选超一屏只打包首屏；归一器对「房屋」类细线图墨点翻倍。
5. 数学页 6 点 / 8 点选中态只有 `checked`，没有 `stateDescription`，TalkBack 可能不报当前档位。

### 1.4 技术债里真正会咬人的两条

- **半开蓝牙链路无超时**（`ReadThread.kt:112` 阻塞 read 无 `setSoTimeout`）：点显器没电或离身后界面仍显示「已连接」但不出点，自动重连整条不启动，只能拔插。对应 54 号文档第 1 条，成本 M。
- **有线点显器几十秒后停更**（11-13 真机现象，未修）：写入撞 1000 ms 传输超时后链路无失败恢复。两条是同一类问题：**「设备还在、输出死了、App 不知道」**。

## 2 目标

**四周内产出一个「真机可用」的候选发布版**，标准是：

1. 一台真实点显器（metec 40 方有线 / 清华 V3 / 无界 BLE，有哪台算哪台）能连接、能读、能翻页、能输入，连续用 30 分钟不出现「点显器停住但 App 不知道」。
2. 已知缺陷 1.3 的第 1、2、3 条修掉并有回归用例。
3. 工作区干净：所有成果已提交、已推远端；`发布/` 里有一个带版本号、已签名、附发布说明的 release 包。

---

## 3 方案原则

- **真机是唯一的验收口径**。模拟器全绿只算「离线通过」，不算「功能完成」。
- **每批必须落盘**：改完就提交，不再出现两天成果全在工作区的情况。
- **一条红线不动**：盲文输出正确性、断连恢复、TalkBack 语义、已支持点显器兼容性（沿用 50 / 65 号四条红线）。
- **新功能冻结**：数学与触觉图在拿到真机反馈前不再扩功能，只修缺陷。

## 4 阶段安排

### 阶段 0 · 收口（半天，今天可做）

1. 把工作区现有成果提交成一个（或「数学」「触觉图」两个）提交，提交信息写明「模拟器已验、真机未验」。
2. 推送远端，确认 `origin/main` 与本地一致。
3. 根目录约 100 个 `.tmp-*` 日志（合计 55.5 MB）**保持原样**：`.gitignore` 已明确「只忽略，不删除、不移动」，不搬；`docs/.acceptance-*.log` 已补进忽略规则。两份 `.so_backup_*` 先留着，等阶段 4 确认 release 包正常后再删。
4. `docs/README.md`：补 74–77 号索引，69 号条目的 golden 数改成 20/20，把「当前重点」改成「真机验收 + 稳定性」，与新方针一致。

### 阶段 1 · 修已知缺陷（2–3 天）

| 顺序 | 缺陷 | 做法 | 验收 |
|---|---|---|---|
| 1 | 多行三段式失败 | `rebuild` 的 catch 落异常类型与消息；`Session.build` 各阶段补日志；`wrapIntoScreens` 逐行 try/catch，翻译服务不可用时封面封底降级为空屏 | 40×4 / 20×4 / 20×3 各 6/8 点在模拟器出书，补一条 JVM 用例复现原异常 |
| 2 | 阅读器重复汉字 | `reconstructSource` 改为每个源片段只在首格 append 一次 | 用 `cbs_test.txt` + 新导入一本 txt 对比屏显与源文一致 |
| 3 | 全角减号 | `MathFullwidth` 补该组合，L15 入单测 | L15 出 `OBSERVE` 以外的确定结果 |
| 4 | 小项 | `ο/Ο` 表项或可读报错 + 单测；数学页 6/8 点加 `stateDescription`；图例多屏分页 | 对应单测绿 |

每修一条提交一次，全量单测 + `assembleDebug` 过了才算完。

### 阶段 2 · 真机验收闭环（3–5 天，含等设备）

这是整个方案的关键一关，需要你配合插设备。

- 设备优先级：朋友那台 metec 40 方有线 → 清华 V3 → 无界 BLE。
- 验收清单（每项记 PASS / FAIL / 未测，写进 `docs/78-真机验收报告.md`）：
  1. 连接：插线 / 配对后 30 秒内出点，播报一句「已连接」。
  2. 阅读：打开一本 txt，翻页 20 次不丢、不卡；断开重连后自动恢复。
  3. 输入：点显器键盘打一句话上屏，回显 1.5 秒后还原。
  4. 触觉图：单行视口总览 → 细节 → 平移 → 图例，边界短震能感觉到。
  5. 数学：推 3 条公式到点显器，6 点 / 8 点各一次，看第 7/8 点是否真亮。
  6. TalkBack：三入口标签、焦点顺序、liveRegion 主动播报实听。
- 发现的问题按 1.3 的格式登记，严重的回流到阶段 1。

### 阶段 3 · 稳定性债（1 周）

1. 蓝牙读循环加读取超时 + 心跳看门狗，接入既有退避重连（54 号第 1 条）。
2. USB 写入超时后的失败恢复：超时即断链重连，不再只能拔插（11-13 真机现象）。
3. 50 号 #9「设备守护」最小版：断线先响一声再自动连，电量广播只在设备支持时启用。
4. 真机复测 30 分钟连续使用。

### 阶段 4 · 发布工程（3–5 天）

1. release 签名接入（16 号文档缺口），`.so` strip，确认 release 体积回到 21 MB 量级。
2. versionCode 35、versionName 1.1，`发布/` 命名统一为 `linxi-<版本>-<日期>.apk`，附一份可朗读的发布说明。
3. K80 与模拟器各装一次 release 包冒烟。

### 阶段 5 · 新功能（真机反馈之后）

按 65 号文档的顺序，全部带 feature flag 默认关：

- N1 转译体检单 → N3 打印预检 → N4 桌面比对台（都是 S 量，不改主链）
- N2 真值对语料 500 句（把「防重构」的测试变成「防错译」的测试）
- 之后才是 N6 用户规则覆盖、N9 拍照即读 v2；触觉图与数学的真机反馈决定它们是继续投入还是降级为实验功能。
