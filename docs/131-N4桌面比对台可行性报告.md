## 2 Q2 · 口径差人工判定指引（本报告核心价值）

> 警告（沿用 65 §2.1）：liblouis 中文表与自研链路的分词口径不同，**差异不等于我们错**。比对台只负责把两边点位串并排列出，「谁错」必须按本节顺序人工判定；只有判定为我们真错的条目才收进错题库。

### 2.1 两边链路事实（本地依据，可复核）

### 2.2 判定前置：先排除工具链噪声（不算口径差，更不算真错）

拿到一句差异，先按下面顺序排掉环境性原因；任何一条不满足，该句挂「工具链待复查」，不进入人工对错判定。

1. **表与版本一致**：两边必须用同一张表（首版锁定 `zhcn-cbs.ctb`），表文件路径、版本/校验号记入 CSV。一侧误用 `zhcn-g1.ctb`（现行标调）或 `zhcn-g2.ctb`（双拼）时，整句差异不可比。
2. **编码与未覆盖字符**：确认输入为 UTF-8；未在表内定义的字符被透传或丢弃，属覆盖度问题，单独记 `undefined` 类型，不按点位错判。
3. **空格与全半角归一化**：比对前统一全半角、首尾空白；词间空格是分词产物，先单独标注，不混进点位差异。
4. **同一句、同一输入**：确认两边拿到的原文一致（含标点、数字、外文大小写）。
5. **盲文透传字符**：U+2800–U+28FF 点位字符在我们侧是直通映射，不重译；这类片段不参与 liblouis 比对。
   出处：`TranslatorService.java` `translateWithBraillePassThrough` 方法注释。

### 2.3 六类口径差的判定顺序（从最常见到最少见）

排除噪声后，按下述顺序逐类核对。每类先给「判为口径差的条件」，再给「判为真错候选的条件」。

#### 2.3.1 分词边界（词间空格位置）

- 现象：两边点位序列里，空格（空方）落的位置不同；相邻音节的点位本身相同。
- 判为口径差（分词口径）：对齐到单字后，每个字的声、韵、调点位一致，仅词界空格位置不同。成因是我们 jieba/词表切分与 liblouis 内部成词不同，属分词口径差，归档 `known-difference`。
- 判为真错候选：词界差异伴随某个字的声韵调点位改变（空格切断后触发了不同的词组规则或单字规则），转入 2.3.2/2.3.6 继续核。
- 规则依据：GF 0019-2018 §12 分词连写规则；GB/T 15720-1995 §6.2 分词连写。

#### 2.3.2 连写 / 分写（语节合并与切开）

- 现象：同一词组，一侧整体连写、一侧拆成两段或多段；或一侧在汉字/字母间插了连接号（我们侧复合词边界用 U+2824 点 36 连接号，见 `mergeLetterHanziCompounds`）。
- 判为口径差（连写口径）：拆开/合并之后，各字内部点位一致；差异只是语节切分。我们侧的连写/分写词表是显式产品决策（`segment_connect.txt`「多连少分」、`sunshine_split.txt` 阳光分写），与表内默认分组不同属预期分歧。
- 判为真错候选：合并后某字被 `always` 词组规则改成与单字规则不同的点位，且该词组读音/词义在本句语境不成立；或连接号位置导致两词粘连成另一语义。
- 特别注意：liblouis `always` 词组规则要求词组字面连续出现；我们侧分词在词组内部插空格会使规则不触发（这正是 `liblouis_phrases.txt` 5075 条保护词组存在的原因，见 `tools\gen_liblouis_phrases.py` 注释）。这类「我们插空格 → 表内词组简写未触发」先记为分词口径差，不直接记错。

#### 2.3.3 简写 / 缩写（contraction）

- 现象：一侧用单字简缩方，一侧用双拼全写。
- 表内已知简缩（`zhcn-cbs.ctb` 头部说明与 `sign` 条目）：
  - 的 ⠙⠢ 简为 ⠙（点位 145）
  - 么 ⠍⠢ 简为 ⠍（134）
  - 你 ⠝⠊⠄ 简为 ⠝（1345）
  - 他 ⠞⠔ 简为 ⠞（2345）
  - 她 ⠞⠔⠁ 简为 ⠞⠁（2345-1）
  - 它 ⠁⠞⠔ 简为 ⠈⠞（4-2345）
- 判为口径差：简缩与否的差异由 2.3.1/2.3.2 的分词边界引起（词组被切开，简缩规则未命中），词内点位仍一致。
- 判为真错候选：一侧使用了 GF 0019 §11 简写规则之外的简缩；或该简缩在本语境造成同音混淆；或规定应简缩的高频字漏简（需结合 §11 简写规则逐条核，不靠感觉）。
- 出处：GF 0019-2018 §11 简写规则（同上 moe PDF）；表内条目见 `zhcn-cbs.ctb` 上述 `sign` 行。

#### 2.3.4 声调（调号有无与位置）

- 现象：同一音节一侧有调号方、一侧没有；或调号点位不同。
- 先认体系：`zhcn-cbs.ctb` 是通用盲文，总原则「字字标调」，再按声母规则省写部分调号；不是现行盲文「需要时标调」体系。
  出处：GF 0019-2018 §10.1（每个音节都标调、变调标本调）、§10.2（按声母省写）；答记者问说明通用盲文与现行盲文标调差异：http://www.moe.gov.cn/s78/A19/moe_814/201805/t20180521_336624.html
- 已核实的省写规则（§10.2，摘自方案 PDF）：
  - 声母 f 省写阴平符号；
  - 声母 p、m、t、n、h、q、ch、r、c 省写阳平符号；`tóu` 不省；
  - 声母 b、d、l、g、k、j、x、zh、sh、z、s 省写去声符号；`lè`、`zì` 不省；
  - 韵母自成音节 ō、ó、ǒ、ò 的声调符号省写；ē、é、ě、è 不省写（§10.2.6）。
  - 其余自成音节特例（§10.2.5）以方案 PDF 原文为准，判定时逐条核对，不凭记忆。
  - 需要调号提供点位参照或区分音义时，调号不省写（§10.2.8）。
- 判为口径差：调号有无符合上述省写规则（一侧按规则省、一侧按全标显示），或差异来自分词上下文导致的规则触发不同。
- 判为真错候选：违反省写规则（该省不省 / 不该省却省）；调号点位错（阴平 1、阳平 2、上声 3、去声 23，轻声无符号）；变调音节标本调还是变调标错；省写后造成同音歧义且规则要求保留调号。

#### 2.3.5 标点与混排

- 现象：标点点位不同；标点前后空格不同；中外文/数字与汉字边界处理不同。
- 判为口径差：标点点位一致，仅前后空格、连接号、中英分隔位置不同；数字整体保护、数字+字母单位合并等我们侧的分词规则（`mergeNumberUnit` 等）造成的边界差异。
- 判为真错候选：标点点位本身与方案 §8 不符；标点被吞、错位或重复；外文/数字被当成汉字音节误拼。
- 表内标点条目数：仓库 `zhcn-cbs.ctb` 82 条 `punctuation` 规则（本机统计）。

#### 2.3.6 读音（多音字与单字音）

- 现象：某字声母或韵母点位与参考侧不同（不是调号问题）。
- 判为口径差：读音选择不同但两读在本句语境都成立，且属词表/分词层面的多音词组保护差异（对照 `always` 词组读音）。
- 判为真错候选：语境读音选错（多音字读破）；字表内未覆盖该字导致兜底错误；声母/韵母点位与方案音节表不符。此类型优先级最高，直接进存疑池交人工。

### 2.4 判定结论枚举与归档去向

每条差异句人工判定后，结论只能取以下之一：

- `acceptable-difference`：口径差，可接受（注明 §2.3.x 哪一类、哪条规则）。进语料，来源标工具+口径差。
- `ours-wrong`：我们侧真错。进错题库/N2 防错译档，附出错字与首个差异格。
- `lou-wrong`：liblouis 表侧错（或表版本过时）。记录但不改我们引擎；另立表侧问题清单，不记为我们的错。
- `disputed`：两人/两次判定不一致，或规则无明文。留待产品负责人或规范文本裁决。
- `pending`：尚未判定。存疑池初始状态。

判不准的句子不许默认成「口径差」放行，也不许默认成「我们错」入库；一律 `pending` 进存疑池。

### 2.5 已知可预期口径差清单（落地后按实际语料回填）

- 词界空格位置： jieba 切分 vs 表内成词，最高频。
- 四字成语/三音节整体概念的连写分写：我们侧 `segment_connect.txt` 与阳光分写库的显式决策，与表内默认分组不同。
- 高频虚词简缩是否触发：受分词空格影响。
- 数字、外文单位、化学式、书名号内片段的保护与合并规则。
- 表版本差：仓库派生表与官方 3.39.0 包内表字节数不同（`zhcn-cbs.ctb` 仓库 1,096,206 字节 / 官方包 1,064,683 字节）；首版须固定用哪一张表并在 CSV 记录。

## 4 Q4 · `tools/compare/` 输出契约（只设计，不写代码）

### 4.1 目录与产物

- 目录：`tools/compare/`（当前不存在，K-15 落地时新建；遵循 65 §2.1「Python 侧只做离线分析工具」）。
- 产物一：`diff_report.csv`，逐句并列两边点位串与差异标记，供人工判定。
- 产物二：下游 N2 语料 YAML（字段见 §4.7），由 CSV 经三道筛流转生成；未人工复核的条目不进防错译档。
- 运行环境约定：`D:\bb-tools\venv` 独立环境；表文件路径、liblouis 版本号写入 CSV 头部元数据行，保证可复现。

### 4.2 点位串编码约定（两边必须同一种编码）

- 每一方点位串默认用 Unicode 盲文图案字符（U+2800–U+28FF）逐格表示，格间用半角空格分隔；空方用 U+2800。
- 另存一份点位编号记号（如 `145-26`）供读屏/点显核对，二选一作主展示，另一份作附注；编码版本号写进 CSV 头部。
- 字符串内不混入换行；标点格、数字标志格与汉字格同样按格计数。

### 4.3 `diff_report.csv` 字段定义

顺序固定如下，缺字段留空，不留占位符。

1. `sent_id`：句号（序号，如 S0001）。
2. `source_text`：原文（该句完整文本）。
3. `ours_cells`：自研链路点位串（App 现有分词 + 翻译链路的导出结果）。
4. `lou_cells`：liblouis 参考侧点位串（Python 绑定 + 锁定表）。
5. `table_id`：比对所用表名（首版 `zhcn-cbs.ctb`）。
6. `table_version`：表文件版本/校验（文件大小或校验值，便于发现表被换过）。
7. `match_status`：`equal` / `diff`。
8. `diff_positions`：差异位置（对齐后首个差异格序号，多个用逗号分隔；对齐不上时记 `unaligned`）。
9. `diff_type`：差异类型枚举，见 §4.4。
10. `rule_basis`：命中的口径条目编号（引用 §2.3.x 与 GF0019 章节号；口径不明留空）。
11. `bucket`：三道筛分流结果，`consistent` / `known-difference` / `suspect`。
12. `decision`：人工判定列，`pending` / `ours-wrong` / `lou-wrong` / `acceptable-difference` / `disputed`。
13. `reviewed_by`：判定人。
14. `reviewed_at`：判定日期（YYYY-MM-DD）。
15. `note`：备注（语境、多音字、存疑点等自由文本）。

### 4.4 差异类型枚举（`diff_type`）

- `segmentation`：分词边界（词界空格位置不同）。
- `joining`：连写/分写（语节合并、切开、连接号差异）。
- `contraction`：简写/缩写（单字简缩、词组简缩触发与否）。
- `tone`：声调（调号有无、位置、省写规则）。
- `punctuation`：标点点位或前后空格、混排边界。
- `reading`：读音（多音字、单字音声母韵母差异）。
- `undefined`：未覆盖字符透传/丢弃。
- `tooling`：工具链噪声（编码、归一化、表版本不一致等，待复查）。

### 4.5 三道筛分流（产品负责人 2026-11-26 决定，口径以此为准）

判定顺序即 §2 的人工判定指引：

1. **第一道 · 工具判一致**：`match_status=equal` → `bucket=consistent`，直接进语料，`source=tool`。按 §4.6 比例抽检。
2. **第二道 · 差异但属已知口径差**：`match_status=diff` 且能按 §2.3 归入已知口径差、`rule_basis` 可填条目 → `bucket=known-difference`，进语料，`source=tool`，标记「工具+口径差」。按 §4.6 比例抽检。
3. **第三道 · 差异且口径不明**：`bucket=suspect`，进存疑池交人工；人工判完才归档为 `ours-wrong` / `lou-wrong` / `acceptable-difference` / `disputed`。

### 4.6 抽样比例与工作量估算（500 句规划口径）

抽样比例（首版建议，首批 50 句试点后用实测返工校准）：

- 存疑池（suspect）：抽检 100%，全部人工判定。
- 一致项（consistent）：抽检 5%–10%。
- 已知口径差（known-difference）：抽检 10%。

单句工时假设（规划值，试点后回填）：存疑句 1.5 分钟/句（需摸两边点位串、对照规则下结论）；抽检句 0.5 分钟/句。

三档差异分布情景下，500 句的人判量与工时（数字为本机计算器实算）：

- 低差异（一致 80% / 口径差 10% / 存疑 10%）：人判 75 句（存疑 50 + 一致抽检 20 + 口径差抽检 5），约 87.5 分钟，≈ 1.5 小时。
- 中性（一致 60% / 口径差 20% / 存疑 20%）：人判 125 句（存疑 100 + 一致抽检 15 + 口径差抽检 10），约 162.5 分钟，≈ 2.7 小时。
- 高差异（一致 40% / 口径差 25% / 存疑 35%）：人判 197.5 句（存疑 175 + 一致抽检 10 + 口径差抽检 12.5），约 273.75 分钟，≈ 4.6 小时。

说明：差异分布在首版工具跑出真实语料前无出处、未实测；上述比例与工时是规划假设，抽检句数按比例四舍五入取整；第一批 50 句（125 §3 判据）跑完后必须用实测句数和分钟数替换。

### 4.7 N2 语料 YAML 字段设计

每条语料一个条目，字段：

- `id`：句号，与 CSV `sent_id` 对应。
- `source_text`：原文。
- `ours_cells`：自研点位串。
- `lou_cells`：liblouis 点位串。
- `source`：`tool`（工具产出）或 `human`（人工直接录入/纠正）。
- `bucket`：`consistent` / `known-difference` / `suspect`。
- `diff_type`：同 §4.4 枚举。
- `rule_basis`：引用的口径条目（§2.3.x 或 GF0019 章节号）；口径不明留空。
- `decision`：同 §2.4 枚举。
- `reviewed_by`：判定人；未复核留空。
- `reviewed_at`：判定日期；未复核留空。
- `tier`：`blocked-error`（防错译档）/ `pending-review`（待判定档）。
- `note`：备注。

分档规则（硬规则）：

- 仅当 `reviewed_by` 非空、`reviewed_at` 非空，且 `decision` ∈ {`ours-wrong`, `lou-wrong`, `acceptable-difference`}，条目才进 `blocked-error` 防错译档。
- 其余一切条目（含全部工具直出、未复核条目）只能进 `pending-review` 待判定档，不许进防错译回归。
- `source=human` 的条目同样要填 `reviewed_by` / `reviewed_at` 才能升档。

### 4.8 风险声明

工具筛本身可能漏错（把真错判成一致）；抽检比例越低，漏检概率越高。`consistent` 与 `known-difference` 两档在未经人工抽检复核前，其「正确」只是工具结论，不等同于人工确认；因此 §4.7 规定未复核条目一律不进防错译档。抽检比例下调时，必须同步在语料统计里记录漏检风险上升，不得静默缩小抽检面。
