# 95 · 屏幕按书页显示，点显器独立推送

## 需求

「书籍正文还是要按正常的书籍内容显示，盲文只是在后台翻译，后台推给显示器和显示屏幕没有任何关系……你不需要知道手机显示多少行，显示多少行都是正常的」

即：屏幕是**普通电子书**（按版面排页、翻页、页码），点显器是后台翻译出的盲文流，按它自己的方数独立推进；两边只共享一个「当前位置」，不要求同一个单位。

上一版（94 号的延伸做法）把页单位改成「连上点显器时一页 = 点显器一屏（30 方）」是错的：那会把一本 3MB 书拆成十三万页，屏幕只剩十二个汉字一页，而且屏幕排版被迫跟着点显器走。

## 改动

`brailleback/.../BrailleReaderActivity.kt`

- `readingUnit()` 回退为**只按屏幕自己的排版**：`mCellsPerLine × mLinesPerPage`（由 Compose 实测的「一行几个字 × 几行」× 2.5 方/字换算），与点显器方数、连接状态完全无关。
- `showPage()`：屏幕正文**从本页起点**（`mPageOffsets[currentUnit()]`）开始铺满一整屏，`screenAt(mCellsPerLine, mLinesPerPage)`；不再从 `mOffset`（点显器那一格）起渲染，所以点显器在页内推进时屏幕不抖、跨到下一页才翻页——像看一本正常的书。
- `sendToDisplay()` 不变：仍然从 `mOffset` 起、取到词边界为止的一屏（点显器自己的 30 方），与屏幕页起点无关。
- `onScreenTextMetrics()`：页单位变化就 `rebuildPageOffsets(keepPosition = true)` 重建页表，位置与点显器推送都不动。
- 新增日志：`page table: unit=… pages=… connected=… displayCells=…`、`display state=… cells=…`。

## 验证（真机）

```
17:03:08 screen metrics: chars=18 lines=30 -> cells=45 lines=30 unit=1350
17:03:08 page table: unit=1350 pages=1215 connected=false displayCells=40 keep=true
17:03:08 screen metrics: chars=18 lines=22 -> cells=45 lines=22 unit=990
17:03:08 page table: unit=990 pages=1708 connected=false displayCells=40 keep=true
17:03:11 display state=1 connected=true cells=30
17:03:11 page table: unit=990 pages=1708 connected=true displayCells=30 keep=true   # 连上点显器，页单位不变
17:04:00 send: from=3240 to=3270 len=30 display=30                                 # 点显器从当前位置推 30 方
```

- 页单位只随屏幕排版变（竖屏 45×22 = 990 方/页），接上/断开点显器都不再改页表（那两次重建 pages 相同）。
- 点显器按自己的 30 方从 3,240 起推，屏幕显示的是 3,240 所在那一页的整页正文（约 396 字），两者互不牵制。
- `brailleback 955 例 / service 226 例` 全过。

## 保留的两条独立规则

- 屏幕：页 = 屏幕一屏；`上一页/下一页` 走页表；页码 = 页号 / 总页数。
- 点显器：一屏 = 驱动上报方数（30）；按键与长按都按这一屏步进，且回退到词首不劈字（见 93 号）。

两边共用的只有 `mOffset`：点显器在页内推进时屏幕不动，推到下一页起点时屏幕才翻页、页码才变。
