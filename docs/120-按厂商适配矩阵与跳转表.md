## 1. 平台级判定顺序

服务「开不起来」的四种成因（从未开启 / 受限设置 / 被清理关闭 / 疑似高级保护）是**平台级、按行为判定**的，不按厂商分支。判定信号、顺序与用户动作见《119》第 5 节，本节不重复粘贴全文。

一条边界：**受限设置与厂商无关，是 Android 13 起的平台能力；厂商差异只体现在自启动 / 加锁 / OTG 这些步骤上。** 工程代码里，厂商分支只允许出现在两处：① 自启动引导的 Intent 候选；② 是否出现「加锁」步骤。

## 2. 通用路由（各厂商共用的平台项）

| target | 判定代理 | 首选候选 | 回落候选 |
| --- | --- | --- | --- |
| 无障碍服务 · 从未开启 | 启用列表中无本服务，且不在设置页 | `android.settings.ACCESSIBILITY_SETTINGS` | 应用信息页 |
| 无障碍服务 · 受限设置 | 刚从设置返回仍 false，API ≥ 33 | `android.settings.APPLICATION_DETAILS_SETTINGS`（带本包名） | 无兜底 |
| USB 权限 | `UsbManager.deviceList` 有设备且任一已授权 | 应用信息页 | 无其他公开入口 |
| 电池优化 | `PowerManager.isIgnoringBatteryOptimizations` | `android.settings.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`（带本包名） | `android.settings.IGNORE_BATTERY_OPTIMIZATION_SETTINGS` |

被清理关闭（`CLEANED_BY_SYSTEM`）的补救路径复用该厂商的自启动候选，回落应用信息页；疑似高级保护（`AAPM_SUSPECTED`，API ≥ 36 且受限路径连续失败 ≥2 次）App 无法程序化检测，只给文案并标 `UNKNOWN`，不带跳转候选。

## 3. 分厂商 Profile

### 3.1 小米 / HyperOS（含 Redmi、POCO）

- **独有坑**
  - 自启动默认关闭，需手动允许。
  - OTG 有独立开关，闲置约 10 分钟自动关闭；连接后若断链，需重插一次。
  - 「应用管理 → 手动管理」路径曾被用户踩过：USB 权限可能被自动管理拦掉。
- **可跳 target 与候选组件（按顺序逐个 try）**
  - 自启动：① action `miui.intent.action.OP_AUTO_START`（官方 FAQ 提供）；② 显式组件 `com.miui.securitycenter/com.miui.permcenter.autostart.AutoStartManagementActivity`。全失败回落应用信息页。
  - USB 权限、电池优化：走第 2 节通用路由。
- **系统不开放 Intent、只能文字引导的步骤**
  - OTG 开关与闲置自动关闭：无可用直达 Intent，页面只给文字指引（设置 → 更多设置 → OTG；断链重插）。
- **来源**
  - 小米澎湃OS开发者平台《开发最佳实践与兼容性建议（适配常见问题）》：<https://dev.mi.com/docs/appsmarket/technical_docs/adaptation_FAQ/>
  - 《自启动权限管理说明》：<https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1624>

### 3.2 华为（EMUI / HarmonyOS 4 兼容 Android 侧）

- **独有坑**
  - 官方支持页明确：清理后台或重启设备后，已开启的第三方无障碍服务开关会自动变回关闭（服务被清理后起不来，系统识别为关闭）。
  - 解决路径：重新打开开关 + 多任务界面下拉卡片加锁 + 手机管家 → 应用启动管理里关「自动管理」，并开「自启动 / 关联启动 / 后台活动」三开关。
- **可跳 target 与候选组件**
  - 启动管理：显式组件 `com.huawei.systemmanager/com.huawei.systemmanager.startupmgr.ui.StartupNormalAppListActivity`；失败回落应用信息页。
  - 加锁：多任务下拉卡片手势完成，无直达 Intent。
  - USB 权限、电池优化：走通用路由。
- **系统不开放 Intent、只能文字引导的步骤**
  - 多任务下拉加锁；手机管家内三个开关的勾选动作。
- **来源**
  - 华为官网《华为手机/平板无障碍中的第三方应用的服务开关自动关闭》（`zh-cn00410039`）：<https://consumer.huawei.com/cn/support/content/zh-cn00410039/>
  - 《应用启动管理，管控应用活动》：<https://consumer.huawei.com/cn/support/content/zh-cn00441262/>

### 3.3 荣耀（MagicOS）

- **独有坑**
  - 官方支持页：Launch / App launch → 关闭 Manage automatically → 勾「Run in background」→ CONTINUE；另需电池优化设为「不限制」；再在多任务里下拉加锁。
  - 无障碍被清理后关闭的问题与华为共用同一套平台级文案（见 119 第 5 节成因 3），不另造厂商口径。
- **可跳 target 与候选组件（按顺序逐个 try）**
  - 启动管理：① `com.hihonor.systemmanager/com.honor.systemmanager.startupmgr.ui.StartupNormalAppListActivity`；② 老版本 MagicOS 复用华为组件 `com.huawei.systemmanager/com.huawei.systemmanager.startupmgr.ui.StartupNormalAppListActivity`；失败回落应用信息页。
  - 加锁：多任务下拉手势，无直达 Intent。
- **系统不开放 Intent、只能文字引导的步骤**
  - 多任务下拉加锁；电池优化「不限制」的勾选。
- **来源**
  - Honor Support《An app running in the background restarts when re-accessed》：<https://www.honor.com/global/support/content/en-us00406916/>
  - Honor Support《Apps launch slowly》：<https://www.honor.com/global/support/content/en-us00406923/>

### 3.4 OPPO / 一加 / realme（ColorOS）

- **独有坑**
  - 「应用速冻」：后台超过约 5 分钟未使用即冻结。
  - 「允许自启动」与「允许关联启动」**开任意一个即免速冻**，两个都关才生效；另需「允许后台运行」（耗电保护）。文案必须写清「这两个开关任开一个就行」，不让用户两个都开。
- **可跳 target 与候选组件（按顺序逐个 try）**
  - 自启动：① `com.coloros.safecenter/com.coloros.safecenter.permission.startup.StartupAppListActivity`；② `com.oppo.safe/com.oppo.safe.permission.startup.StartupAppListActivity`；失败回落应用信息页。
  - USB 权限、电池优化：走通用路由。
- **系统不开放 Intent、只能文字引导的步骤**
  - 耗电保护内「允许后台行为」的勾选。
- **来源**
  - OPPO 客服《应用速冻的介绍》：<https://support.oppo.com/cn/self-service/#/articleDetail/?aid=SI2106885>
  - OPPO 客服《软件保持后台运行的方法》：<https://support.oppo.com/cn/self-service/#/articleDetail/?aid=2088176>
  - OPPO 开放平台《OPPO手机应用自启动管理说明》：<https://open.oppomobile.com/documentation/page/info?id=10165>

### 3.5 vivo / iQOO（OriginOS / Funtouch）

- **独有坑**
  - 加速白名单靠**卡片式后台里按住应用下滑加锁**，**没有可用 Intent 直达**——只能文字指引，并明说「这一步必须在多任务界面用手势做」。
  - 另有「后台高耗电」白名单。
- **可跳 target 与候选组件**
  - i 管家自启动：显式组件 `com.vivo.permissionmanager/com.vivo.permissionmanager.activity.BgStartUpManagerActivity`；失败回落应用信息页。
  - 电池优化：走通用路由。
- **系统不开放 Intent、只能文字引导的步骤**
  - 卡片后台按住下滑加入加速白名单（加锁）：纯手势，无 Intent。
- **来源**
  - vivo 客服《如何设置加速白名单》：<http://kefu.vivo.com.cn/robot/imgmsgData/fbf3c38f576042a780629b173ba9ff6d/index_1.html>

### 3.6 三星（One UI）

- **独有坑**
  - 接近原生，主要坑在「USB 配置」默认用途被选成「仅充电」，导致枚举不到设备。
- **可跳 target 与候选组件**
  - 不自启厂商启动管理页；电池走标准 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`；USB 权限走通用路由。
- **系统不开放 Intent、只能文字引导的步骤**
  - 连接后 USB 用途的切换（系统下拉面板内选择，无第三方直达 Intent）。

### 3.7 原生 / Pixel（Generic）

- **独有坑**
  - 无厂商专属坑。
- **可跳 target**
  - 只保留平台三项：无障碍服务、USB 权限、电池优化。**不出现任何厂商专属文案，不出现加锁 / OTG 项。**
- **系统不开放 Intent、只能文字引导的步骤**
  - 无。

## 4. 无 Intent 可达步骤汇总

| 步骤 | 出现于 | 原因 | 页面呈现方式 |
| --- | --- | --- | --- |
| 多任务卡片下拉加锁 | 华为、荣耀、vivo | 系统未开放直达 Intent；vivo 明确为卡片后台手势 | 纯文字指引，行不可点，无候选与兜底 |
| OTG 开关与闲置自动关闭 | 小米 | OTG 开关无公开直达 Intent；10 分钟闲置自动关闭 | 纯文字指引，行不可点 |
| USB 用途切换 | 三星及通用场景 | 系统下拉面板内选择 | 文字提示，结合 USB 权限项 |

### 5.3 本机无法构造的档位及原因

- **被系统清理关闭（CLEANED_BY_SYSTEM）**：未在真机复现。尝试经 `settings put secure enabled_accessibility_services` 追加本服务后，MIUI / API 37 立即把整表剥离清空（读回 `null`，`Enabled services:{}`），服务无法经 adb 启用；`everEnabled` 历史落在 DataStore，不便由调试通道手注。该档判定顺序与文案由单测锁死（`everEnabled=true` + 当前 false → CLEANED_BY_SYSTEM）。
- **受限设置（RESTRICTED_SETTINGS）**：未在真机复现。adb 会话式安装通常被信任，但本机未提供可触发「允许受限设置」弹窗的场景；文案「应用信息 → 右上角三点 → 允许受限设置 → 输入锁屏密码」由单测与资源核对，不编造截图或推断结论。
- **疑似高级保护模式（AAPM_SUSPECTED）**：App 无法程序化检测；API 37 上观察到的未验证服务被剥离现象，与受限设置 / 已验证无障碍工具限制方向一致，但不足以判定为 AAPM，按口径只给文案并标 `UNKNOWN`。
