# 64 · 连接方式三项化与提示收敛

## 背景

设置页「连接方式」原来列了 6 项：

`auto` / `hid_ble` / `hid_usb` / `usb_serial` / `serial` / `hid_classic`

这 6 项是把「传输通道」直接暴露给用户（`connection_transport` 键），
用户看到的是 HID、串口、经典蓝牙之类的通道名，而不是「我想怎么连」。
同时，打开设置页会立即触发后台自动连接，进度逐条 `announceForAccessibility`，
读屏用户一进页面就被灌一串「正在扫描…正在连接…」的提示。

用户要求：

> 把连接选项，减少一下自动连接、蓝牙连接和有线连接，给它合并一下，只保留这三个，
> 另外打开软件，各种连接提示，也可以不要提示那么快，只有点击连接的时候才有提示。

## 三项化的做法：只留「协议」一层

不新增枚举，直接把 UI 切到本来就存在、天然三值的 `connection_protocol` 键
（`auto` / `bluetooth` / `usb`），用已有的数组
`pref_connection_protocol_values` / `pref_connection_protocol_entries` 渲染对话框。

选中某一项时：

- 写 `connection_protocol`；
- 把 `connection_transport` 复位为 `DEFAULT_TRANSPORT_AFTER_PROTOCOL_PICK`（= `auto`），
  顺带清掉历史残留的 `hid_usb` / `serial`，避免旧的通道值继续生效。

服务端补两处语义，保证「蓝牙」真的是蓝牙：

| 位置 | 改动 |
| --- | --- |
| `HidTransportRouting.resolve()` | 新增 `protocolValue == BLUETOOTH -> BLUETOOTH`：协议选蓝牙时，插着线也不被拽去 USB |
| `HidTransportRouting.shouldReactToUsbAttach()` | `else` 改为 `protocolValue != BLUETOOTH`：蓝牙协议下不响应 USB 插入广播 |

### 补回缺失的资源

`pref_connection_protocol_bluetooth_label` 与 `pref_connection_protocol_usb_label`
原来被数组引用却根本没定义（数组一直没被使用，所以从未暴露）。三项化后必须存在，已补。

另加三条对话框摘要：

- `compose_settings_protocol_summary_auto`
- `compose_settings_protocol_summary_bluetooth`
- `compose_settings_protocol_summary_usb`

## 提示收敛：成功念一句，失败全静音

原始诉求是「打开软件不要一串提示，只有点击连接时才提示」。实测后用户进一步明确：
**连接成功可以出声，连接失败那一串可以不出声**——失败细节（扫描、尝试、找不到设备、
驱动表不匹配）本来就是一堆连续文案，读屏用户听不完。于是最终策略是：

### 1. 主设置页（`SettingsActivity`）

- `onConnectionChangeProgress`：进度只记录，不朗读。
- `onConnectionStateChanged`：只在「上一次不是已连接、这一次是已连接」时念一句
  `connstate_connected`；失败与断开不播报，只更新状态行。

### 2. 应用内连接页（`DeviceConnectionComposeActivity`）

- 进度（`onConnectionChangeProgress`）一律不出声。
- `connectedAnnounced` 标志保证每一轮连接**只念一次「已连接」**；离开已连接状态即复位。
- 用户点「断开连接」后，`awaitingDisconnectAnnounce` 仍会在落到未连接时念一句「已断开」，
  这是用户自己动作的回执，保留。
- 其余状态跳变（含失败）只写状态行，不朗读。

## 契约测试连带改动

- `ComposeMigrationContractTest`：原先钉 `.putString(protocolKey, protocolForTransport)`，
  改为钉新写法 `.putString(protocolKey, next)` + `DEFAULT_TRANSPORT_AFTER_PROTOCOL_PICK`。
- `HidTransportRoutingTest`：补两条断言——`resolve(BLUETOOTH, AUTO, 插线=true) == BLUETOOTH`；
  `shouldReactToUsbAttach(BLUETOOTH, AUTO) == false`。

## 中文文案补齐

`values-zh-rCN/strings.xml` 原先缺 `pref_connection_protocol_bluetooth_label` /
`_usb_label` / 三条 `compose_settings_protocol_summary_*`，中文界面会混进英文。
本次一并补上；同时把 `pref_connection_protocol_auto_label` 从
「自动（插着点显器走 USB，没插走蓝牙）」缩成「自动」，
因为 Compose 行是「label · summary」，长 label 会和摘要重复念一遍。

## 已知取舍

- 连接失败的整串细节不再出声，只在状态行显示；如果用户需要复述一次，聚焦状态行即可听到。
- 「有线 USB」仍然要经过 brltty 驱动表匹配；没有匹配设备的线插上去只会得到失败文案。

## 回滚方式

改动集中在：

`brailleback/src/main/java/com/linxi/brailleback/compose/DeviceConnectionLogic.kt`、
`DeviceConnectionScreen.kt`、`DeviceConnectionComposeActivity.kt`、
`brailleback/src/main/java/com/linxi/brailleback/SettingsActivity.kt`、
`service/src/main/java/.../HidTransportRouting.kt`、两份契约测试与 `strings.xml`。

`git revert` 对应提交即可；`connection_transport` 的历史值不受影响（只在选中时被复位）。
