## 为什么这么切

**Activity 侧**按闭环分簇，互不共享可变状态：

- 导航簇围绕页表/窗口/版面几何，与点显推送、导出互不重叠；
- 翻译簇围绕待译文本、盲文流增量与片段，自成后台循环；
- 文件 IO 与解码、点显推送、进度持久化各是独立闭环；
- 导出与目录书签都是「读 Activity 状态 → 弹对话框/后台线程 → 回填状态或播报」，不碰翻页状态。

**Screen 侧**按部件分：弹窗只依赖标题、条目与回调；正文列表自成一条可滚动焦点流（「key 用下标」的约定跟着列表走）；滑块是反复调过的独立部件，一个部件占一个无障碍节点，手势判定、Canvas 绘制与语义声明自成体系。

主文件保留：生命周期（`onCreate/onResume/onPause/onDestroy`）、连接状态广播、输入监听匿名对象、`startTranslation`/`applyTranslatedChunk`、三个 SAF 导出启动器、`showExportMenu` 的翻译闸门、伴生常量与 `PendingTranslation` 等数据类。

## 调用方怎么接

- **Activity 侧**：`onCreate` 装配与事件转发处按原方法名调用同包 `internal` 扩展函数；扩展经 `BrailleReaderActivity` 接收方访问放宽后的 `internal` 字段/方法；伴生常量在扩展文件内以 `BrailleReaderActivity.X` 限定引用；`TranslatedChunk` 转为顶层 `internal data class`，同包直接引用。不引入 DI 框架。
- **Screen 侧**：`BrailleReaderScreen` 调 `ReaderBodyList(modifier = Modifier.weight(1f), uiState, onTextMetrics, onTopSegment, onNeedMoreSegments)`——`weight` 由调用方传入，保住根 Column 的 `ColumnScope` 接收者；弹窗分发处按原签名调同包 `internal` 弹窗；两处 `ScrubberBar(...)` 调用的签名与实参不变。
- 对外类型与签名未改：Activity 类名、`ReaderUiState`、`ReaderDialog` 各子类、阅读器入口 `EXTRA_URI` 原位保留。

## 踩过的坑

- 嵌套数据类 `TranslatedChunk` 随翻译簇搬到顶层后，同包直接引用即可；若仍留在 Activity 体内，扩展文件里每处都要写宿主限定名。
- 扩展函数访问伴生常量必须写限定名，裸名在扩展文件内解析不到；被访问的私有成员按需放宽 `internal`，方法体、注释、缩进逐字未动。
- 本轮合并自动完成、无冲突；`compileDebugKotlin` 走缓存通过，未出现新的编译错误或契约失败。

## 代价（已知、明确的）

- 一批宿主字段/方法/常量由 `private` 放宽到 `internal`，模块内可见性扩大，不暴露到模块外。
- 阅读器导航/翻译/导出逻辑分散到 7 个 Activity 协作文件，追踪调用时按文件名后缀（Navigator/Translation/FileLoader/Pusher/ProgressStore/Export/TocBookmarks）定位。
