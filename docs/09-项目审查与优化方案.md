# 09 - 项目审查与优化方案（2026-09-02）

> 审查基线：迁移终点 93.0%（HEAD `0efaed3`），全量编译绿，76 单测全绿。
> 审查范围：5 个模块全部源码 + 构建配置 + 资源。方法：模式扫描（死代码/异常处理/线程）、
> 引用可达性分析、资源对照、构建产物检查。

## 一、总体判断

代码健康度良好：迁移后类型安全显著提升、核心纯逻辑（解码/分页/排版）有测试兜底、
DisplayManager 双线程模型经逐点复核无并发错误、已知耗电热点已有对策（事件合并 100ms、
motion-mode 刷新合并、空闲清屏）。

**没有需要立即修复的崩溃级问题**。优化空间集中在三类：
① 直接影响盲人使用体验的资源问题；② 大面积死代码拖累构建与 APK；③ 工程化欠账。

## 二、P0 —— 影响使用体验（建议本周内做）

### P0-1 43 条字串缺中文翻译（听读屏会念英文）
- 实测：`values/strings.xml` 217 条 vs `values-zh-rCN/strings.xml` 174 条，缺 43 条。
- 缺失集中：声音功能全部（`sound_name_*` 24 条、`sound_scheme_*` 3 条、
  `sound_editor_volume`、`pref_sound_*` 6 条）+ `brailleback_setup_title`、
  `checkmark_checked/not_checked`、`pref_connection_protocol_default`。
- 影响：中文设备上设置页/声音方案名被 TalkBack 念英文，体验割裂。
- 方案：补齐 43 条中文；**建立预防机制**——新增字串必须中英双写（架构文档已有约定，
  可加一个 10 行的检查脚本挂进编译前校验）。
- 成本：约 1 小时。风险：零。

### P0-2 真机验证欠账（唯一未验证面）
- 清单（架构文档已列）：点显器刷新/翻译模式/书架 SAF/前台服务/targetSdk 35 行为/16KB 对齐。
- 迁移后新增：IME 输入（BrailleIME.kt）、蓝牙切换（toggleBluetoothConnection）、
  平移策略切换（DisplayManager + WrapStrategy 全 Kotlin 化）。
- 方案：接真机按清单逐项点测；有文件日志兜底（设置→开发者选项→查看调试日志），
  现场问题可直接导出日志。

## 三、P1 —— 稳定性与可维护性（建议 1-2 周内）

### P1-1 死代码清理：libraries/utils 约 5100 行（占模块 46%）
引用可达性分析结论（排除模块内部相互引用后确认）：

| 死代码簇 | 规模 | 说明 |
|---|---|---|
| MIDI 全簇（com.leff.midi 26 文件 + MidiUtils + examples） | ~3300 行 | 自封闭，App 模块 0 引用 |
| TtsEngineUtils | 370 行 | 0 引用（brailleback 不做 TTS） |
| ExploreByTouchHelper + ObjectHelper | 581 行 | 0 引用（无自定义视图场景） |
| ContrastSwatch + ContrastUtils | 389 行 | 0 引用 |
| GestureOverlay + TouchGestureControlOverlay | 345 行 | 0 引用 |
| ScreenshotUtils / AutomationUtils / PackageManagerUtils / SparseIterableArray / ScreenDimensionUtils | 585 行 | 0 引用 |

- 影响：`minifyEnabled false`（见 P2-1）下死代码全部进 APK 的 DEX；同时拖慢编译。
- 方案：按簇逐个 `grep -w` 全仓复核（防反射引用）后分批删除，每批独立提交 + 编译绿。
  **MIDI 簇最确定，先删**。
- 成本：半天（含复核）。风险：低（都是 0 引用叶子节点）。

### P1-2 关键纯逻辑补测试
- 现状 76 个测试全在阅读器链路；迁移最重的 3 个类零测试：
  - `WrapStrategy`（平移/避头尾点/折行——502 行纯逻辑，JVM 可测，**价值最高**：
    国标排版规则回归全靠它）
  - `DisplayManager.Content.translateWithVerbatimBraille`（三分段拼接逻辑，
    可构造 FakeTranslator 测 left/mid/right 拼接与游标映射）
  - `DisplayManager` 静态位置映射（textToDisplayPosition/displayToTextPosition 边界：
    -1、越界、cursor 优先）
- 方案：每处 5-8 个用例，预计 +25 tests。这是迁移后唯一没有安全网的改动面。
- 成本：1 天。风险：零（只加测试）。

### P1-3 printStackTrace 23 处 → 统一走 LogUtils
- 分布：CompatUtils(8)、FeedbackController(4)、LabelOperationUtils(3)、
  ZipResourceExtractor(2)、其他 6 处。
- 背景：文件日志（LogFileWriter）已上线，但异常若走 printStackTrace 就**不会进文件日志**，
  真机排障时盲区。
- 方案：机械替换为 `LogUtils.log(x, Log.ERROR, "...", e)`，独立提交。
- 成本：1 小时。风险：低。

## 四、P2 —— 工程化（择机）

### P2-1 Release 构建策略
- 现状：`minifyEnabled false` + debug 签名。个人侧载可用，但：
  APK 14MB（其中 native .so 22MB 未压缩为大头）、无混淆、死代码全量打包。
- 建议（按序，每步真机回归）：
  1. `splits { abi { enable true } }` 拆分 v7a/arm64 → 单 ABI APK 约省 1/3 体积；
  2. minify 暂缓开启——开启需补 JNI/反射 keep 规则（libbrlttywrap/liblouiswrap、
     手写 AIDL、LabelProvider 内容提供器），**收益小风险大，不建议现在做**；
  3. 签名保持 debug（自用场景）。
- 另：`ndk.abiFilters` 若确认无 32 位点显器用户，可只留 arm64。

### P2-2 CI（GitHub Actions）
- 单 workflow：`gradle testDebugUnitTest assembleDebug`（配置缓存已开，约 1 分钟）。
- 前提：仓库托管到远端；纯本地 git 则无必要。

### P2-3 杂项清理
- `brailleback/src/.../WrapStrategy.java.bak-avoidhead` 备份文件混在 src 里 → 删；
- `DisplayManager` 的 SELECTION_DOTS/FOCUS_DOTS 可做成偏好设置（上游 TODO，
  用户可感知的显示定制，低优先）；
- BrailleReaderActivity 885 行持续增长——架构文档已定"暂不拆"，超过 1200 行再议。

### P2-4 性能（低优先）
- 耗电三热点已有对策；本次审查未发现新的主线程 I/O 或轮询问题。
- 若真机仍感觉耗电：优先查 `DisplayService` 蓝牙扫描策略与 OverlayDisplay 的
  主线程视图刷新频率，再议。
