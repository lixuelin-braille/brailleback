# 123 - 阳光阅读链路移植（PUA docx 解码 + 30→40 方重排）

> 日期：2026-11-26
> 分支：`feat/sunshine-docx`，基线 `61c7a6c`（= origin/main）
> 来源：旧工程 `BrailleFileDecoder.kt` / `SunshineDocxTest.kt` / `assets/yangguang.ttf` 只读移植；独立 worktree，不合并 main、不 push。

## 1. 背景与范围

中国盲文图书馆电子盲文 docx：正文是 Unicode 私用区（PUA）字符，U+E234～U+E273，
每个字符一个盲文方，空方 U+E273；既不是汉字，也不是 U+2800 标准盲文。

基线 `61c7a6c` 这条链路整体缺失：无 PUA 解码；`detectKind` 只认 U+2800 盲文、汉字、
Braille ASCII，PUA 三不沾会被落进 TEXT 当明眼文字送翻译；无按词装行的重排层；无阳光字体。

本轮按迁移清单逐条落地。红线：不动阅读器翻页语义（`ReaderPageNavigator` 的 unit 分页
口径、翻页/折行判据）、不动 `ScrubberBar`、`ime/`、点显器主链；不引三方依赖；不改播报
文案口径。

> ⚠️ **关键缺口：本轮只做到「解出 PUA 正文」，还做不到「在点显器上摸到」。**
>
> - **屏幕侧**：docx 已能解出 PUA 正文、判为盲文、按实际文本列数重排；
> - **点显侧**：没有 PUA→点位映射（`toDots` 的 `SUN_MIN..SUN_MAX` 分支未移植，
>   属点显器主链，本轮按红线未动）。真机上把书推到点显器时，PUA 字符拿不到点位，
>   **点显器会是空白方，摸不到盲文**；
> - 这条映射要**单独一轮补**，**不属本轮范围**。在此之前，阳光书只能在屏幕侧看到
>   PUA 文本，点显链路不通。

## 3. 数据流

1. `ReaderFileLoader.loadBytes()`（后台线程）：先 `decodeSunshineDocx(bytes)`，
   `isSunshinePua` 命中 → `reflowSunshine` 走盲文链路；未命中 → 仍交
   `EbookTextExtractor` 提取进翻译链路；其余格式走 `decodeDocument`。
2. `decodeDocument(bytes, fileName, textCells)`：docx/docm 分支解码阳光正文后按
   实际文本列数重排；bdo/bdoc 走 Bword 结构化解码；其余按文本解码。
3. `detectKind` 最前面的 PUA 分支把阳光正文判为 `BRAILLE` → `setBrailleStream`，
   不进翻译服务。

## 4. 重排规则（实验版，只对阳光 docx 生效）

- 空行分段；段内按原书空方切成「词 / 空方段」逐 token 装行，能放进当前宽度的词不挪
  下一行，不拆词、不吞连续空方。
- `mergeTinyTail`：段尾只剩 1～2 个非空方（30→40 重排把最后一词挤成孤行）时，把
  上一行最后一个词连同其后空方并回来；只挪最后一词 + 其后空方，原词间空方保留。
- 行内规则：
  - U+E257（三十六点）续行：优先于短行判断，删标记后直接接，不插空方；
  - 行首恰好两个空方：原书新段落缩进标记，结束当前段并插空行（段落跳转快捷键只认
    空行断点），新段保留两方缩进；
  - 段内短行紧跟空行：视为标题，原样单独一行；
  - 其余短行：视为页码，按「2 空方 + 页码 + 2 空方」内联到上一行后；
  - 下一行已以空方开头、或上一行结尾已有空方：不重复插；其余正文接缝插一个空方；
  - 目录行（≥3 个 U+E243 引导点）原样保留。
- brf / bdo / brl / txt 一律不调用重排，保持原样。

## 5. 宽度取值来源与兜底口径

- **来源**：连上点显器时，`displayProperties.numTextCells`（驱动上报的实际文本列数）
  → `mDisplayCells`；`loadBytes` 把它传给 `decodeDocument` 的 `textCells` 与
  `reflowSunshine` 的 `width`。
- Metec 点显器共 42 格 = 40 文本列 + 2 状态格；状态格不参与正文排版。文本列数以
  驱动上报的 `numTextCells` 为准，本层不猜设备方数。
- **兜底**：未连接 / 未上报（`<=0`）或明显越界（`>256`）时回退
  `SUNSHINE_DEFAULT_TEXT_CELLS = 40`，与阅读器 `DEFAULT_CELLS` 一致；`reflowSunshine`
  另对宽度做至少 1 方守卫。
- 待真机核对：若驱动上报的是总格 42 而非文本列 40，状态格扣除（-2）规则本轮未做，
  需接上真实点显器确认 `numTextCells` 口径后再定。

### 7.1 `yangguang.ttf` 取证：谁加载过它、当前路径吃不吃它

**旧工程（只读参照）加载点——属于阅读器屏幕渲染层，不在解码链路：**

  Typeface**，点阵不靠这个字体；`BrailleFileDecoder.kt` 是纯文本解码，全程不碰字体。

**当前侧（worktree 基线 `61c7a6c`）渲染路径取证：**
