## 0. 结论先看

- 123 只通了屏幕侧：阳光 docx 能解出 PUA 正文、判为盲文、按列数重排；
  但推到点显器时 PUA 字符拿不到点位，点显器输出空白方。本补丁把

## 1. 缺口位置（码点从哪进来、在哪一步丢失、在哪一步补）

链路（阅读器 → 点显推送）：

1. `ReaderFileLoader.loadBytes()`：`decodeSunshineDocx` 解出 PUA 正文，
   `isSunshinePua` 命中后走盲文链路，`reflowSunshine` 重排；
2. `detectKind` PUA 分支判 `BRAILLE`，正文进 `mStream`（PUA 字符原样保留，
   不送翻译服务）；
3. `ReaderDisplayPusher.sendToDisplay()`：`cellsAt(mStream, offset, len)`
   取本屏字符（`cellsAt` 只把 `\n` 换成空方，PUA 字符原样带出）；
4. 逐方构造 patterns：`patterns[i] = (BrailleFileDecoder.toDots(cells[i]) and 0xFF).toByte()`，
   再 `display.displayDots(patterns, cells, map)` 推到点显器。

丢失步骤：补丁前的 `toDots`（`BrailleFileDecoder.kt`）只有两条出路——
- U+2800..U+28FF：标准 Unicode 盲文，`code - 0x2800`；
- 其余：`asciiToDots(c)`，按 `code - 0x20` 查 NABCC 表，查不到返回 null。

PUA 码位既不在 U+2800 段，也不在 Braille ASCII 段，`asciiToDots` 返回 null，
`toDots` 兜底返回 0 → 推到点显器的就是全 0 空方。这正是 123 §1 记的
「做了但摸不到」。

修补步骤：在 `toDots` 里、ASCII 兜底之前，增加 `SUN_MIN..SUN_MAX` 分支。
改动只在这一个函数，未动解码、判定、重排、推送链路本身。

## 2. PUA 区间与映射规则

常量（`BrailleFileDecoder.kt`，123 已带入）：

- `SUN_MIN = 0xE234`，`SUN_MAX = 0xE273`，`SUN_BLANK = 0xE273`；
- 区间共 64 个码位：U+E234～U+E272 为 63 个实方，U+E273 为空方。

映射规则（六点掩码，0～63）：

- U+E234～U+E272：`dots = code - 0xE233`（即 `code - (SUN_MIN - 1)`），
  得 1～63；
- U+E273（空方）：`dots = 0`；
- 位序与本仓库既有盲文位序一致：点 1 = bit0(1)、点 2 = bit1(2)、
  点 3 = bit2(4)、点 4 = bit3(8)、点 5 = bit4(16)、点 6 = bit5(32)。

取证依据：`service/jni/liblouiswrapper/liblouis/tables/zhcn-cbs.ctb`
第 31096～31159 行 `noback sign` 序列：

- `\xE234 1`（点 1，掩码 1）
- `\xE236 12`（掩码 3）、`\xE237 3`（掩码 4）
- `\xE240 134`（掩码 13）、`\xE243 5`（掩码 16）
- `\xE253 6`（掩码 32）、`\xE257 36`（掩码 36）
- `\xE26B 456`（掩码 56）、`\xE272 123456`（全六点，掩码 63）
- `\xE273 0`（空方）

同一序列也出现在 zhcn-g1 / zhcn-g2 / zhcn-cbs-homophone / zhcn-g1-toned-full
各表。64 个组合 = 2^6，掩码上限 63，故为六点制；点 7/8（高位）不参与。

1. `sunshine PUA range matches liblouis table`
   解析 zhcn-cbs.ctb 的 `noback sign` 行，对 U+E234～U+E273 全 64 个码位
   逐条比对 `toDots` 结果；实际校验 64 个，全部一致（未跳过）。
2. `sunshine PUA endpoints map to dots`
   端点：E234 → 1（点 1）；E272 → 63（123456）；E273 → 0（空方）。
3. `sunshine PUA midpoints spot check`
   中点抽查：E236=12(3)、E237=3(4)、E240=134(13)、E243=5(16)、
   E253=6(32)、E257=36(36)、E26B=456(56)、E272=123456(63)。
4. `codepoints outside sunshine range return blank`
   区间外不误判：E233（下限邻码）、E274（上限邻码）、E000（其他 PUA 段）、
   汉字「中」、空格，均返回 0。
5. `original unicode and ascii paths unchanged`
   原路径零回归：U+2800=0、U+2801=1、U+283F=63；NABCC 抽查
   A=1、B=12、Z=1356、逗号=6。

## 6. 真机验证方法（待真机确认，本轮未做）

以下条目必须接上真实点显器后由有权限的角色核对，本角色结论一律记
「待真机确认」：

1. 准备一本真实阳光 docx 电子书（中国盲文图书馆来源），连点显器后打开；
2. 对照书页已知方核对点位：点 1 方（E234）、全六点方（E272）、空方（E273）
   在点显器上的凸起应分别为单点 1、六点全凸、全平；
3. 连续一行实方：点位左右顺序、上下两列（1/2/3 左列、4/5/6 右列）
   不得镜像或错位；空方之间不得多出误凸点；
4. 翻页、重连后重铺：点位跟随正常，断连恢复行为不变（红线，未改但需回归）；
5. 若真机出现点位左右镜像或缺点，先按印刷书页抽样复核点号位序，
   再判断是否需要位序翻转；当前位序是按 liblouis 表与本仓库既有位序推定，
   未经物理设备确认。
