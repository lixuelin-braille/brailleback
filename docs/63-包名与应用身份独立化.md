# 63-包名与应用身份独立化

> 日期：2026-11-22
> 目标：让本应用不再与 Google 原版 BrailleBack 共享同一个应用身份，消除安装与运行时冲突
> 结果：`applicationId` / `namespace` / 主模块 Java 包名 全部换为 `com.linxi.brailleback`；编译通过、全量单测 1554 例全绿、lint 0 error、模拟器上与 Google 原版并存安装并正常启动绑定

---

## 1. 为什么要换

| 冲突点 | 换之前 | 换之后 |
|:---|:---|:---|
| 安装身份 | `com.googlecode.eyesfree.brailleback`，与 Google 原版逐字节相同 → 同机只能留一个，签名不同则 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | `com.linxi.brailleback`，两个包各装各的 |
| 桌面/设置里的条目 | 与原版同名同图标，用户无法区分 | 独立条目 |
| IME 组件 id | `com.googlecode.eyesfree.brailleback/.BrailleIME`，与原版互斥 | `com.linxi.brailleback/.BrailleIME` |
| 数据目录 | 与原版共用一个 `/data/data/...` | 各用各的 |

实测（模拟器 `brailleback_api35`，原本已装 Google 原版）：

```
安装前：com.googlecode.eyesfree.brailleback / .test
adb install -r brailleback-debug.apk  →  Success
安装后：com.googlecode.eyesfree.brailleback / .test / com.linxi.brailleback
```

两个包同时存在，互不覆盖。

### 刻意**不**换的（契约层，一改就断外部对接）

| 项 | 值 | 原因 |
|:---|:---|:---|
| AIDL 包名 | `com.googlecode.eyesfree.braille.display / selfbraille / translate` | binder 的 interface descriptor 由 `.aidl` 包名生成，服务端 `onTransact` 会 `enforceInterface(DESCRIPTOR)`；消费者（林夕读屏 / TalkBack）用的是各自编译时的那份，改名必抛异常 |
| 2 个自定义权限 | `com.googlecode.eyesfree.braille.display.PERMISSION_CONNECT`、`com.googlecode.eyesfree.braille.selfbraille.PERMISSION_WRITE` | 权限名是授予对象与声明方之间的字符串契约，消费者清单里写着同一个名字 |
| 3 个服务 action | `ACTION_DISPLAY_SERVICE` / `ACTION_SELF_BRAILLE_SERVICE` / `ACTION_TRANSLATOR_SERVICE` | 消费者按 action 查询并绑定，改名后老消费者找不到服务 |
| `service` 模块的 Java 包名 | `com.googlecode.eyesfree.braille.service[.display/.translate]` | `service/jniLibs` 里是**预编译 .so**，`BrlttyWrapper.c` 与 `LibLouisWrapper.c` 共 6 个 JNI 符号写死为 `Java_com_googlecode_eyesfree_braille_service_*`；改 Java 包名等于要重编 brltty + liblouis，否则 `UnsatisfiedLinkError` |
| `addon/` 6 个模块的包名 | `com.google.android.accessibility.*` | 与 TalkBack 盲文键盘同源，JNI 符号同样写死，且 `settings.gradle` 里已有注释说明必须保持 |

## 3. 顺带修掉的共存崩溃

换包名后第一次在“同时装着 Google 原版”的模拟器上启动，`SettingsActivity` 直接崩：

```
java.lang.SecurityException: Not allowed to bind to service Intent {
  act=com.googlecode.eyesfree.braille.service.ACTION_DISPLAY_SERVICE
  cmp=com.googlecode.eyesfree.brailleback/....DisplayService }
  at com.googlecode.eyesfree.braille.display.DisplayClient.doBindService(DisplayClient.kt:256)
```

根因：`DisplayClient` / `TranslatorClient` 按 action 查询到**多个**候选，直接取 `resolveInfo[0]`，碰巧取到 Google 原版的服务；我们的应用没有对方的签名，绑不上。

修法（两处同改，`client` 模块）：

```kotlin
// 自己声明了这个 action 就优先绑自己；否则（林夕读屏等外部宿主）退回原顺序
val serviceInfo = resolveInfo.firstOrNull {
    it.serviceInfo.packageName == mContext.packageName
} ?: resolveInfo[0]
```

这个改法对嵌在别的宿主里的同一份代码是**无行为变化**的：宿主自己不声明该 action 时 `firstOrNull` 落空，仍走 `[0]`。

验证：重装后 `logcat` 出现 `DisplayClient: Bound to braille service`，无 `FATAL EXCEPTION`。

## 5. 用户可见的变化（升级须知）

1. **等于新装一个应用**：桌面出现独立图标，原 `brailleback` 旧包如仍在机上，是另一个应用，不会自动继承设置。
2. **要重新开启两个开关**：系统设置 → 无障碍 → 本应用；系统设置 → 输入法 → 盲文硬件键盘。旧包名下的授权不算数。
3. **旧的本地数据不迁移**：数据目录随 `applicationId` 变更，旧包的 SharedPreferences/DataStore 留在旧目录；如需带走设置，需要另做一次性导出/导入。
4. 同时装着 Google 原版也不会互相覆盖，但**两个都开无障碍服务会抢同一个 action**，只开要用的那个。

## 6. 遗留风险与下一步

**风险 A（真实存在）**：action 名与 2 个权限名仍与 Google 原版完全相同。

- 同机装着原版时，`pm.queryIntentServices` 会解析到两个服务；我们这边的内部绑定已修成"优先自己"，但**外部消费者（林夕读屏 `com.linxi.screenreader`）仍取 `[0]`**，可能绑到原版并对不上签名。
- 自定义权限同名时，后安装方的 `<permission>` 声明会被忽略，`PERMISSION_CONNECT` 实际归属原版（签名级），第三方拿不到 → 点显器链路可能整条不通。

**要彻底隔离，需要第二批改动**（本次未做，避免牵动另一个仓库）：

1. 我们的 3 个 action 改为 `com.linxi.braille.service.ACTION_*`，2 个权限改为 `com.linxi.braille.*`；
2. 同步改 `D:\软件\林夕读屏`（另一仓库）里那份 client 源码的同名常量，否则读屏找不到我们的服务；
3. AIDL 包名与 `service` JNI 包名仍必须保持原样（见第 2 节表格）。

**风险 B**：`addon/` 与 `client/` 的类仍在 `com.google.*` 命名空间下，只是不再影响应用身份；若日后要连包名一起"去谷歌化"，`service` 与 `addon` 必须先解决 JNI 符号重编问题。
