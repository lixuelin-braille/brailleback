# 59 - 输入法主类 BrailleIme 结构拆分

## 背景与目标

`addon/brailleime` 模块的盲文输入法主体 `BrailleIme`（包名
`com.google.android.accessibility.brailleime`）在拆分前是一个 1807 行的大类，
输入法生命周期、读屏/点显器桥接回调、触屏手势与点位输入、两点校准播报、对话框与教程回调、
设置变更联动、系统监听器、输入连接与上屏发布全部堆在同一个文件里。

本次只做**结构拆分**：运行时行为、线程模型、回调时序、对外 API 语义（类名、可见性、
方法签名、常量值）一律不动；资源与文案不改。拆出的协作对象仍在同一包内，主类只保留
输入法生命周期与装配/编排。

## 为什么这样切

- **按数据流切，不按行数硬切**：输入从触屏平面进入（`BrailleImeInputPlaneCallback`），
  经动作执行器（`BrailleImeActor`，既有文件）落到编辑缓冲；点显器与读屏是两条平行的
  宿主桥接（`BrailleImeDisplayBridge` / `BrailleImeTalkBackBridge`）；对话框、教程、
  视图三类回调各自收口；设置联动与系统监听器是旁路；连接与上屏发布是所有回调共用的
  基础能力。每条数据流对应一个文件，避免再次互相缠绕。
- **校准播报单独成类**：触屏平面回调与朝向检测回调都会触发两步校准提示与重复播报，
  共享同一个 Handler、语音流水号和文案，因此抽到 `BrailleImeCalibrationAnnouncer`，
  防止两套 Handler 与文案分叉。
- **主类保留编排权**：生命周期回调（`onCreate`/`onStartInputView`/`onFinishInputView`/
  `onDestroy` 等）、视图装配、激活/停用编排、Actor 与手势控制器的创建仍在 `BrailleIme`，
  协作对象在 `onCreate` 链路里装配；主类不直接持有各回调的实现细节。
- **可见性处理**：被协作对象跨文件调用的原私有成员放宽为 `internal`（同模块可见），
  对外公开/受保护的生命周期方法、`testing_*` 测试钩子签名与 `OrientationSensitive`
  嵌套接口保持不变；`internal` 不暴露给模块外调用方，对外 API 语义不变。

## 契约测试同步

新增源码文本契约测试：

`addon/brailleime/src/test/kotlin/com/google/android/accessibility/brailleime/BrailleImeSplitContractTest.kt`
