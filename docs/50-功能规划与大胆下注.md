# 50 · 功能规划：三条主线与三次大胆下注

> 这份文档是产品规划，不是工程约束清单。它的作用是先把「值得做、敢做」的东西摆出来，
> 工程可行性放在每条的「技术落点」里，而不是放在决策前面。

## 0 先把「不敢动」的枷锁拆掉

过去几轮我确实太保守，原因有两个，都真实存在：

1. **744 个用例里有一大批「源码契约测试」**，它们读源码文本断言现有行为。任何重构都会撞红，撞红就得改测试，改测试就会被当成「为了过测试而弱化约束」。
2. **没有可用设备**（`adb devices` 为空），触觉类改动无法端到端验证，于是倾向于「不动最安全」。

但这两条都不该阻止产品往前走。解法是三层隔离，而不是不做：

| 层 | 规则 |
| --- | --- |
| 新功能入口 | 一律走 **feature flag**（默认关，设置页「实验功能」里开），关掉时零代码路径、零资源占用 |
| 新功能代码 | 放**独立包/独立模块**，核心文件（`DisplayManager`、`keymap/`、`BrailleIME`）只加**一行钩子**，不改内部逻辑 |
| 契约测试 | 分两档：**已发布行为**（不许破，继续钉死）；**实验行为**（跟着功能走，允许随迭代重写）。文档里明确哪条属于哪档 |

**可以犯的错**：做得难看、先上个丑 MVP、做完推翻重来、指标不达标直接删。
**不能碰的**：盲文输出正确性、断连恢复、TalkBack 朗读语义、已支持点显器的兼容性。这四条一破，用户当天就没法用手机。

## 1 用户是谁（决定取舍）

主用户：在校盲生（中医康复专业），设备组合是 **点显器 + 手机 + 蓝牙键盘**，场景按时间排序是：课堂听讲、教材与讲义、记笔记、写作业、通勤、读书。
次用户：成年盲人工作者，需求是**读文档、回消息、查资料**。

明确不做：给明眼人看的「无障碍演示」「宣传视频」类功能——那不是这个 App 的用户。

## 2 三条主线

- **A 学习线**：课堂上把听到的东西变成能摸的盲文；把纸面教材变成能摸的盲文。
- **B 阅读线**：网页、文档、书籍的「结构化降噪」——盲文屏只有一行十几格，噪声就是成本。
- **C 交互线**：输入与设备——让点显器不只是显示器，而是终端。

## 4 三次大胆下注

### 注 1：反向翻译引擎（盲文 → 汉字）

**赌什么**：这是本项目**最大的空白**，也是所有「输入类」功能的地基（笔记、写作业、发消息、搜索）。现在只有汉→盲，没有盲→汉。做成之后，点显器从「只读终端」变成「可写终端」，产品性质变了。

**最小验证**：不做全量。先做「单句、无缩写、一级盲文」的盲→汉，语料用你自己写的 50 句中文盲文，人工标注正解。准确率 ≥ 90% 再往下做二级与缩写。

**失败判据**：50 句样本准确率 < 60%，或歧义造成的错误无法用「候选列表」补救。那就退回「只做关键词纠错」，不做完整输入。

**退出成本**：独立包 + 纯 Kotlin 纯函数，删掉不影响主链。

### 注 2：实时语音 → 盲文（课堂模式）

**赌什么**：这是他每天真实发生 4–6 小时的场景。做好了，上课不用再靠听记，摸到的就是笔记骨架。别家读屏软件都没做这件事，因为它要「识别 + 分词 + 分页 + 低延迟」四件事同时成立。

**最小验证**：一段 10 分钟课堂录音（自己录），跑通「识别→分词→点显器」离线回放；用「用户能跟上讲授速度」作为唯一指标，延迟 < 2 秒、字数吞吐 ≥ 每秒 4 字才算过。

**失败判据**：延迟降不到 3 秒以内，或分词错误导致语义拧巴（摸不懂）超过 1/3 句子。

**退出成本**：`lecture/` 独立包，flag 关掉即消失。

### 注 3：点显器第二屏（协作模式）

**赌什么**：点显器一直是「一个人用」的设备。让它变成**两个人的界面**——明眼人看手机、盲人摸点显器、同步翻页——会打开课堂、办公、家庭三个场景。这是别人没做的产品假设。

**最小验证**：同一段教材，手机与点显器同源；明眼人翻一页，点显器跟一页，偏差 0；盲人按点显器上的键，手机屏同步高亮。

**失败判据**：同步延迟 > 0.5 秒让人感到「两套东西」，或明眼人操作会把盲人的位置挤掉。

**退出成本**：`copilot/` 独立包。

## 5 排期建议

| 批次 | 内容 | 为什么这个顺序 |
| --- | --- | --- |
| 第 1 批（4 周） | #9 设备守护 → #1 课堂流 MVP → #8 文件互转 | 前两个是「每天都在用」的痛点，第三个是纯工程、零风险，先把 flag 机制和「实验功能」入口跑通 |
| 第 2 批（3 月） | #2 拍照即读 → #4 页面降噪 → #6 生词本 | 都以「把噪声压掉」为核心，共享分词与分页改造 |
| 第 3 批（6 月） | #3 盲文笔记（依赖注 1） → #5 表格 → #7 乐谱 | 依赖最重的放最后，前面批次会顺手把反向翻译的语料攒出来 |
| 并行实验轨 | #11 口袋点显、#12 学习游戏 | 可以随时砍，成功就当彩蛋，失败也算把触觉参数摸清了 |

## 6 验收指标（都用盲用户视角，不用工程指标）

1. **单位时间摸到的有效字数**：同一篇文章，新功能 ≥ 现有实现的 1.3 倍。
2. **首次可用时间**：新功能从打开到听到第一行有效内容 ≤ 10 秒、≤ 3 步操作。
3. **误操作可撤销**：任何改变内容的动作，必须一键回到上一步。
4. **断连/崩溃**：连续用 30 分钟不出现「点显器停住但 App 不知道」。

## 7 需要拍板的三件事

1. **先做哪条主线**：A 学习线（课堂流）与 C 交互线（设备守护）谁先。
2. **能不能上云**：语音识别与大模型摘要如果走云端，效果明显更好，但课堂内容会离开设备。可接受「本地优先 + 用户显式选择云端」吗？
3. **实验功能默认隐藏**：我倾向默认关闭、在「实验功能」里逐项打开，避免主流程被半成品污染。是否同意这个默认？
