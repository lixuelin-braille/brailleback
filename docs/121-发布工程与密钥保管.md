## 2. 签名密钥位置与保管

### 2.1 文件位置（均在仓库外）

| 文件 | 绝对路径 | 说明 |
|---|---|---|
| release keystore | `D:\keys\brailleback-release.jks` | RSA 4096 密钥与自签证书 |
| keystore 密码 | `D:\keys\brailleback-release-密码.txt` | 与 keystore 同目录；**本文件、文档、版本库均不记录密码明文** |

仓库内只有一个被忽略的 `keystore.properties`（字段：`storeFile` / `storePassword` / `keyAlias` / `keyPassword`），用于把本机构建接到上面的 keystore；它本身不进版本库（见 §3）。

### 2.2 密钥参数

| 项 | 值 |
|---|---|
| alias | `brailleback-release` |
| 算法 / 密钥长度 | RSA 4096 |
| 签名算法 | SHA384withRSA |
| 有效期 | 10000 天 |
| 有效期区间 | 2026-11-26 16:39:46 CST → 2054-04-13 16:39:46 CST |
| 证书 DN | `CN=BrailleBack, OU=Braille Service, O=BrailleBack, C=CN` |
| 条目类型 | `PrivateKeyEntry`（自签，Owner = Issuer） |

### 2.3 证书指纹（两处取证，已核对一致）

`apksigner verify --print-certs`（release APK）与 `keytool -list -v -keystore ...`（keystore）取到的指纹：

| 指纹 | 值 |
|---|---|
| SHA-256 | `e0bf6b261930030949a944c815015e477b80723d0bae72c08a2db0d331f1968a` |
| SHA-1 | `753a22f929b93bd6d796aa52db506ea09d21af48` |
| 证书 DN | `CN=BrailleBack, OU=Braille Service, O=BrailleBack, C=CN` |

两处 SHA-256 逐字节一致（`keytool` 输出为冒号分隔大写，去掉冒号转小写后与 `apksigner` 输出相同）。

### 2.4 备份要求（硬性）

- 这份 release keystore 与密码**必须离线备份至少 2 份**（不同物理介质 / 不同地点），例如加密 U 盘 + 离线硬盘。
- **密钥丢失后无法给已安装的旧版本做覆盖升级**：Android 要求覆盖安装包与已装包签名一致；没有原密钥就只能发一个包名不同的新应用，旧用户的阅读进度、书签、点显器配对状态都带不过去。
- 密码与 keystore 分开保管：keystore 一份介质、密码另一份介质，避免单个介质丢失即整体失控。
- 不要在截图、聊天记录、issue、提交信息、构建日志里粘贴密码；`keystore.properties` 只存在于本机工作区。

## 3. 签名配置与入库红线

### 3.1 构建侧回落策略

`brailleback/build.gradle` 读取仓库根 `keystore.properties`：

- 文件存在 → 用 `signingConfigs.release` 签名；
- 文件缺失 → release 回落 `signingConfigs.debug`，**保证别人 clone 仓库后不配置密钥也能 `assembleDebug` / 出 release 包（debug 签名），构建不会因缺密钥而崩**。

### 3.2 永不进版本库的文件（写死）

以下内容**永远不允许提交**到版本库，`.gitignore` 已覆盖：

- `keystore.properties`（第 76 行）；
- `*.jks`（第 77 行）；
- `*.keystore`（第 78 行）；
- keystore 密码文本（`brailleback-release-密码.txt` 等，位于仓库外 `D:\keys`，本就不被跟踪）。

提交前以 `git status --porcelain` 复核：列表里看不到 `keystore.properties`、任何 `.jks` / `.keystore`、任何密码文本。

> 别人 clone 本仓库后只能构建 debug 签名包；要出可发布的 release 包，必须在本机准备同名 keystore 与 `keystore.properties`。debug 证书（`CN=Android Debug`）指纹：`3e81238ce1128b09341a947572d9bbd369974b764e83cea52d673b55b12fd9ac`，仅用于开发自测，**不能用于发布**。

## 4. 签名验证命令与输出摘要

### 4.1 校验 APK 签名（在装有 build-tools 37.0.0 的机器上）

```
apksigner verify --print-certs brailleback/build/outputs/apk/release/brailleback-release.apk
```

本轮输出摘要：

```
V2 Signer: certificate DN: CN=BrailleBack, OU=Braille Service, O=BrailleBack, C=CN
V2 Signer: certificate SHA-256 digest: e0bf6b261930030949a944c815015e477b80723d0bae72c08a2db0d331f1968a
V2 Signer: certificate SHA-1 digest: 753a22f929b93bd6d796aa52db506ea09d21af48
```

退出码 0，校验通过。

### 4.2 从 keystore 侧复核指纹与有效期

```
keytool -list -v -keystore D:\keys\brailleback-release.jks -alias brailleback-release
```

本轮输出摘要：

```
Alias name: brailleback-release
Entry type: PrivateKeyEntry
Owner: CN=BrailleBack, OU=Braille Service, O=BrailleBack, C=CN
Issuer: CN=BrailleBack, OU=Braille Service, O=BrailleBack, C=CN
Valid from: Thu Nov 26 16:39:46 CST 2026 until: Mon Apr 13 16:39:46 CST 2054
    SHA256: E0:BF:6B:26:19:30:03:09:49:A9:44:C8:15:01:5E:47:7B:80:72:3D:0B:AE:72:C0:8A:2D:B0:D3:31:F1:96:8A
Signature algorithm name: SHA384withRSA
```

### 4.3 一致性核对口径

把 `keytool` 的 SHA256 去掉冒号、转小写，与 `apksigner` 的 SHA-256 digest 逐字节比对；两者必须相同。本轮结果：相同（见 §2.3）。
