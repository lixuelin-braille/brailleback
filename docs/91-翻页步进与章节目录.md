# 91 翻页按屏幕一屏步进、目录改用章节标题

## 现象

用户反馈两件事：**翻页好像不起作用**、**目录要优化**。

## 定位

两件事是同一个根：阅读单位按**点显器一屏**（30 方）算。

- 一本 3MB 的书翻出 378 万格，按 30 方一页拆成 **138,302 页**；
- 屏幕正文是 30 方 × 20 行 = 600 方，点一次「下一页」只挪 30 方，
  可见文本几乎不动，看起来就是「翻页没反应」；
- 目录按 10 页一组 → **13,830 条**「第 1-10 页」，全是页码，没有任何内容线索。

顺带查出的第二个坑：`上一页/下一页` 的 `OutlinedButton(onClick=...)` 外面又挂了
`combinedClickable(onClick=..., onLongClick=...)`。同一个按钮两处点击入口，
TalkBack 双击时两条路径都会触发，一次点按走两页——真机上同样像「翻页不对劲」。

## 改动

1. **页 = 屏幕一屏**：`readingUnit()` 改为 `mCellsPerLine * mLinesPerPage`，不再看点显器方数。
   页数从 138,302 降到几千；`上一页/下一页` 一次翻掉整屏，页码、跳页、目录都按这个口径。
2. **点显器按键按方数步进**：`ReaderDisplayKey` 的平移键与上下行键统一走
   `moveLineFromKey`（步长 `mDisplayCells`），一次正好换掉点显器上的一屏；
   单行点显器没有「行」可分，不必为此再造一层。
3. **按钮只挂一处点击**：新增 `ReaderButton`（`Box` + `combinedClickable(enabled = …)`，
   点击/长按/禁用语义一致），替掉 `OutlinedButton` 外套 `combinedClickable` 的双绑定。
4. **目录按章节**：新增 `reader/ReaderChapters.kt`（纯 JVM，可单测）——
   认「第X章/节/回/卷/部/篇/集」与「序言/引子/楔子/尾声/后记/番外/外传/大结局」，
   长度 ≤ 32 字、不以句号逗号收尾，重复标题（目录页 + 正文）只留一条，最多 300 条。
   阅读器把每章起始字映射到盲文流偏移（沿流扫一遍，用逐格源表反查），
   目录条目直接显示章节标题，点一条就跳到那里。
5. **兜底目录**：识别不到章节（纯盲文文件、无标题的书）时仍按页分组，
   但组大小自适应（条目 ≤ 150），标签带上首行原文预览
   （`第3-8页  他走进院子…`），没有原文可取的盲文文件只显示页范围。

## 验证

- 样书《随波逐流之一代军师》：25,982 行里识别出 **236** 个章节标题
  （「第一部 南楚状元 第一章 落魄书生」这种），不再是一条条页码。
- 页粒度：12,047 字的首块 = 16 页（≈750 字/页）；整本 3.78M 格约 5,000 页，
  此前同样内容被算成 138,302 页。
- `ReaderChaptersTest` 6 例（偏移、正文误命中、固定名、去重、上限、空文本）全绿；
  全量单测 947 例 0 失败，lint 0 error。

## 遗留

- 真机手感待验：点显器按键的实际步进、目录长列表（236 条）用 TalkBack 逐条听的体验，
  都需要用户在设备上过一遍。
- 章节识别依赖原文；EPUB/Word 走同一条 `EbookTextExtractor` 文本路径，因此同样生效。
