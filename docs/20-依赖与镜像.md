# 20 - 依赖与镜像

项目一直是「离线缓存构建」（`GRADLE_USER_HOME=D:\cache\gradle`），缓存里有什么就只能用什么。
这份文档记录这次用国内镜像补进来的依赖、试跑结论、以及哪些接了 / 哪些决定不接。

> **2026-11-18 更新**：本机网络已恢复（aliyun google / public 与 Maven Central 均实测 200）。
> 随后做了 [38-依赖解冻](./38-依赖解冻.md)：Compose 1.7.6→1.12.1、activity-compose→1.13.0、
> material3→1.4.0、core→1.19.1、appcompat→1.8.0、coroutines→1.11.0。
> 因此下面表格的性质变了：从「缓存里有没有」变成「值不值得引」。
> 其中 `ui-test-junit4` 现在可以用同版 1.12.1，Compose 交互测试不再被版本卡住。

| `androidx.work:work-runtime-ktx:2.10.0` | 后台任务调度 | 与现有保活/重连机制重复，引入等于架构改动 |
| `androidx.profileinstaller:profileinstaller:1.4.1` | Baseline Profile 安装 | 收益是启动提速，但生成链路要 macrobenchmark 模块 + 设备；先把 targetSdk 与边到边做完再谈 |

## 三、静态检查的试跑结论

| 工具 | 能否解析 Kotlin 2.2 | 报告量 | 决定 |
|:--|:--|:--|:--|
| ktlint 1.3.1 | 能 | **9256 条**风格问题 | **不接门禁**。要接必须先全仓 `ktlintFormat`（248 个文件的巨大 diff），风险大于收益 |
| detekt 1.23.7 | 能 | 真实复杂度问题（见下） | 建议接「baseline + 只拦新增」 |

detekt 报出来的都是真问题，不是风格洁癖：

- `BrailleBackService`：类过大、39 个函数（阈值 11）
- `BrailleBackService.onMappedInputEvent`：圈复杂度 15（阈值 15）
- `BrailleFileDecoder.detectKind`：圈复杂度 17
- `BrailleFileDecoder.collapseBlocks`：嵌套过深
- `BrailleReaderActivity`：45 个函数、`setBrailleStream` 7 个参数
- `BrailleView.onDraw`：84 行、圈复杂度 19

这些正是「`!!` 280 处 + 三个千行级大类」之外的另一种可维护性证据。

## 四、这次真正接进来的能力

`androidTest` 新增 `SettingsCategoryNavigationTest`（3 例），用 UiAutomator 真实点击：

| 用例 | 断言 |
|:--|:--|
| `deviceCategoryOpensDeviceConnectionScreen` | 点「设备与连接」→ 前台变成 `DeviceConnectionComposeActivity` |
| `keysCategoryOpensKeysGesturesScreen` | 点「按键与手势」→ 前台变成 `KeysGesturesComposeActivity` |
| `stabilityCategoryOpensStabilityScreen` | 点「稳定性与省电」→ 前台变成 `StabilityComposeActivity` |

为什么这条值：以前出过「设置里分类点击进不去、没反应」——`settings.xml` 里条目没落进文件，
`wireCategory` 在 null 上静默返回。那种 bug 编译能过、JVM 单测和契约测试全绿，
只有真的用手指点一下才暴露。

实现细节（踩过的坑）：

- **不能用 Espresso**：Preference 的标题是 TextView，`click()` 会报 "View is not clickable"。
- **要滚动**：屏幕小的设备上「稳定性与省电」不在首屏，`By.text` 只命中可见节点，
  找不到就向上滑一次重试（最多三次）。
- **断言前台 Activity** 用 `ActivityLifecycleMonitorRegistry.getActivitiesInStage(RESUMED)`，
  必须在主线程读（`runOnMainSync`），否则拿到正在变迁的状态。
- **模拟器会崩 SystemUI**：连跑多轮 uiautomator 后 `com.android.systemui` 会在
  `FinalizerWatchdogDaemon` 上超时崩溃，接着 `adb install` 报 `Broken pipe`。
  重启模拟器后恢复正常，不是被测代码的问题。

实测：`emulator-5554` 上 `OK (3 tests)`；全量 7 例一起跑 `OK (7 tests)`，12 秒。

## 五、下次要补依赖时怎么做

1. 改 `tools/dependency-probe/build.gradle`（jar）或 `android-probe.init.gradle`（AAR）里的坐标列表。
2. 跑对应命令，确认 `BUILD SUCCESSFUL` 且「解析到 N 个文件」。
3. 主工程 `build.gradle` 里加 `implementation` / `androidTestImplementation`，然后照常 `--offline` 构建。
4. 把「为什么接 / 为什么不接」写进这份文档，别让下一个人重复评估。
