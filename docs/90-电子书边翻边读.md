# 90 电子书边翻边读：先出前几页，其余后台续翻

## 现象

一本 3MB 的小说整本翻译约一分钟。此前必须等整本翻完才铺流，用户打开书后只能对着
「正在翻译」干等；中途失败还会整本退回原文。用户明确要求：**先翻前几页出来能读，
剩下在后台继续**。

## 做法

1. **增量交块**（`translateParagraphs(text, translator, onChunk)`）
   - 逐段翻译，第一块攒够 `FIRST_PUBLISH_CHARS`（12,000 字）就交，之后每
     `PUBLISH_INTERVAL_MS`（2 秒）交一块；收尾再交最后一块。
   - 交出去的是**增量**：`sb.substring(publishedChars)` + 位置缓冲的
     `copyFrom(publishedCells)`。第一版交的是累计全文，UI 侧又当增量往末尾追，
     一本 3.7M 格的书被铺成 18M 字符、页数翻五倍——真机日志一眼看出
     `append: +711605` 这种越来越大块。
2. **UI 侧追加**（`applyTranslatedChunk` / `appendBrailleStream`）
   - 第一块走 `setBrailleStream`（分配位置、记最近打开、建页表），之后只追加：
     `mStream += delta`，页表 `rebuildPageOffsets(keepPosition = true)` 重建，
     当前偏移不动，用户正读的那一屏不会被拽走。
   - 逐格源表不换对象：`CellSourceTable.appendAll(delta)` 往尾部接位置，
     `ReaderSourceModel` 拿着的引用仍然有效。
3. **进度归位**：上次读到的偏移可能还没翻到。第一块先按位置比例落位，把真实目标
   记在 `mPendingRestoreOffset`；等流长越过目标再一次性跳过去并播报
   「已回到上次读到的第 N 页」。
4. **失败不再整本回退**：中途某段翻不出来（含 `OutOfMemoryError`）时，把已经翻好的
   部分交出去并播报「翻译在第 N 段停下，已翻出的 M 页可以先读」；只有第一段就失败
   才退回原文流。

## 验证（真机 24117RK2CC / Android 17，同一本 3MB 小说）

| 指标 | 结果 |
| --- | --- |
| 第一块上屏 | 启动翻译后约 0.6 秒（12,047 字） |
| 后续续块 | 每 2 秒 +120k～130k 字，`append` 记录稳定 |
| 整本收尾 | `translate end: paragraphs=12169 chars=3779328 invalidCells=0` |
| 阅读位置 | `pos=291` 从头到尾不变，未被追加挪动 |
| Dalvik Heap | 峰值 66MB（修复前整本一次性铺流时 229MB 崩） |

单测：`CellSourceTableTest` 全绿；其余 941 例无回归。

## 遗留

- 每续一块都要重建整张页表（3.7M 字符扫一遍）并重绘屏；已实测不卡，但书再大要改成
  只追加页表尾部。
- 用户退出阅读器后后台翻译仍继续（不主动取消），回到正文时追加照常生效。
