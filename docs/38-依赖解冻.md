# 38 · 依赖解冻（把被离线缓存锁住的一代补齐）

> 2026-11-18。前几批所有升级都卡在「本机离线缓存里没有新版本」这一条上，
> 这次实测 `maven.aliyun.com` 与 `repo1.maven.org` 都返回 200，可以联网解析了，
> 于是把主侧依赖一次性抬到当时（2026-11）的稳定版。

## 1. 升了什么

| 依赖 | 改前 | 改后 |
|:--|:--|:--|
| `androidx.compose.ui:ui` 及 foundation | 1.7.6 | **1.12.1** |
| `androidx.compose.material3:material3` | 1.3.1 | **1.4.0** |
| `androidx.activity:activity-compose` | 1.9.3 | **1.13.0** |
| `androidx.core:core` | 声明 1.9.0（实际解析 1.13.1） | **直声明 1.19.1** |
| `androidx.appcompat:appcompat` | 1.6.1 | **1.8.0** |
| `kotlinx-coroutines-android` / `-test` | 1.9.0 | **1.11.0** |
| `androidx.test.ext:junit` | 1.1.5 | **1.3.0** |
| `androidx.compose.material:material-icons-core` | 跟随 compose 1.7.6 | **单独钉 1.7.8** |

没动的：AGP 9.2.0 / Kotlin 2.2.10（Compose 编译器插件必须与 AGP 内置 Kotlin 同版）、
detekt 1.23.7（1.23.8 可用，但升它要重跑整套规则基线，值得单独一批）、
`preference-ktx 1.2.1`（已是该 artifact 最新版）、`timber 5.0.1`（已是最新）。

版本号来源不是猜的：对每个 artifact 拉了 `maven-metadata.xml`，取过滤掉
`alpha/beta/rc/dev` 后的末位稳定版。

## 2. 两个坑

### 2.1 `material-icons-core` 没有 1.12.x

第一次编译直接失败：

```
Could not find androidx.compose.material:material-icons-core:1.12.1
```

这个 artifact **在 1.7.8 之后就不再随 compose 主线发布了**（图标拆到别处）。
而全仓只用到一处 `Icons.AutoMirrored.Filled.ArrowBack`（`SettingsComponents.kt`），
所以给它单开一个 `composeIcons = "1.7.8"` 版本钉最省事——它自己依赖的 compose-ui
会被 Gradle 取高版本解析到 1.12.1。

### 2.2 Compose 1.12 的新 lint 抓到一个真问题

升级后 lint 门禁报 error：

```
BrailleDisplayComposeActivity.kt:183: Error: Reading locale in a non-observable way
in a composable function [NonObservableLocale]
    val systemLanguage = Locale.getDefault().language
```

这不是误报：`Locale.getDefault()` 在 composable 里读不会参与重组，用户切系统语言时
点显器表格的语言分组会停在旧语言。改成可观察的配置：

```kotlin
val systemLanguage = LocalConfiguration.current.locales[0].language
```

同一个文件里另外两处 `Locale.getDefault()`（在非 composable 的普通方法里）不受影响，没动。

## 4. 代价：debug APK 变大

**49.49 MB → 55.99 MB（+6.5 MB）**。主因是 Compose 1.12 的运行时/UI 库本身比 1.7.6 大一圈，
叠加 minSdk 29 之后 dex 不压缩（docs/35 第 4 节）。release 包（混淆 + 资源裁剪）这次没重测，
测了再补数字。

## 5. 回滚

只改 `gradle/libs.versions.toml` 一处即可回到旧版本组合；
`material-icons-core` 的独立钉是随这次一起引入的，回滚时也要一并回到 `compose` 引用。

## 6. 这件事改变了什么

- 之前「升级要先去 `tools/dependency-probe` 确认离线缓存有没有」的约束**不再成立**，
  只要网络在，`libs.versions.toml` 里写新版本就能解析；
- 因此 `docs/20-依赖与镜像.md` 里那张「备选依赖表」的性质变了：从「缓存里有没有」变成
  「值不值得引」；
- 下一步可以真正做 Compose 交互测试了（`ui-test-junit4` 现在能用 1.12.1 同版），
  也能把阅读器 Compose 化提上日程——之前卡住的只是版本，不是设计。
