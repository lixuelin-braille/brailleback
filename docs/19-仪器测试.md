# 19 - 仪器测试（androidTest）

## 为什么补这一层

仓库此前 instrumented test 目录数是 **0**：主模块 50 套件 / 520 用例、service 23 套件 / 164 用例
全部是 JVM 单测。单测和契约测试（读源码字符串断言）能挡住「逻辑回退」，
但挡不住下面这一类问题——它们只在设备上才暴露：

- `res` 里某个 `string-array` / 文案真的不存在或长度不对（编译能过，运行时抛）。
- Compose 屏在 `onCreate` 首次渲染时崩（主题、依赖注入、初始化顺序）。
- Activity 走不到 `RESUMED`（`ActivityNotFound`、权限缺失、`SecurityException`）。
- 资源被 R8 / shrinkResources 裁掉，只在 release 包上才炸。

所以这一层只做**冒烟**：能起来、关键资源读得出来。Activity 级不做 UI 交互断言
（原因见最后一节）；**组件级**的交互断言从 2026-11-18 起有了（见下面的
`ComposeSettingsInteractionTest`），因为它不需要启动 Activity。

## 用例（`brailleback/androidTest/kotlin/.../AppLaunchSmokeTest.kt`，7 个）

| 用例 | 断言什么 | 挡住什么 |
|---|---|---|
| `settingsActivityReachesResumed` | `ActivityScenario` 启动 `SettingsActivity` 到 `RESUMED` | 设置主屏起不来，六个分类入口全无从进入 |
| `stabilityScreenReachesResumed` | `StabilityComposeActivity` 到 `RESUMED` | 保活屏首次渲染崩、资源缺 |
| `stabilityVendorStepsResolveToTwelveEntries` | `stability_vendor_steps` 恰 12 条且非空 | 按厂商切区间，少一条就有一家厂商读到空段落 |
| `settingsCategoryKeysAndProtocolLabelsResolve` | 六个分类 key 能解析、连接方式三项且 `auto` 排第一、`values`/`entries` 等长 | key 缺失导致 `wireCategory` 静默不生效；数组错位导致读屏念错选项 |
| `bookshelfActivityReachesResumed` | `BookshelfActivity` 到 `RESUMED`（基类已换 `ComponentActivity`） | 换基类后 `BraillebackTheme`（`Theme.DeviceDefault`）下窗口挂载失败 |
| `brailleReaderActivityReachesResumed` | `BrailleReaderActivity` 到 `RESUMED` | 同上；且 `onCreate` 里绑点显器客户端失败 |
| `imeWizardLaunchesWithoutThemeCrash` | IME 向导弹窗停在 `RESUMED` 或正常 `DESTROYED` | `Theme.Holo.Dialog` + 新基类的窗口背景报错 |

另有 `ImportFlowSmokeTest`（1 例）：真点一次书架「导入」，断言前台包从本应用切走，
即系统文件选择器真的被拉起。它挡的是「launcher 注册时机 / `CATEGORY_OPENABLE` /
星号 MIME 任一处理错 → 用户点了没反应且无日志」这一类问题。

分类导航的 3 例（设备 / 按键 / 稳定性入口）见同目录 `CategoryNavigationTest`。

新手引导页的 3 例（能起、按钮演示在跑、`onPause` 后协程停下）见同目录
`OverlayTutorialSmokeTest`，对应 [36-界面层协程化](./36-界面层协程化.md) 的改造。

## 组件级交互（`compose/ComposeSettingsInteractionTest.kt`，5 个）

七个设置屏全部共用 `SettingsComponents` 这一套底座，所以补它的点击语义等于补所有屏的骨架。
用 `createComposeRule` 直接渲染组件，**不启动 Activity**：状态由参数传入、动作走回调，
因此不依赖 `TranslatorManager`、点显器连接这些系统资源，能在模拟器上稳定跑。

| 用例 | 断言什么 |
|---|---|
| `switchRowClickReportsNewValue` | 关着的开关行点标题（整行可点）上报 `true` |
| `switchRowWhenCheckedReportsFalse` | 开着的开关行点一下上报 `false` |
| `disabledSwitchRowIsNotClickable` | 禁用态 `assertIsNotEnabled`，且不上报变化 |
| `listRowClickFiresOnce` | 选择行点一次只回调一次（防重复回调 / 双焦点） |
| `actionRowClickFires` | 动作行点击回调 |

挡的是什么：整行 `toggleable` 若被误改成只有 `Switch` 可点、`semantics(mergeDescendants)`
被拆掉导致读屏只念半行、禁用态仍上报、点击穿透触发两次——这些都不会崩，用户只觉得「点了没反应」。

## 设置存储（`SettingsStoreInstrumentedTest.kt`，6 个）

`SettingsStore` 是 DataStore + 内存快照（见 [41-设置存储DataStore化](./41-设置存储DataStore化.md)），
它的正确性只能在设备上验（JVM 单测拿不到 `Context`、`Looper`、真实文件）。

| 用例 | 断言什么 | 挡住什么 |
|---|---|---|
| `applyIsVisibleToImmediateSyncRead` | `apply()` 后不等待、立刻 `getBoolean` 能读到新值 | 快照更新晚于落盘 → 用户点了开关界面不变 |
| `stringSetRoundTripsAndReturnsCopy` | `StringSet` 往返一致，返回集合是副本 | 调用方改动返回集合把存储写坏 |
| `crossProcessKeyLandsInLegacyFile` | `chinese_segmentation` 写进旧 `SharedPreferences` 文件 | `:service` 进程读不到分词开关（无日志、无线索） |
| `legacyValuesAreMigratedOnceAndRemovedFromTheOldFile` | 旧文件里的值迁进 DataStore 且从旧文件消失 | 双源并存：改一处、另一处还是旧值 |
| `listenerIsNotifiedOnWrite` | 写入后监听器被调用（等主线程空闲再断言） | `DisplayManager` 等依赖通知的模块收不到变更 |
| `unsupportedTypeFallbackInsteadOfCrash` | 类型不符回退默认值，不抛 `ClassCastException` | 老用户残留类型不一致的值 → 设置页崩 |

## 依赖怎么选的

只用本机离线缓存里**确认存在**的组合：

```
androidx.test.ext:junit:1.1.5
androidx.test:runner:1.5.2
androidx.test:core:1.5.0     // ActivityScenario
```

刻意不引 `espresso-core`（会顺带拉一堆 androidx 运行时）。
`androidx.compose.ui:ui-test-junit4` 此前也不能引：缓存里只有 **1.10.2**，与当时的 Compose 1.7.6
不同版，混用会在运行时版本冲突。**2026-11-18 网络恢复 + 依赖解冻（[38](./38-依赖解冻.md)）后**
该限制消失，现在 `ui-test-junit4` 与 `ui-test-manifest` 都取同版 1.12.1。

`build.gradle` 里新增 `androidTest` sourceSets（`androidTest/kotlin`），
`testInstrumentationRunner` 原本就是 `AndroidJUnitRunner`，未改动。

## 怎么跑

**不要用 `gradlew connectedDebugAndroidTest`**：AGP 9.2 的该任务依赖
`com.android.tools.utp:android-test-plugin-host-additional-test-output:32.2.0`，
本机离线缓存没有它，`--offline` 下必然失败（实测先报 configuration cache 序列化错误，
加 `--no-configuration-cache` 后暴露真正的依赖缺失）。缺的是依赖，不是缓存配置问题。

改用 `tools\run-androidtest.ps1`（`adb install` + `am instrument`，效果相同）：

```powershell
.\gradlew.bat :brailleback:assembleDebug :brailleback:assembleDebugAndroidTest --offline
powershell -File .\tools\run-androidtest.ps1                      # 默认 emulator-5554
powershell -File .\tools\run-androidtest.ps1 -Serial '10.121.61.209:5555'   # 真机
```

详见 `tools/run-androidtest.md`。

## 跑之前先关掉系统错误弹窗

模拟器桌面（`com.google.android.apps.nexuslauncher`）偶尔 ANR，弹出的「应用无响应」对话框
会**抢走焦点**，被测 Activity 随即 `PAUSED → STOPPED`，UiAutomator 就找不到按钮——
表现为「书架上没找到导入按钮」这种莫名其妙的失败（2026-11-18 实测踩到一次，查 logcat
才看到 `mCurrentFocus=Application Not Responding`）。开跑前执行：

```powershell
adb -s emulator-5554 shell settings put global hide_error_dialogs 1
```

这不是代码问题，也不该靠改测试超时去掩盖。

## 默认用哪个设备

**默认模拟器**，原因：真机装 test APK 会打断用户手上的事，而模拟器开机（headless）约 30 秒、
不占屏幕：

```powershell
& "C:\tools\android-sdk\emulator\emulator.exe" -avd brailleback_api35 `
    -no-window -no-audio -no-snapshot-save -no-boot-anim
adb -s emulator-5554 emu kill      # 跑完就关，别让它一直吃内存
```

只有涉及 native（`BrlttyWrapper`、liblouis、点显器驱动、真实蓝牙/USB 连接）的用例才必须上真机。

## 为什么模拟器能跑（以及什么时候不能）

debug APK 的 `abiFilters` 只有 `armeabi-v7a` / `arm64-v8a`，模拟器是 `x86_64`，包内没有 `x86_64` 的 `.so`。
当前 **25 个用例都不碰 native**：启动设置壳、保活屏、书架、阅读器、IME 向导、新手引导页，
读资源数组，再点一次书架「导入」拉起系统选择器，五例设置组件的点击闭环，
以及六例设置存储（DataStore 快照同步读 / 跨进程键落旧文件 / 迁移 / 监听器 / 类型回退）。
阅读器会 `bindService` 到盲文服务，但不初始化点显器驱动，因此 x86_64 上也起得来。

`BrlttyWrapper`（`System.loadLibrary("brlttywrap")`）只要被类初始化就会在模拟器上
`UnsatisfiedLinkError`。以后要加「盲文服务能起来」「点显器能连上」这类用例，
**必须跑真机**：`-Serial '10.121.61.209:5555'`（会往用户手机装 test APK）。
要彻底解决，可以在 `defaultConfig` 里给 debug 加 `x86_64`，但会让 debug 包变大，
是否值得按需再定。

## 这一层刻意没做的

- **没有 UI 交互断言**（点击分类、进子屏、读朗读文本）。需要同版 `ui-test-junit4`，
  离线缓存里没有；补齐依赖之前不硬凑。
- **没有覆盖无障碍服务本身**。启用服务需要用户在系统「无障碍」里手动授权，
  `am instrument` 无法代做；能自动断言的是服务类的装载与 `onServiceConnected` 之外的部分，
  价值不如「真机上把服务开起来走一遍」，后者仍是人工验收项（见 `docs/17` 的未做清单）。
- **没有接入 CI 的仪器测试门禁**。CI 里没有设备/模拟器，硬加会变成长期红。
  现在它是一条手动命令，改 UI 或动资源数组时跑一次。
