# 33 · 版本目录（gradle/libs.versions.toml）

> 2026-11-17。11 个模块里散落的 `compileSdk 37`、`androidx.core:core:1.9.0`
> 这类字面量，收进一份 `gradle/libs.versions.toml`。本次**不升级任何依赖版本**，
> 只改「版本写在哪」，产物大小与行为都不变。

## 1. 为什么

改之前的状态：同一个坐标在多个模块里各写一遍，`compileSdk / targetSdk / minSdk`
在 11 个模块里各抄一遍。实际的害处不是难看，是**漏改不报错**：

- 升级 `androidx.core` 时只改了 `brailleback`，`compatutils` 还留着旧版本，
  Gradle 会按最高版本收敛，这次没事；但一旦哪天是降级或加 `strictly`，
  就会出现「某个模块悄悄用旧版、行为不一致」；
- `targetSdk` 漏改的模块不会报错，只会继承默认值，等到运行时行为变更才暴露；
- 代码评审看散文式的 build 脚本，很难看出少改了一行。

版本目录把「版本」变成可搜索、可断言的一个文件，顺带把这件事写成了测试
（见第 4 节）。

## 2. 结构

`gradle/libs.versions.toml` 三个区：

| 区 | 放什么 | 例子 |
|:--|:--|:--|
| `[versions]` | 唯一版本号 + SDK 三级 | `agp = "9.2.0"`、`android-compileSdk = "37"` |
| `[libraries]` | 依赖坐标，版本用 `version.ref` 引用 | `androidx-core = { module = "androidx.core:core", version.ref = "core" }` |
| `[plugins]` | 三个构建插件 | `kotlin-compose = { id = "org.jetbrains.kotlin.plugin.compose", version.ref = "kotlinCompose" }` |

两类版本刻意**没有**进目录：

- `compileOptions` 的 `JavaVersion.VERSION_17`：这是语言级别，跟 artifact 版本不是一类；
- `ndkVersion '28.2.13676358'`（`addon/brailletranslate`）：只此一处使用，且必须与 CI 安装的 NDK
  对应，放目录反而增加一处要同步的地方。

注释里保留了三条「为什么钉这个版本」的原因（Compose 不引 BOM、coroutines 1.9.0、
core 声明 1.9.0 实际解析 1.13.1），避免以后有人当成随手写的数字改掉。

## 3. 改法

根脚本：

```groovy
plugins {
    alias(libs.plugins.android.application) apply false
    alias(libs.plugins.android.library) apply false
    alias(libs.plugins.kotlin.compose) apply false
}
```

模块脚本（11 个都改）：

```groovy
android {
    compileSdk libs.versions.android.compileSdk.get().toInteger()
    defaultConfig {
        minSdk libs.versions.android.minSdk.get().toInteger()
        targetSdk libs.versions.android.targetSdk.get().toInteger()
    }
}
dependencies {
    implementation libs.androidx.core
    implementation libs.compose.ui
    // ...
}
```

Groovy DSL 里 catalog 访问器要 `.get()` 拿 `String` 再 `toInteger()`，
因为 `compileSdk` 只接受 `int`。这是 Groovy 与 Kotlin DSL 的差别，不是目录的限制。

## 4. 契约测试

新增 `DependencyCatalogContractTest` 4 例：

| 用例 | 断言 |
|:--|:--|
| `catalogExists` | `gradle/libs.versions.toml` 存在且有 `[versions]` |
| `noModuleHardcodesACoordinate` | 11 个模块脚本里没有 `'group:artifact:version'` 形状的字面量 |
| `everyModuleTakesSdkLevelsFromTheCatalog` | 每个模块都用 `libs.versions.android.*`，且不再出现裸 `compileSdk 37` |
| `catalogPinsTheComposeAndCoroutineVersionsWeVerified` | 已验证的 6 个版本钉（compose 1.7.6 / material3 1.3.1 / activityCompose 1.9.3 / coroutines 1.9.0 / compileSdk 37 / minSdk 23）都在目录里 |

同时改了 `ComposeMigrationContractTest.composeCompilerPluginMatchesBuiltInKotlin`：
它原本断言根脚本里写死 `version '2.2.10'`，版本搬走后改为断言
「根脚本用 `alias(libs.plugins.kotlin.compose)`」+「目录里 `kotlinCompose = "2.2.10"`、
`agp = "9.2.0"`」，并把模块断言改成 `libs.*` 别名。契约的意图没变，只是换了证据位置。

## 5. 验证

- 配置期：`gradle projects --offline` 全部 11 个模块配置通过（catalog 访问器与 SDK
  的 `toInteger()` 写法都在这一步验证过）；
- 单元测试：主模块 **53 套件 / 538 用例**、service **25 套件 / 172 用例**全绿；
- `lintDebug`：`brailleback` 与 `service` 两个门禁均通过（`abortOnError=true`）；
- `detektCheck` 通过；
- 产物：debug APK **28.98 MB**，与改前逐字节量级一致（版本没动，只是引用方式变了）；
- 仪器测试（默认路径，模拟器 `brailleback_api35` / API 35）：headless 开机 27 秒，
  **11 例全过**，用时 39 秒；跑完已 `emu kill`。

## 6. 边界

- **没有升级任何依赖**。要升 Compose 1.7.6 → 更高版本，先确认本机离线缓存里有对应构件，
  否则 `--offline` 构建直接断（见 `docs/20-依赖与镜像.md`）；这一步单独做、单独验；
- 仍是 Groovy DSL，没有迁 Kotlin DSL（`.gradle.kts`）。迁移会和现有的
  `VerifyNativeLibsUpdated` 任务类、`buildConfigField` 字符串拼装一起重写，收益低于风险；
- `tools/dependency-probe/build.gradle` 不在打包链里，保持原样；
- ktlint 仍未接门禁（全仓 9256 条风格问题，见 `docs/20`），版本目录不管这件事。
