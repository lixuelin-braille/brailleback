# 中文盲文引擎详解（项目核心价值）

> 代码位置：`service/src/com/googlecode/eyesfree/braille/service/translate/`
> 组件：`JiebaDict.kt`(272) + `BrailleSegmenter.kt`(509) + `TranslatorService.java`(489)
> 数据：`assets/jiebadt.txt`(34.9万词) + `assets/sunshine_supplement.txt`(12,405词) + `assets/zh_segment_overrides.txt`(8条) + `assets/sunshine_split.txt`(6,782条) + `zhcn-cbs-full.ctb`

---

## 一、为什么需要"分词"这道工序

中文盲文（现行盲文/通用盲文）的关键排版规则是**分词连写**：

> 词与词之间**空一方**，词内字**连写**。

所以"我爱北京天安门"不能逐字翻译，必须先正确切词：
```
正确：我 / 爱 / 北京 / 天安门     → 盲文：我  爱  北京  天安门
错误：我 / 爱 / 北 / 京 / 天 / 安 / 门  → 盲文：我 爱 北 京 天 安 门（不可读）
```

**liblouis 只负责"字符→点位"的转换，不负责中文分词。**
因此本项目在 liblouis 之前，自研了一层**分词规则引擎** —— 这就是核心价值所在。

## 二、整体流水线

```
原始中文文本
   │
   ▼ ① BrailleSegmenter.segment()          ← 自研规则引擎
   │     （书名号保护 → 数字保护 → 字母保护 → jieba 分词 → 规则调整 → 化学式保护）
   │
   ├─► 带词间空格的文本   "我 爱 北京 天安门"
   └─► 位置映射 origToSeg[] / segToOrig[]
   │
   ▼ ② LibLouisWrapper.translate()         ← JNI → liblouis 2.6.0
   │     用 zhcn-cbs-full.ctb 把每个字转成点位，空格 → 空 cell
   │
   ├─► byte[] cells（盲文点位）
   └─► ttb[] / btt[]（在"分词文本"坐标系下的位置映射）
   │
   ▼ ③ TranslatorService.translateWithSegment()  ← 坐标还原
   │     用 origToSeg / segToOrig 把位置映射换算回"原始文本"坐标系
   │
   ▼ TranslationResult（cells + 原文坐标系下的位置映射 + 光标）
```

> **坐标还原是容易忽略但致命的一步**：
> 分词插入了空格，字符下标全变了。若不还原，
> 光标位置、焦点高亮、选中范围**全部会错位**。

## 三、第一层：`JiebaDict` —— 自实现分词器

**为什么自研**：不引第三方依赖（TalkBack 主体 98.3% Java，零 interop 风险；
另一个项目 `/d/软件/林夕读屏` 迁移时也是"纯 Java，零依赖"的考量）。

**算法**（等同 jieba，`HMM=false`）
```
1. 加载词典：word freq [pos]，同时把每个词的所有前缀写入 freqMap（值 0）
2. buildDag(s)：对每个起点 k，用前缀表找出所有能成词的终点
3. DP 从后往前：score(i) = max over x in dag[i] of
                    ( log(freq(i..x)) - logTotal + score(x+1) )
4. 回溯 end[] 得到最优切分
```

**对外 API**
| 方法 | 用途 |
|:---|:---|
| `init(InputStream)` | 载入词典（后台线程调用） |
| `addWord(word, freq)` | 强制成词（连写词/专名，freq 传 100000） |
| `delWord(word)` | 删词（让它被切开） |
| `isWord(word)` | 判断双字组合是否成词（2+2 分写规则用） |
| `segmentWithPos(s)` | 返回 `[word, start, end]` ← **BrailleSegmenter 用这个** |
| `segment(s)` | 只要词列表 |

**性能特征**：5 MB 词典全量载入内存 + O(n·len) 建前缀表，
必须在**后台线程**初始化（`TranslatorService.startSegmenterInit()` 已这么做）。

## 四、第二层：`BrailleSegmenter` —— 规则引擎（核心创新）

### 4.1 词典预处理（`init` 块）

| 操作 | 词表 | 目的 |
|:---|:---|:---|
| `delWord` | `SPLIT4` | 把"应分写"的整体词从词典删掉 → jieba 会自然切开 |
| `addWord(100000)` | `CONNECT` | 强制连写 |
| `addWord(100000)` | `NAMESET` | 专名保护（音译名/机构名不被拆） |
| `addWord(100000)` | `SPLIT4_INNER` | 分写后需要的内部词 |

### 4.2 分段处理顺序

```
segment(text)
  ① BOOK_RE《…》        书名号内整体，不参与分词（《时间简史》不被切成"时间 简史"）
  ② addPlainTokens
     ├─ PROTECTED_RE    URL / 邮箱整体（协议、斜杠、查询参数不拆开）
     ├─ NUM_PAT         数字整体（1,234.56 / 3.8% / 全角数字不被切开）
     ├─ LETTER_RE       连续 ASCII/全角字母整体（BrailleBack / HID 不逐字母切）
     └─ addJiebaTokens
          ├─ 阳光强制分写词库（sunshine_split.txt）
          ├─ 后附成分合并（SUFFIX，仅 们/子/儿/头）
          └─ 四字词 2+2 语节分写
  ③ mergeAsciiAlnum     字母数字标识符保护（MP3 / A4 / 3D / COVID-19）
  ④ mergeChemFormulas   化学式保护（H2O / CO2 / H2SO4）
  ⑤ 拼装 + 双向位置映射
```

### 4.3 各条规则详解

**规则 A：书名号内连写**
```
正则： (《[^》]*》)
处理： 《 + 书名(整体 token) + 》
效果： 《时间简史》→ 内部不分词（书名是专名，应整体连写）
```

**规则 B：数字整体**
```
正则： [-－]?[0-9０-９]{1,3}([,，][0-9０-９]{3})+(?:[.．][0-9０-９]+)?[%％]?
      | [-－]?[0-9０-９]+(?:[.．][0-9０-９]+)?[%％]?
效果： 1,234.56 整体 / 3.8% 整体；１２３、１，２３４．５％、－5 也不会被拆开
```

**规则 C：字母数字标识符整体**
```
正则： LETTER_RE = [A-Za-zＡ-Ｚａ-ｚ]+
      ALNUM_RE  = [A-Za-z0-9０-９Ａ-Ｚａ-ｚ₀-₉－-]+
处理： 先按连续字母/数字切 token，再由 mergeAsciiAlnum 合并原文中真正相邻的 token
效果： BrailleBack、MP3、A4、3D、B2B、C3PO、COVID-19 整体保护；
      只在原文相邻时合并，不会跨空格或标点粘连
```

**规则 C2：URL / 邮箱整体**
```
正则： (?:https?|ftp)://… | www.… | local@example.com
效果： 协议、冒号、斜杠和查询参数不会被当成分隔符；URL/邮箱整体作为一个 token
```

**规则 D：阳光强制分写词库**（`sunshine_split.txt`，6,782 条）
```
格式： 词\t分1 分2 分3
例：   一丘之貉\t一丘 之 貉
效果： 相邻 jieba token 拼接后匹配该词，命中则按词库替换成分写结果
        （规则词被切成多个 token 时同样生效；CONNECT 连写白名单优先）
校验： 分片拼接必须与词条完全一致，否则忽略该行，避免位置映射错位
```

**规则 D2：阳光补充词库**（`sunshine_supplement.txt`，12,405 条 / 139 KB）
```
来源： 阳光读屏《分词词库_clean.tsv》第 2 列（segmented），只保留纯中文、
       长度 ≥2 且 jiebadt.txt 中不存在的词
格式： 词\t词频
词频： 二字词 = 10，三字及以上 = 100（低频补词，不覆盖主词典）
加载： JiebaDict.loadSupplement()，跳过已有词、注释和坏行；失败只告警不阻塞分词器就绪
效果： 下一步 / 不合格 / 点字 / 原计划 / 不值得 / 不等于 / 张伟 等成词
```
补充词库解决的是“主词典完全没有这个词”的 OOV，不改变主词典已有词的词频。
因此像 `正确`（主词典 6167）仍可能输给 `正`(37763) + `确切`(785) 的组合，
这类问题由下一层的“高优先级覆盖表”处理。

**规则 D3：高优先级覆盖表**（`zh_segment_overrides.txt`，8 条）
```
用途： 1) 补充主词典和阳光补充词库都没有的专名/领域词；
       2) 覆盖主词典中明显偏低的词频
加载： jiebadt.txt -> sunshine_supplement.txt -> zh_segment_overrides.txt
语义： 同名主词典词会被覆盖；不改变 logTotal，不影响其他词的全局概率
示例： 正确 20000（修复 正+确切 竞争）
       王芳 / 大语言模型 / 协议栈 / 易守难攻 / 中医药学家 / 保险单据 / 中和力量
```
覆盖表保持很小，只收“有明确语料证据”的词；新增条目必须跑语料回归。
当前 1,740 行文档语料中仅 7 处变化，均为改善，未观察到误合并。

**规则 E：后附成分合并**
```
SUFFIX = 们子儿头
条件： 当前 token 是单字 且 在 SUFFIX 中 且 前一个 token 不是标点
       且 前一个 token 不是单字虚词（的了着过是在和与及或把被让给对从向于…）
效果： 孩子 + 们 → 孩子们；石 + 头 → 石头
不合并：的 + 头 → 的 头（避免"的头"这类跨词连写）
说明： 性/者/员/家/手/化/度/法/学/论/品 已由词典覆盖，
       动态合并会把「待 + 学」「会 + 学」「近 + 家」错误粘连，故不再参与。
```

**规则 F：四字词 2+2 语节分写**
```
条件： 4 字 且 不在 CONNECT/SPLIT4/NAMESET/SPLIT4_INNER 黑名单
      且 前 2 字成词 且 后 2 字成词（dict.isWord 双向校验）
效果： 按语节 2+2 分写（符合盲文语节习惯）
```
拆分完全由「前后两段是否各自成词」决定，不再使用“第 2/3 字是虚词就拆”的启发式。
该启发式曾把 `迫不及待` 误拆成 `迫不 / 及 / 待`，已删除；成语分写统一以
`sunshine_split.txt` 的显式规则为准（如 `一丘之貉 -> 一丘 之 貉`）。

**规则 G：化学式保护**
```
mergeChemFormulas：合并相邻 [字母][数字][字母]… token
isChemFormula 校验：首字符大写 + 每段是合法元素符号（118 元素表）+ 必须含数字
效果： H2O / CO2 / H2SO4 整体（不会切成 "H" "2" "O"）
```

## 五、已知质量水平与改进方向

> 数据来源：早期在 **5,030 万字全量书籍语料**上的验证（Python 版规则引擎，逻辑与本 Kotlin 版一致）

| 指标 | 结果 |
|:---|:---|
| 词间控方提升（Python 版历史） | +4.05 倍 |
| 数字错误率（Python 版历史） | 0.04% |
| 抽样 20 段「完全合理」（历史） | 约 9/20（45%） |
| 抽样 20 段「基本可用」（历史） | **20/20（100%）** |

**2026-10 真实电子书复测**（Kotlin 引擎，每本截取约 5 万汉字）：

| 语料 | 词数 | 单字词 | 词级 OOV | 字符 OOV |
|:---|:---|:---|:---|:---|
| 变形记（文学） | 32,402 | 49.6% | 0.24% | 0.42% |
| 100个似是而非的问题（科普） | 29,905 | 39.0% | 0.10% | 0.19% |

读法说明：
- 单字词比例高主要是 `的/了/是/在/我/他` 等独立虚词、代词和单音节动词，属于正常分词，
  不能直接当作切分错误率。
- 分写规则会把部分双字词拆成语节（如 `无动 于衷`、`汗流 浃背`），拆出的片段不在词典中，
  因而词级 OOV 会高于纯 jieba 模式；这部分是规范分写，不是错误。
- 当前主要 OOV 来源是未登录专名（徐培里昂、波西米亚）和领域名词，而不是虚词误切。
- 本轮同时修复了后附成分过度合并（`的 头` 曾被并成 `的头`）和虚词启发式误拆
  （`迫不及待` 曾被拆成 `迫不 及 待`），词级 OOV 由 0.41%/0.17% 降至 0.24%/0.10%。

**剩余瑕疵（按收益排序）**
1. **词库覆盖不足（已部分修复）** —— 普通多字词被切开：
   - `易守难攻`：修复前 `易守难 攻`，现为整词 `易守难攻`
   - `中医药学家`：修复前 `中 医药 学家`，现为整词 `中医药学家`
   - `保险单据`：修复前 `保险单 据`，现按 2+2 分为 `保险 单据`
   - `中和力量`：修复前 `中 和 力量`，现按 2+2 分为 `中和 力量`
   - `大语言模型`：修复前 `大 语言 模型`，现为整词 `大语言模型`
   - `协议栈`：修复前 `协议 栈`，现为整词 `协议栈`
   → **已做**：`sunshine_supplement.txt` 补齐阳光与 jieba 的 12,405 个差集词；
     `zh_segment_overrides.txt` 修正上述专名/领域词和 `正确` 的词频竞争
   → **仍需**：更多人名、音译名、机构名和新领域词；这些应继续追加到覆盖表（纯数据改动）
2. **专名覆盖仍是种子级** —— `NAMES_ARR` 约 50 条，覆盖表仅收录少量样例；
   真实语料里的人名/机构名需要从通讯录或公开词表批量扩充
3. **生僻字** —— 靠 `zhcn-cbs-full.ctb`（通用盲文全字符表，7,093 常用 + 13,605 生僻字同音覆盖）

**建议的改进工作流**
```
1. 拿真实语料跑一遍，收集"被错误切开"的词
2. 批量整理成词表
3. 补进 CONNECT_ARR（代码）、sunshine_supplement.txt（低频补词）、
   zh_segment_overrides.txt（专名/领域词或词频纠正）或 jiebadt.txt（主词典）
4. 重跑语料回归，看「基本可用率」与「数字错误率」
```

## 六、调试技巧

`TranslatorService.translateWithSegment()` 里有现成的调试日志：
```java
Log.d("SegDebug", "IN : [" + text + "] L=" + text.length());
Log.d("SegDebug", "OUT: [" + seg.text + "] segL=" + seg.text.length());
```
```bash
adb logcat -s SegDebug          # 看分词前后对比
adb logcat -s BrailleSegmenter  # 看分词器就绪/失败
adb logcat -s JiebaDict         # 看词典加载（words=xxx）
adb logcat -s TranslatorService # 看表解压/翻译降级
```

**降级路径要留意**：若 `mSegmenterReady == false`（分词器还在初始化，或词典加载失败），
中文表会**静默降级**为直接 liblouis（不分词），盲文质量明显下降但不报错。
出现"盲文没分词"的现象时，先查 `JiebaDict` 的 `dict loaded` 日志。
