# 中文盲文引擎详解（项目核心价值）

> 代码位置：`service/src/com/googlecode/eyesfree/braille/service/translate/`
> 组件：`JiebaDict.kt`(207) + `BrailleSegmenter.kt`(418) + `TranslatorService.java`(424)
> 数据：`assets/jiebadt.txt`(34.9万词) + `assets/sunshine_split.txt`(1,439条) + `zhcn-cbs-full.ctb`

---

## 一、为什么需要"分词"这道工序

中文盲文（现行盲文/通用盲文）的关键排版规则是**分词连写**：

> 词与词之间**空一方**，词内字**连写**。

所以"我爱北京天安门"不能逐字翻译，必须先正确切词：
```
正确：我 / 爱 / 北京 / 天安门     → 盲文：我  爱  北京  天安门
错误：我 / 爱 / 北 / 京 / 天 / 安 / 门  → 盲文：我 爱 北 京 天 安 门（不可读）
```

**liblouis 只负责"字符→点位"的转换，不负责中文分词。**
因此本项目在 liblouis 之前，自研了一层**分词规则引擎** —— 这就是核心价值所在。

---

## 二、整体流水线

```
原始中文文本
   │
   ▼ ① BrailleSegmenter.segment()          ← 自研规则引擎
   │     （书名号保护 → 数字保护 → 字母保护 → jieba 分词 → 规则调整 → 化学式保护）
   │
   ├─► 带词间空格的文本   "我 爱 北京 天安门"
   └─► 位置映射 origToSeg[] / segToOrig[]
   │
   ▼ ② LibLouisWrapper.translate()         ← JNI → liblouis 2.6.0
   │     用 zhcn-cbs-full.ctb 把每个字转成点位，空格 → 空 cell
   │
   ├─► byte[] cells（盲文点位）
   └─► ttb[] / btt[]（在"分词文本"坐标系下的位置映射）
   │
   ▼ ③ TranslatorService.translateWithSegment()  ← 坐标还原
   │     用 origToSeg / segToOrig 把位置映射换算回"原始文本"坐标系
   │
   ▼ TranslationResult（cells + 原文坐标系下的位置映射 + 光标）
```

> **坐标还原是容易忽略但致命的一步**：
> 分词插入了空格，字符下标全变了。若不还原，
> 光标位置、焦点高亮、选中范围**全部会错位**。

## 三、第一层：`JiebaDict` —— 自实现分词器

**为什么自研**：不引第三方依赖（TalkBack 主体 98.3% Java，零 interop 风险；
另一个项目 `/d/软件/林夕读屏` 迁移时也是"纯 Java，零依赖"的考量）。

**算法**（等同 jieba，`HMM=false`）
```
1. 加载词典：word freq [pos]，同时把每个词的所有前缀写入 freqMap（值 0）
2. buildDag(s)：对每个起点 k，用前缀表找出所有能成词的终点
3. DP 从后往前：score(i) = max over x in dag[i] of
                    ( log(freq(i..x)) - logTotal + score(x+1) )
4. 回溯 end[] 得到最优切分
```

**对外 API**
| 方法 | 用途 |
|:---|:---|
| `init(InputStream)` | 载入词典（后台线程调用） |
| `addWord(word, freq)` | 强制成词（连写词/专名，freq 传 100000） |
| `delWord(word)` | 删词（让它被切开） |
| `isWord(word)` | 判断双字组合是否成词（2+2 分写规则用） |
| `segmentWithPos(s)` | 返回 `[word, start, end]` ← **BrailleSegmenter 用这个** |
| `segment(s)` | 只要词列表 |

**性能特征**：5 MB 词典全量载入内存 + O(n·len) 建前缀表，
必须在**后台线程**初始化（`TranslatorService.startSegmenterInit()` 已这么做）。

## 四、第二层：`BrailleSegmenter` —— 规则引擎（核心创新）

### 4.1 词典预处理（`init` 块）

| 操作 | 词表 | 目的 |
|:---|:---|:---|
| `delWord` | `SPLIT4` | 把"应分写"的整体词从词典删掉 → jieba 会自然切开 |
| `addWord(100000)` | `CONNECT` | 强制连写 |
| `addWord(100000)` | `NAMESET` | 专名保护（音译名/机构名不被拆） |
| `addWord(100000)` | `SPLIT4_INNER` | 分写后需要的内部词 |

### 4.2 分段处理顺序

```
segment(text)
  ① BOOK_RE《…》        书名号内整体，不参与分词（《时间简史》不被切成"时间 简史"）
  ② addPlainTokens
     ├─ NUM_PAT         数字整体（1,234.56 / 3.8% 不被切开）
     ├─ LETTER_RE       连续 ASCII 整体（BrailleBack / HID 不逐字母切）
     └─ addJiebaTokens
          ├─ 阳光强制分写词库（sunshine_split.txt）
          ├─ 后附成分合并（SUFFIX）
          ├─ 虚词分写（FUNC，4 字词）
          └─ 四字词 2+2 语节分写
  ③ mergeChemFormulas   化学式保护（H2O / CO2 / H2SO4）
  ④ 拼装 + 双向位置映射
```

### 4.3 各条规则详解

**规则 A：书名号内连写**
```
正则： (《[^》]*》)
处理： 《 + 书名(整体 token) + 》
效果： 《时间简史》→ 内部不分词（书名是专名，应整体连写）
```

**规则 B：数字整体**
```
正则： (-?\d{1,3}(,\d{3})+(\.\d+)?%? | -?\d+(\.\d+)?%?)
效果： 1,234.56 整体 / 3.8% 整体（不会切成 "3" "." "8" "%"）
```

**规则 C：ASCII 字母串整体**
```
正则： [A-Za-z]+
效果： "BrailleBack" 不逐字母切（否则盲文会是 11 个孤立字母）
```

**规则 D：阳光强制分写词库**（`sunshine_split.txt`，1,439 条）
```
格式： 词\t分1 分2 分3
例：   一丘之貉\t一丘 之 貉
效果： jieba 切出该词时，直接按词库替换成分写结果（对标阳光读屏的商业决策）
```

**规则 E：后附成分合并**
```
SUFFIX = 们子儿头性者员家手化度法学论品
条件： 当前 token 是单字 且 在 SUFFIX 中 且 前一个 token 不是标点
效果： 孩子 + 们 → 孩子们（否则会切成"孩子 们"）
```

**规则 F：虚词分写（4 字词）**
```
FUNC = 之而所如即若亦俱尚犹且及焉哉乎耳
若第 2 字是虚词 → 1+1+2   一丘之貉 → 一丘 / 之 / 貉
若第 3 字是虚词 → 2+1+1   一挥而就 → 一挥 / 而 / 就
```

**规则 G：四字词 2+2 语节分写**
```
条件： 4 字 且 不在 CONNECT/SPLIT4/NAMESET/SPLIT4_INNER 黑名单
      且 前 2 字成词 且 后 2 字成词（dict.isWord 双向校验）
效果： 按语节 2+2 分写（符合盲文语节习惯）
```

**规则 H：化学式保护**
```
mergeChemFormulas：合并相邻 [字母][数字][字母]… token
isChemFormula 校验：首字符大写 + 每段是合法元素符号（118 元素表）+ 必须含数字
效果： H2O / CO2 / H2SO4 整体（不会切成 "H" "2" "O"）
```

## 五、已知质量水平与改进方向

> 数据来源：早期在 **5,030 万字全量书籍语料**上的验证（Python 版规则引擎，逻辑与本 Kotlin 版一致）

| 指标 | 结果 |
|:---|:---|
| 词间控方提升 | +4.05 倍 |
| 数字错误率 | 0.04% |
| 抽样 20 段「完全合理」 | 约 9/20（45%） |
| 抽样 20 段「基本可用」 | **20/20（100%）** |

**剩余瑕疵（按收益排序）**
1. **词库覆盖不足**（最主要）—— 普通多字词被切开：
   - 易守难攻 → 易守 难攻
   - 中医药学家 → 中 医药 学家
   - 保险单据 → 保险单 据
   - 中和力量 → 中 和 力量
   - 老人们 → 老 人们
   → **改法**：往 `CONNECT_ARR` 加词，或往 `jiebadt.txt` 补词（纯数据改动，不动代码）
2. **专名词表待扩充** —— `NAMES_ARR` 现约 50 条，真实语料里音译名/机构名远不止这些
3. **生僻字** —— 靠 `zhcn-cbs-full.ctb`（通用盲文全字符表，7,093 常用 + 13,605 生僻字同音覆盖）

**建议的改进工作流**
```
1. 拿真实语料跑一遍，收集"被错误切开"的词
2. 批量整理成词表
3. 补进 CONNECT_ARR（代码）或 jiebadt.txt（数据）
4. 重跑语料回归，看「基本可用率」与「数字错误率」
```

## 六、调试技巧

`TranslatorService.translateWithSegment()` 里有现成的调试日志：
```java
Log.d("SegDebug", "IN : [" + text + "] L=" + text.length());
Log.d("SegDebug", "OUT: [" + seg.text + "] segL=" + seg.text.length());
```
```bash
adb logcat -s SegDebug          # 看分词前后对比
adb logcat -s BrailleSegmenter  # 看分词器就绪/失败
adb logcat -s JiebaDict         # 看词典加载（words=xxx）
adb logcat -s TranslatorService # 看表解压/翻译降级
```

**降级路径要留意**：若 `mSegmenterReady == false`（分词器还在初始化，或词典加载失败），
中文表会**静默降级**为直接 liblouis（不分词），盲文质量明显下降但不报错。
出现"盲文没分词"的现象时，先查 `JiebaDict` 的 `dict loaded` 日志。
