# 彗光（CometLight）盲文刻印机固件分析

分析日期：2026-10-30
目标：本机安装的“彗光盲文软件”及其刻印机固件
性质：自有设备的兼容性/硬件研究，未拆机、未改动设备

## 1. 结论摘要

- 本机安装的是 **彗光盲文软件 1.7.11**（厂商目录名 `CometLight`，不是“辉光/惠光”）。
- 固件位于 `C:\Program Files (x86)\CometLight\EmbosserService\CLBrailleEditor\firmware\`。
- 共 **16 个机型固件**，版本统一为 **v0.7.1**（2025-03-10），单文件约 70 KB。
- 固件外层是 `{"type": "bin"}` 16 字节头 + **AES-128-ECB + PKCS#7** 密文。
- 解密后是 **ARM Cortex-M3** 固件：初始栈 `0x2000C000`（48 KB RAM），复位入口 `0x080095C1`，Flash 基址 `0x08000000`。
- 规模与向量表符合 **STM32F103RC/VC 级（256 KB Flash / 48 KB RAM）或引脚兼容的国产替代**；具体丝印需拆机确认。
- 固件是裸机程序（无 RTOS），包含：串口文本协议、步进电机运动控制、TF 卡 FATFS、参数存储、Bootloader 升级。
- 机型差异：Leo（小狮座）系列同一套代码，仅相差 16–28 字节（型号 ID、机械参数、尾部校验）；Aries（白羊座）与 Leo 相差约 3.1 万字节，属于不同的机构/驱动实现。

## 3. 固件封装与加密（已确认）

文件结构：

```
偏移 0x00  16 字节   {"type": "bin"}\n
偏移 0x10  余下部分  AES-128-ECB(PKCS#7) 密文
```

关键点：

- 所有机型文件的首个 16 字节密文完全相同，符合 **ECB + 相同密钥 + 相同明文前缀**。
- 密钥是 `print_service.exe` 中 `FUN_0044bb80` 用 4 个小端 32 位常量拼出的 16 字节：

```
02 62 06 46 3F AD D4 2A B1 CF 47 66 40 AA 7A BB
```

- 解密函数路径：`FUN_004c11f0`（识别 `bin` 类型）→ `FUN_004c2160`（CryptoPP Rijndael/ECB）。
- 同一套代码还用于 `clxf` 盲文文件（AES-ECB）和登录数据（AES-CBC + MD5 派生密钥）。

解密后的文件已放在：

```
D:\软件\brailleback盲文\_re\cometlight\fw_dec\
```

## 4. 解密后固件画像（已确认）

以 `t_app_v0.7.1_leo1_m4_dec.bin` 为例：

- 大小：71,800 字节；另有部分机型 71,808 字节。
- 向量表：
  - 初始 MSP：`0x2000C000` → 48 KB SRAM
  - Reset：`0x080095C1`
  - NMI/HardFault：`0x0800E91D` / `0x0800E91F`
- 尾部标记：`ASCII`、`ASCII`、`CL_EB_1_APP`
  - `CL_EB_1_APP` 可理解为 CometLight Embosser Board v1 的 App 镜像标识。

外设基址出现情况（按字面量统计）：

| 外设 | 基址 | 说明 |
|---|---|---|
| GPIOA/B/C/D/E | `0x40010800` 等 | 打印头、电机、传感器、电源控制 |
| USART1 | `0x40013800` | 与 PC 的主串口协议 |
| DMA1 / DMA2 | `0x40020000` / `0x40020400` | 串口/存储搬运 |
| TIM3 / TIM4 | `0x40000400` / `0x40000800` | 步进脉冲/计时 |
| SPI2 | `0x40003800` | TF 卡（FATFS） |
| IWDG | `0x40003000` | 独立看门狗 |
| RCC / FLASH / CRC | `0x40021000` / `0x40022000` / `0x40023000` | 时钟、参数存储、校验 |

未发现 USB 设备栈迹象，结合安装包自带 CH341SER 驱动，PC 侧应为 **USB 转串口（CH340/CH341）+ USART1** 的连接方式。

## 5. 固件功能与协议

固件内可直接读到的命令/模块名：

```
reboot  cur_pos  homing  return  feed
move_to  move_rela  move_next_page  move_prev_page
head_prt  head_on_dura  set_head_assignment
start_print  abort_print  deal_prt_cmd  prtctrl_loop
protocol_process  recv_file  parser_process
storage_param_read/write/reset
fatfs_loop  update_boot_sd  verify_sd  boot_sv
Bstepper_stop  motion_loop
```

PC 端 `print_service.exe` 中存在同名命令表：

```
op  homing  return  head_prt  move_to  move_rela
x  X  y  p  v  V  total_page  current_page
```

说明这是 **串口文本命令协议**：上位机下发命令与坐标，固件解析后控制打印头/走纸机构。

升级流程（来自服务端字符串与调用关系）：

1. 上位机请求进入升级：`requestUpgradeApp`。
2. 设备重启进入 Bootloader（`wait to restart to bootloader`）。
3. 协商/切换波特率（`Change baudrate to %d`）。
4. 分块发送固件（`send firmware data: %d`），完成后等待设备校验重启。
5. 固件自身还支持从 TF 卡更新 Bootloader（`update_boot_sd` / `verify_sd` / `boot_sv`）。

## 6. 机型差异

以 Leo m4 为基准：

| 文件 | 大小 | 字节差异 |
|---|---:|---:|
| leo1L_m5 | 71,800 | 16 |
| leo1_M_m10 | 71,800 | 18 |
| leo1_M_m11 | 71,800 | 25 |
| leo1_m31 | 71,800 | 25 |
| leo1L_M_m80 | 71,800 | 27 |
| leo1L_M_m81 | 71,800 | 28 |
| aries1_m10000 | 71,800 | 141 |
| aries1L_m10001 | 71,800 | 151 |
| aries1_* / aries1L_* 其余 | 71,808 | 约 31,800 |

Leo 系列的差异集中在：

- `0x009072`、`0x009E90`：型号 ID（m4=4、m5=5、m10=0x10…）。
- `0x0108F6` 起：机械/纸张参数表（单精度浮点，如 213.0×294.0、280.0×302.0，与 `model.conf` 的纸张尺寸一致）。
- `0x011874`–`0x011877`：尾部 32 位校验值。

结论：Leo 的 8 个型号是 **同一固件按参数裁剪**；Aries 是另一套机构代码。

## 7. 对硬件与成本研究的意义

- 彗光采用“移动打印头 + 步进电机 + 走纸机构”的 X-Y 刻印结构，而不是无界书城那种 30 方固定点阵。
- 因而：
  - 电子 BOM 更简单：1 颗 Cortex-M3、串口、电机驱动、TF 卡、传感器即可；
  - 机械件占比更高：导轨、同步带/丝杆、打印头、压纸机构；
  - 打印速度受机械扫描限制，但成本显著低于 180 点固定执行器阵列。
- `set_head_assignment`、`Bstepper_stop` 以及更新日志中的“双头刻印机”，提示存在双打印头机型（“M”后缀很可能与双头/多任务分配有关，但未拆机确认）。
- 固件仅 70 KB、无 RTOS、无 USB/BLE 协议栈，说明这套产品的软件门槛不高，核心难点在机械精度、打印头寿命与一致性。

## 8. 证据边界

已确认：

- Cortex-M3 向量表、48 KB RAM、Flash 基址、外设使用、命令表、机型差异。

- “M”后缀与双打印头的对应关系；
- CH340/CH341 是否为唯一 PC 连接方式（也可能是原生串口或其他桥片）。
