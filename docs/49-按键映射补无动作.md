# 49 · 按键映射补「无动作」：让难按的键彻底空转

## 起因

论坛「按键自定义」第 21 楼，用户「欢喜就好」提问：能不能映射点显器的热键，V3 那条滚平键按得太难受了。

查代码后的结论是：**映射功能其实已经有了**（`keymap/BrailleKeyMapPolicy.kt`，设置路径「按键与手势 → 自定义按键」），`CMD_NAV_PAN_LEFT` / `CMD_NAV_PAN_RIGHT` 就在「可被改掉的按键」清单第 1、2 位。所以「能不能改」答案是能。

但用户的真实诉求是**不想按那个键**，而当时的清单里只有 29 个真实动作——没有任何一项表示「什么也不做」。于是：

- 把滚平键改成别的动作 → 平移能力就没了；
- 想让它空转 → 做不到。

这是当时唯一的缺口，本文记录补法。

## 改动

### 1. 纯逻辑层：新增虚拟动作 `NO_ACTION`

`BrailleKeyMapPolicy` 里加常量：

```kotlin
const val NO_ACTION = "NONE"
val ASSIGNABLE_ACTIONS = REMAPPABLE_COMMANDS + GLOBAL_ACTIONS + NO_ACTION
```

它与既有的 `DEFAULT_ACTION` 语义完全不同，不能混：

| 值 | 含义 | 存在形式 |
| --- | --- | --- |
| `DEFAULT` | 「表里没有这一条」，行为回到出厂动作 | 只存在于界面，不写入偏好 |
| `NONE` | 「表里这一条指向空动作」，出厂动作被显式覆盖为「不执行」 | 写入偏好：`CMD_NAV_PAN_LEFT=NONE` |

`NONE` 允许当**目标**，不允许当**源**（`isRemappable("NONE") == false`）——它不是点显器能发出来的键。

### 2. 持久化层：`NONE` 不能走 `stringToCommand`

`CustomKeyMapStore.runtimeMap` 原来对所有目标调 `BrailleInputEvent.stringToCommand`，解析失败返回 `CMD_NONE`（`-1`），然后被当成坏数据 `continue` 跳过。如果照原样处理，用户设的「无动作」会被**静默丢弃**，表现是「设置里改了、按了还是原行为」——这类问题盲用户极难自查。

所以单独分支：目标名等于 `NONE` 时，直接把 `source` 映射到 `BrailleInputEvent.CMD_NONE`。

### 3. 分发层：`applyCustomKeyMap` 返回可空，吞掉事件

`DisplayManager.onInputEvent` 是所有输入事件的唯一汇聚点（brltty/JNI 主路径 + BLE 旁路的 `WujieGattConnection`），映射在这里生效，IME 模式走的 `IMENavigationMode` 拿到的也是映射后的事件，所以「无动作」在 brailleback 与盲文键盘两种场景都成立。

```kotlin
val effectiveEvent = applyCustomKeyMap(event) ?: return   // 返回 null = 吞掉
```

`applyCustomKeyMap` 里：

```kotlin
if (target == BrailleInputEvent.CMD_NONE) {
    LogUtils.log(this, Log.VERBOSE, "CustomKeyMap: %d -> no action", event.command)
    return null
}
```

**静默是刻意的**：抱怨「这个键太难按」的用户要的正是「按了当没按」，不给振动、不给提示音。

### 4. 资源与文案

- `values/key_map.xml`：动作清单加 `NONE`，标签 `No action (key does nothing)`；头部注释从「29 条」更新为「24 + 5 + 1 条虚拟 = 30 条」。
- `values-zh-rCN/key_map.xml`：标签「无动作（按了没反应）」，排在最后一条。
- `custom_key_map_instructions`（中英）：补一句「嫌某个键难按时，可以把它设为『无动作』」。

设置界面本身不用改：`CustomKeyMapActivity` 的动作列表由数组直接生成，`DEFAULT` 由代码插到首位，`NONE` 作为数组最后一条自然出现；摘要「当前：X」也走 `labelOf()` 查同一份数组，中文名自动显示。

### 5. 一处刻意的排除

`duplicateTargets` 不把 `NONE` 算作「冲突」。多个键都空转是用户有意的选择，提示「有 N 组按键被设为同一动作」只会让人困惑。

## 契约测试：让「NONE 必须缺席」也成为不变量

项目原有的 `KeyMapResourceContractTest.everyWhitelistedNameIsRegisteredInBrailleInputEvent` 断言「白名单里每个名字都在 `CMD_NAMES` 登记过」。`NONE` 是虚拟动作，必须在 `CMD_NAMES` 里**缺席**（否则 `stringToCommand("NONE")` 会解析成 `-1`，和「坏数据」无法区分）。所以该测试改成：

- `NONE`：断言 `CMD_NAMES` 里**没有**它；
- 其余 29 条：仍然断言必须在。

另加 `noActionIsSwallowedAtTheDispatchPoint`，静态锁三件事：`applyCustomKeyMap` 里有 `CMD_NONE` + `return null`；`onInputEvent` 有 `?: return`；`runtimeMap` 里有 `NO_ACTION` + `CMD_NONE`。

`KeyMapResourceContractTest` 另外四条（源清单一致、动作清单一致、源是动作的前缀、中英标签等长且已翻译）在数组加一条后自动覆盖到 30 条。

纯逻辑层新增 6 个用例：

| 用例 | 锁住的行为 |
| --- | --- |
| `noActionIsAssignableButNeverASource` | 可当目标、不可当源 |
| `noActionRoundTripsThroughPersistence` | `CMD_NAV_PAN_LEFT=NONE` 能存能读 |
| `noActionCanBeRevertedByDefault` | 「保持默认」能撤销 NONE（否则用户被自己锁死） |
| `noActionDoesNotCountAsDuplicateTarget` | 多个键空转不报冲突 |
| `noActionIsAnAcceptableMappingButNotACommand` | 用 NONE 当源被拒绝 |

## 用户侧怎么用（可以照这个回帖）

1. 连上点显器，进 **按键与手势 → 自定义按键**；
2. 每一行会显示「实际按键：xxx」，先确认 V3 的滚平键对应的是 **向左平移 / 向右平移** 哪一条；
3. 点进去选 **无动作（按了没反应）**；
4. 如果还想保留平移，就把另一个顺手的键（比如上一行 / 下一行 / 向前滚动）设成 **向左平移 / 向右平移**——一个源只能指一个目标，所以那个键原本的功能会让位。

## 已知边界（没做）

- **不能用盲文点位组合（dot chord）当触发键**：当前映射的源只能是点显器的 24 个标准命令，盲文点位键 `CMD_BRAILLE_KEY` 明确禁止当源（改掉会毁掉盲文输入）。
- **不能把路由键当源**：带位置参数，重映射后 `sendMappedEvent` 的坐标换算会错乱。
- **不递归**：A→B、B→C 时 A 只变成 B，避免循环与连锁。
