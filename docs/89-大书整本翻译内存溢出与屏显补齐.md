# 89 大书整本翻译：内存溢出与屏显缺字

## 现象

用户读一本 3MB 长篇小说（GB18030，1,545,748 字符、12,169 段）时听到两件事：

1. 进书后**翻译了好几遍**（先按原文铺一遍，翻译好了再铺一遍；表清单与翻译器各自通知一次，等于铺了两次）；
2. 翻译跑到 30–40 秒左右，屏幕弹「翻译失败」，整本退回原文——重试三次也照样失败。

真机日志先给的是「`translate` 返回 null」，容易误判成 liblouis 表或分词器的问题。这次把崩溃栈抓到了，方向完全不同。

## 定位

复现后进程直接消失（`Process com.linxi.brailleback has died: fg +50 FGS`），logcat 里的真凶是：

```
java.lang.OutOfMemoryError: Failed to allocate a 19806408 byte allocation with 16021000 free bytes
  at java.util.ArrayList.grow / addAll
  at com.linxi.brailleback.BrailleReaderActivity.translateParagraphs(BrailleReaderActivity.kt:977)
```

`translateParagraphs` 原先是**逐格攒 `List<CellSource>`**：每个盲文格一个 `CellSource`，里面再套一个 `SourceSpan` 和一个单字 `String`。这本书翻出 378 万格，等于四百多万个对象，实测翻译到一半堆已 229MB / 上限 256MB，`ArrayList.addAll` 要扩到 19MB 连续空间，直接 OOM，进程被杀。

这一条同时解释了两个「看起来无关」的症状：

- 崩在 UI 线程之外，`Thread.run` 的未捕获异常把整个进程带走，用户看到的是「闪退 / 重进又翻译一次」；
- 之前的重试无效，不是服务抖动，是内存已经见底，再调一遍 `translate` 也拿不到结果。

另一个真问题在屏显（明眼人看的正文 + 首行播报）：`SourceSpanMapper` 给每格建对象时，同一源字的多个格（声母/韵母/调号）会重复出字；把它们改成「连续相同才出一次」之后，**词式分割压掉的相邻字又被整字吞掉**——原位格映射序列是 `0,0,1,1,2,2…` 这种，第二字的位置与第一字相同，于是屏显成「身地」「举手之劳」这种缺字的句子。

## 改动

1. **`CellSourceTable`（新，`SourceSpan.kt`）**：只存每格对应的源字符下标（`IntArray`，-1 为无映射），`get(cell)` 时才现拼 `CellSource`。对外仍是 `List<CellSource>`，`ReaderSourceModel` / `BrailleExporter` / 点位 JSON 一行不用改。378 万格从约 190MB 降到 15MB。
2. **`IntPositionBuffer`（新）**：逐格记下标用的增长型 int 缓冲，避免 `ArrayList<Integer>` 装箱与倍增拷贝（那次 19MB 分配正是倍增拷贝）。
3. **`translateParagraphs`** 改为：段落起点在全书坐标系里累计，每格写入 `paragraphStart + 局部位置`（`getOrNull` 兜底 -1），失败段落仍原地重试三次。
4. **`startTranslation` 增补 `catch (OutOfMemoryError)`**：内存真的见底时退化成原文流 + 「翻译失败」提示，不再让翻译线程把进程带走。
5. **`ReaderSourceModel.reconstructFromTable`（新）**：按源字符下标单调推进还原屏显文本——位置前进超过 1 就把中间被跳过的原字按原文补齐（上限 200 字，超过视为跳转不硬补），位置不前进则同一字的多格只出一次；换段仍从阅读流的 `\n` 落换行。

## 验证

同一台机（24117RK2CC / Android 17）、同一本 3MB 小说，`am start --es OPEN_URI file:///…/files/book.txt` 复现：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 整本翻译 | 34–40 秒时 `translate` 返回 null / 直接 OOM 被杀 | `translate ok: paragraphs=12169 cells=3781183 invalidCells=0`，约 56 秒完成 |
| Dalvik Heap | 崩前 229MB / 248MB | 翻译后 101MB / 132MB（上限 256MB） |
| 屏显正文 | 「身地，有些事举之劳的可帮个忙」 | 「毕竟身份摆在这里，总不能太过失态……还是袖手旁观的好」 |
| 铺流次数 | 每次进书 2 次 `stream set` | 1 次 `stream set`（翻译器就绪守卫，见上一轮改动）|

单测：`CellSourceTableTest`（全局坐标、无效位置、缓冲扩容、与逐格对象口径一致、跳字补齐、无流时按格序号）+ 其余 935 例，全绿。

## 遗留

- 本书 378 万格仍在 101MB 堆内，够用但不算宽裕；更大的书（800 万字级）大概率还会撞上限，届时可考虑「只保留当前章附近的位置表 + 按需重算」。
- `map probe` 是临时诊断日志（每 1000 段打一条段首与位置序列），排查完可降为 debug-only 或删掉。

> 附注：点位 JSON 导出格式已于 2026-11-27 移除，见 [142](./142-移除点位JSON导出格式.md)。
