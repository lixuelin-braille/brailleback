# 44 - 规范连写词表：向「多连少分」对齐

> 前 43 份文档都在改代码结构，这一份改的是**分词结果本身**。
> 起因是《盲人月刊》2026 年第 6 期钟经华《国家通用盲文与现行盲文分词连写规则比较》，
> 以及 21&ZD292 课题的公开论文（《残疾人研究》2026 年第 4 期）。

---

## 1. 问题：项目一直在按「另一套口径」分词

项目的分词是词典 + 启发式路线（jieba DAG、后附成分合并、四字 2+2 语节分写），
外加一份对标阳光读屏的**强制分写词库** `sunshine_split.txt`（6,782 条）。

那份词库忠实地复刻了现行盲文的写法，而现行盲文正是文章批评的对象。实测命中的例子：

| 文本 | 分写库给的结果 | 规范要求 |
|---|---|---|
| 分钟 | `分 钟` | 连写（词典词） |
| 一瞬间 | `一瞬 间` | 连写（三音节整体概念） |
| 一口气 | `一口 气` | 连写（三音节整体概念） |
| 一丘之貉 | `一丘 之 貉` | 连写（四字成语） |
| 求之不得 | `求 之 不得` | 连写（四字成语） |
| 之所以 | `之 所以` | 连写（词典词） |

这几条正好是文章原文点名的错例。也就是说：**不是我们不会分词，是词库在主动拆。**

## 2. 数据：分写库里有多少条和新方向冲突

| 项 | 实测 |
|---|---|
| 分写库总条目 | 6,782 |
| 2 字 / 3 字 / 4 字 / 5–7 字 | 154 / 998 / 5,035 / 595 |
| 拆分后**含单字片段** | **3,018（44.5%）** |

「拆出单字片段」就是文章说的「零散的单音节」——按国家通用盲文的方向，这类
切分基本都不成立（短语里只要有一个成分是单音节就连写）。3,018 条里：

- 四字 1,698 条 —— 成语与文言固定结构（一丘之貉、求之不得、一分为二）；
- 三字 998 条 —— 数+量+名（一口气、一席话）与单音节+双音节动宾（背黑锅、敲竹杠）。

## 3. 做法：加一张连写表，优先级压过阳光库

新增资产 `service/assets/segment_connect.txt`（2,702 条，35 KB）：

| 分区 | 条数 | 来源 |
|---|---|---|
| 三音节整体概念 | 993 | 分写库中含单字片段的三字条目，剔除 5 条主谓/小句（一是要、还将有、现已有、没人管、听人说） |
| 四字成语/文言固定结构 | 1,698 | 分写库中含单字片段的四字条目 |
| 2+2 结构的成语 | 7 | 手工收录文章点名的错例（无动于衷、同归于尽、随之而来…） |
| 词典词 | 4 | 的话、也罢、也好、分钟（之所以已在三字区） |

引擎侧改动（`BrailleSegmenter.kt`）：

```
loadConnectExtra(InputStream) -> Int      // 读词表，加入 connectDict，并从 splitDict 摘除同名词
matchConnectRule(words, start) -> Int     // 相邻 token 拼接命中就连写，取最长匹配
```

优先级链变成：

```
用户分词覆盖表（UserSegDict）
  > 规范连写词表（connectDict）
    > 内置连写白名单（CONNECT）
      > 阳光强制分写词库（splitDict）
        > 四字 2+2 语节分写
```

关键点：**加载时把冲突词从 `splitDict` 里删掉**。同一个词不可能既连写又分写，
留着两条规则迟早互相打架；删掉之后，加载顺序也不再影响结果（有测试钉住）。

## 4. 为什么不做「全量切换」

文章说「短语里只要有一个组成为单音节即连写」，而 2026 年那篇论文说
「主谓结构分写为纲，定中/动宾按需处理」——**两套思路不同**，规范也还没发布。
所以这次只做两套口径都同意、且是现行 GF 0019 明文要求的部分：

1. 词典词连写（GF 0019 12.2.1「词」的各个音节连写，`的话` 分写本就是错的）；
2. 三音节整体概念连写（GF 0019 12.2.2 明文）；
3. 成语整体连写（两篇文章 + 论文一致）。

没做的：把 5,035 条四字条目整批判连写。因为 GF 0019 12.2.3 仍规定
「四音节及四音节以上按词语或语节分写」，普通四字词（一元方程、一一谢绝）
应当保持 2+2，只有成语例外。

## 5. 验证

| 项 | 结果 |
|---|---|
| 服务层单测 | **183**（原 172 + 新增 11），全绿 |
| 主应用单测 | 560，全绿 |
| lint ×2 / detekt | 通过（`ComplexCondition` 抽成 `keepsWholeWord()`；加载器不再吞异常，改由调用方记 WARN） |
| 仪器测试（AVD `brailleback_api35`） | **27 例全绿** |
| APK 打包 | `assets/segment_connect.txt 35 KB` 已进包（62.53 MB） |

新增测试：

- `ConnectWordListTest`（4 例，纯逻辑）：连写表压过分写库、**后加载分写库也不能翻盘**、
  表外词照旧分写（防越界）、注释/非汉字/单字被忽略；
- `ConnectWordListAssetTest`（7 例，真词典 + 真词库）：成语连写、三音节连写、词典词连写、
  普通四字词仍 2+2、整句里连写词边界不被吞、词表格式不变量（≥2600 条 / 无重复 / 纯汉字）、
  `TranslatorService` 启动时必须打开该资产。

## 6. 遗留

1. **2+2 成语还差一张成语表**。四字条目里 3,337 条是 2+2 切分（无动于衷、一丝不挂、
   一举成名…），前面 10 条靠手工收录。要做批处理，得先有一份成语表（可从语料库或
   公开成语词典取），再用「四字 + 是成语」筛。
2. **三音节仍是启发式筛选**。「含单字片段」能抓住绝大多数整体概念，
   但「一开头」「一见面」这类是副词性固定说法，不是纯整体概念——目前一并连写，
   符合「多连少分」，但与论文的「主谓分写为纲」仍有细微张力。
3. **等正式规范**。一旦分词连写细则/词库正式发布，这张表应当整体替换为官方词库，
   只保留 `loadConnectExtra` 这条加载通道。
