### 要求 4 · 封面/封底文字必须经 BrailleSegmenter + TranslatorService/LibLouisWrapper 翻成盲文；禁止点阵画字；禁止 Python/jieba

**链路走查：**

1. `TactileStripSession.wrapIntoScreens` 逐行调 `bridge.toBraille(line)` — `TactileStripSession.kt:76`。
2. `TactileStripCaptionBridge` 持有 `TranslatorClient`，`ensureReady()` 取表、`getTranslator(id)` 后 `translator.translate(text, -1, false)` — `TactileStripCaptionBridge.kt:32`、`:49`、`:71-78`。
3. 服务侧 `TranslatorService.translateWithSegment`：先 `mSegmenter.segment(text)` 分词（`TranslatorService.java:272`），再交 `LibLouisWrapper.translate(seg.text, …)`（`:281`，JNI liblouis）。
4. 分词器 `BrailleSegmenter.kt` 为纯 JVM/Kotlin 实现（`java.io` / `regex` / `Normalizer`），词典走资源文本；**无 `ProcessBuilder`、无 `Runtime.exec`、无 python 进程调用**（`git grep` 主源码零命中）。

**退化路径核查：**

- 桥接初始化失败 / 翻译空结果：直接抛 `IllegalStateException`（`TactileStripCaptionBridge.kt:66`、`:69`、`:50`），**没有**退化成点阵画字或内置表硬凑。
- 异常上抛路径：`Session.build` 不吞翻译异常；`Activity.rebuild()` 在 IO 线程 `catch (e: Exception)` 后置 `null` 结果并提示解码失败（`TactileStripActivity.kt:262-274`），不生成空书、不自绘字形。
- 命名遗留：词典文件名 `jiebadt.txt`、注释里的「jieba DAG」是算法谱系沿用，运行期不调用 Python jieba。

**结论：链路代码通过；真实翻译输出未在设备上验证（缺口 G2）。**

### 5.1 分级口径（判定依据，不只给词）

- **✅ 可辨**：主体轮廓连通、闭合性或方向可辨；关键特征（环/框/翼/心尖/柱高/格线）不碎裂到无法成图。

### 5.4 两条硬性结论

#### 5.4.1 公式类：点阵不可承载数学语义，公式应走盲文数学记法

分数、根号、上下标、含数字/字母标注的表达式，其数学语义依赖**位置关系**（上标抬高、根号包络、分数上下层级）与**符号记法**（根号钩、分数线、希腊字母、数学数字）。本次探针 6 类数学样本在全部 5 个配置下：
- 上下标位置、根号钩、分数层级、字母/数字标注**均无法在点阵中保留**；
- 点阵最多保留几何外轮廓（三角、坐标轴、柱体、表格框线），不能读出公式内容。

**结论：公式应走盲文数学（项目内 `BrailleSegmenter` + liblouis 数学表 / 盲文数学记法），点阵只保留几何轮廓。**

**liblouis 表盘点名（`service/jni/liblouiswrapper/liblouis/tables/` 与 `service/src/main/res/xml/tablelist.xml`）：**

- 磁盘上**存在**英语 / 欧洲数学表文件：`en-ueb-math.ctb`、`en-us-mathtext.ctb`、`ar-ar-math.uti`、`ukmaths_single_cell_defs.cti`、`ukmaths_unicode_defs.cti`、`nemethdefs.cti`。
- **但 `tablelist.xml` 未登记任何数学表**（清单内只有各语言文学盲文表），`TranslatorService` 不会加载上述数学表。
- **没有中文数学盲文表**：无 `zhcn-math` / 汉语盲文数学记法表；现有中文表 `zhcn-cbs.ctb`、`zh_CHN.tbl`、`zhcn-g1.ctb`、`zhcn-g2.ctb` 均为文学/现行盲文，不含上下标、根号、分数、希腊字母等数学结构记法。
- 含义：当前中文公式即便进入翻译链路，也只能按普通文字处理，数学结构会丢失；要支持需 ① 在 `tablelist.xml` 登记数学表并补中文数学记法映射，② 公式输入走独立数学盲文通道，不混进点阵图形会话。

#### 5.4.2 几何 / 函数图的可用条件

- **最小线宽**：探针里 2–3 像素粗线在 40×4 下不碎；1 点细线在 20×4 与 40×1 下易断。建议线宽 **≥2 点列、≥2 点行**；细线图先在预处理阶段加粗。
- **最小特征尺寸**：闭合轮廓外径建议 **≥8–10 方**（40 宽档）；刻度间距 / 格线间距 **≥3–4 点行**；相邻柱体 / 边距 **≥2 点列**，否则并成一块；若图内必须保留小字符，字符高度需 **≥3–4 点行、字宽 ≥2 点列**（实测此尺寸下小字母/数字仍不可辨，故优先改走文字屏）。
- **标签处理建议**：图内小字母、数字（顶点标注、刻度数字、上下标）在点阵中不可读，**不要在点阵里画小字**；标注应改为盲文文字屏（封面 / 独立图例带）或图例页，图形带只留轮廓。
- **分配置降级建议**：
  - 40×4·8：可承载闭合轮廓（圆、方、心、表格、柱图）；曲线 / 标注类仍受限。
  - 20×4：仅适合粗框、大轮廓；细线、斜翼、格内标记降级。
  - 40×1 单行：适合横向长条与可纵向拼读的粗轮廓；曲线、斜边、多分支碎裂，应降级为轮廓示意。
  - 4×3：仅能表达极简大块面，不适合信息图与数学图形。

## 七、入口路径与操作步骤

**代码路径：**

1. 书架 `BookshelfScreen` → 入口按钮「图片转点显」（`BookshelfScreen.kt:130-135`）。
2. `BookshelfController.openStrip()` → `Intent` 起 `com.linxi.brailleback/.tactile.TactileStripActivity`（`BookshelfController.kt:243`；Manifest `:273-277`）。
3. Activity 选图 → IO 线程 `TactileStripSession.build`：解码灰度 → 二值点阵 → 切片 → `stripEmpty` 剔全空带 → 桥接翻译封面/封底（`maxLines` 按屏行数合并字段）→ 成书 → `TactileStripPager` 翻页 → `TactileStripDisplay.show(bytes, label)` 下发点显。

**模拟器复现步骤（本次已走通 UI 起屏）：**

```powershell
$adb = "C:\tools\android-sdk\platform-tools\adb.exe"
& $adb install -r "D:\软件\brailleback盲文\brailleback\build\outputs\apk\debug\brailleback-debug.apk"
& $adb shell am start -n com.linxi.brailleback/.HomeContainerActivity
# 书架点击「图片转点显」；或 root 后直接：
& $adb shell am start -n com.linxi.brailleback/.tactile.TactileStripActivity
```

**注意**：`TactileStripActivity` 为 `exported="false"`，非 root 的 shell `am start` 会被 `SecurityException` 拒绝；正常用户路径是书架内点击。
