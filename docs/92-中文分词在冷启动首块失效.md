# 92 · 中文分词在冷启动首块失效（「没有分词」）

## 现象

用户读 3MB 小说时反馈「现在没有分词，这个好像没有接好」——点显器上的中文盲文词间没有空格，汉字挤成一串。

## 定位

真机日志（`adb logcat -s TranslatorService:V BrailleReader:V`，装包后 `am force-stop` 再冷启打开）：

```
16:15:55.262 W TranslatorService: Chinese table 'zhcn-cbs.ctb' translated WITHOUT segmentation (segmenter not ready yet)
16:16:00.427 I TranslatorService: Braille segmenter ready
```

两个事实叠在一起：

1. `TranslatorService` 的分词器（`JiebaDict` + `BrailleSegmenter`）由 `BrailleSegmenterInit` 线程异步加载，冷启约 4–5 秒才置 `mSegmenterReady`。
2. 阅读器 90 号改成「边翻边读」后，最先上屏的就是这 4–5 秒里翻出来的那一块。于是**用户最先读到的几页正好没分词**，后面虽然分词了，观感已经定死。

`translate()` 里原本只有 `mSegmenterReady` 为真才走 `translateWithSegment`，未就绪就直接 `LibLouisWrapper.translate`，等于整段按字出盲文。

## 改动

`service/.../translate/TranslatorService.java`

- 新增 `mSegmenterInitFailed`（volatile）：初始化线程 catch 到异常、或 `mJiebaDict.isInitialized()` 为 false 时置真。这样失败后不再让每次长文本白等。
- 新增 `SEGMENTER_WAIT_MS = 8000`；`ServiceImpl.awaitSegmenter()` 以 20ms 轮询等到就绪或 deadline。
- `translate()` 在「中文表 + 分词开关开 + 未就绪 + 未失败」时先 `awaitSegmenter()`，成功就走分词路径，超时/失败才落回无分词兜底。
  - **任何长度都等**，不按字符数设门槛：小说里大量段落不足 64 字，按长度卡会把它们继续漏掉；读屏标签在这几秒最多多等几百毫秒到几秒，但结果是正确的。
- 诊断：`translateWithSegment` 前 20 次调用打一行 `segment: in=/out=/spaces=/cells=/head=`（`head` 是头 36 个点位的十进制值，`0` 即空方）。原来那两行打印整段原文的 `SegDebug` Timber 日志会刷屏，已换成这行紧凑日志。

`brailleback/.../BrailleReaderActivity.kt`

- 新增 `MIN_PUBLISH_CHARS = 1_200`：一块至少攒够这么多字才交。否则等待那几秒会把「每 2 秒交一块」的时钟提前打满，第一块只剩一段话（实测一次只有 28 方）上屏，等于给用户一屏近乎空白。

## 验证

冷启（`force-stop` → `am start ... OPEN_URI file:///data/user/0/com.linxi.brailleback/files/book.txt`）：

```
16:24:23.891 I TranslatorService: waited for segmenter before translating
16:24:23.941 D BrailleReader: stream set: len=1704 translated=true
16:24:24.092 D TranslatorService: segment: in=575 out=835 spaces=260 cells=1487 head=0,0,0,0,21,0,12,...
16:25:33.597 D BrailleReader: translate end: paragraphs=12169 chars=3907921 invalidCells=0 failedAt=0 elapsed=74795ms
```

- 第一块就等到了分词器（`waited for segmenter` 之后再铺流），全程再没有 `WITHOUT segmentation`。
- `in=575 / out=835 / spaces=260`：分词确实插入了 260 个词间空格，`cells=1487` ≈ 1.8 方/字符；`head` 里连续的 `0` 就是词间空方——分词落到了盲文输出里，不只是改了个字符串。
- 第一块 1,704 方（约 3 页），整本 12,169 段 / 3,907,921 方 / 无效格 0，用时约 75 秒，位置停在首页不变。
- `gradle :brailleback:testDebugUnitTest :service:testDebugUnitTest` 通过。

## 代价与取舍

- 冷启第一次翻长文本会多等 4–5 秒（等词典加载）。服务已就绪后再翻书无额外开销（`mSegmenterReady` 为真直接走分词）。
- 若词典初始化真的失败（词库文件缺失等），`mSegmenterInitFailed` 一次置真，后续不再等待，直接无分词兜底。
