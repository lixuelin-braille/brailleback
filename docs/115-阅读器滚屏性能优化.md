## 1. 症状与热点定位

阅读器 `BrailleReaderActivity` 正文是一条 `LazyColumn` 焦点流，翻译在后台按 ~2s 一块追加盲文格；用户手指 / 读屏在正文上滚动。定位到四个既定热点：

1. **翻译推进引起的整窗重铺**：`buildWindowSegment` 对 3 页各跑 `screenAt` + `ReaderSourceModel.build`；整份 `uiState` 替换，触发 `LazyColumn` 全量重组；翻译推进路径上还带一次 `scrollToItem(0)`，把用户读到的位置拽回第 1 页。
2. **`onTopSegment` 整份 `uiState.copy(...)`**：滚动字段（页号 / 行号 / 计数）与正文、按钮使能位、字号混在一份状态里，滚一次屏连带两条自绘滑块与按钮区一起重组；`saveProgress()` 每次翻页写一次 SharedPreferences；同页重复重铺还重复向点显器推一屏。
3. **列表 key 用下标**：`itemsIndexed(..., key = { index, _ -> index })`，重铺时内容全变而 key 不变，复用率上不去。
4. **样式与行高度量现造**：`TextStyle` 每次组合 `MaterialTheme.typography.bodyXxx.copy(fontSize = ...)`；`onTextMetrics` 里每次排版回调都重新 `measurer.measure("汉\n汉\n汉")` 测三行平均行高。

## 2. 量化方法

### 2.1 两个场景

| 场景 | 书 | 落定等待 | 动作 | 抓什么 |
|---|---|---|---|---|
| **A 翻译稳定态** | 小书 `perf_base.txt`（150 段中英混排，基线书副本） | 7000ms，等翻译 / 排版跑完 | `dumpsys gfxinfo reset` → 连续 20 次同向 `input swipe 540 1500 540 500 300`，间隔 800ms → `dumpsys gfxinfo` 取汇总与 HISTOGRAM，`framestats` CSV 交叉核对 | janky%（Total frames rendered / Janky frames）、P90、P95、>16.7ms 长帧、>33ms 长帧、总帧数 |
| **B 翻译推进期** | 大书 `perf_c.txt`（4500 段，1,001,489 B，MD5 `146FEBE7F8EC1DCFAE8CAC83F80FBB5D`） | 500ms 后立即开始 | 同上 20 次滑动；滑动窗内有 6–7 个 append 块，抓翻译推进叠加滚动时的卡顿 | 同上 |

### 2.2 口径

- 每场景 **3 遍**，报中位数与 3 遍原始值；swiftshader 噪声大，单次数字不作证据。
- 长帧取汇总 HISTOGRAM：≥17ms 桶计入 `>16.7ms`，≥34ms 桶计入 `>33ms`（全量帧）；CSV 仅滚动缓冲约 120 帧，作交叉核对。
- 测量脚本：`verify/perf/perf_measure.ps1`（场景 / URI / 等待可参）、`verify/perf/parse_gfx.ps1`（汇总 + HISTOGRAM 解析）。
- 冻结基线包：`verify/perf/before/baseline.apk`，68,921,476 B，MD5 `8B2C4E05D9FCEF158D3ABFBBF1E708E0`（主仓库既成包复制固化，防后续重构建覆盖）。

### 2.3 噪声与漂移教训

- 同一份冻结包跨时段复测：原始基线 A janky% 中位数 29.77，`rebase` 33.05，`rb2` 36.05，`rb3` 36.83，`rb4` 39.20——会话内软件光栅整体变慢是单调漂移的。
- 因此单项是否超噪声，必须用**改动包同时段复测的冻结基线**对照（`rebase / rb2 / rb3 / rb4`），不能只对最早一轮原始基线。
- 噪声带宽实测：原始基线 A janky% 三遍极差 1.26pt、B 2.23pt；后续同时段对照 A 三遍极差 3.63pt 左右。janky% 或 P90 变化小于三遍波动幅度、或只省下不到 1 帧，判为噪声内。

## 4. 逐项改动与增量判定

### 4.1 热点 1：翻译推进的整窗重铺与回顶

**尝试一（`h1`，三合一，已回退、未提交）**：起点快照跳过整窗重铺 + 300–500ms 节流合并 + `showPage(resetScroll = false)`。

| 场景 | 对照基线 | h1 中位：总帧 / janky% / >33ms | 判定 |
|---|---|---|---|
| A | `rebase` 705 / 33.05 / 368 | 709 / 32.58 / 370 | 噪声内，无可见改善 |
| B | `rebase` 720 / 32.57 / 361 | 730 / 35.62 / 409 | janky% +3.05pt、>33ms +48 帧，超出基线 B 三遍极差（1.53pt），**反向** |

`h1` 原始值：A 32.58 / 31.15 / 34.34；B 33.39 / 35.62 / 35.65。整体回退。

**尝试二（`h1c`，保留，提交 `5e55ce3`）**：仅保留 `appendBrailleStream` 内 `showPage(resetScroll = false)`——翻译追内容时不再把列表拽回第 1 页；快照跳过与节流合并两项未留。

| 场景 | 对照基线 | h1c 中位：总帧 / janky% / P90 / P95 / >16.7 / >33 |
|---|---|---|
| A | `rebase` 705 / 33.05 / 48 / 53 / 689 / 368 | 707 / 33.29 / 48 / 53 / 692 / 380 |
| B | `rebase` 720 / 32.57 / 48 / 53 / 704 / 361 | 646 / 37.58 / 48 / 53 / 631 / 394 |

- **定性：行为修复，不是性能收益。** A 侧在噪声内持平；B 侧数值上升，但这里 B 工作负载被行为改动本身改变：旧实现每次 append 都回顶，列表浅；新实现保留用户视口位置，深段落进入组合窗，单帧工作量上升，不能在模拟器上把 B 差值归因于回顶改动。
- 定向观测见 §7：翻译连续推进 4 个 append 块期间，页码 / 正文位置保持不变，日志无 `scroll page` 回退事件。
- 源码改动面：`ReaderTranslation.kt` 的 `appendBrailleStream` → `showPage(resetScroll = false)`；`showPage` 增加 `resetScroll` 形参，显式翻页 / 跳行路径仍回顶。

### 4.2 热点 2：状态拆分 + 进度去抖 + 显器按页节流（保留，提交 `ca5da0a`）

**改动**：
- 新增 `ReaderScrollState`（`pageInfo / lineIndex / lineCount / pageIndex / pageCount / scrollToken`），与 `ReaderUiState`（正文、按钮使能位、字号）分开持有；滚屏只推滚动状态，正文列表与按钮区不再随整份状态一起重组。
- `saveProgress()` 改 900ms lifecycleScope 去抖；新增 `flushProgress()`，`onPause` 立即落盘，离开页面不丢进度；进程被强杀时至多丢最近 900ms 偏移（按任务取舍保留去抖）。
- 新增 `pushDisplayThrottled()`：同一页内重复重铺不重复推点显屏；显式翻页、跳行、重连仍直推；重连重置 `lastPushedUnit`。

## 6. 行为等价性：11 步 UI 树比对

### 6.1 比对方法

照 `verify/before/steps.md` 的同一套 11 步动作（冷启动 → 上滑 ×3 → 下滑 ×2 → 点按 / 双击页码滑块 → 点按 / 双击行滑块 → 连续上滑至稳定），在最终包上重放，产物落 `verify/perf/after/`；逐节点比对 `order / content-desc / text / class / bounds / resource-id`。脚本：`collect_after.ps1`、`compare_nodes.ps1`（通用版 `collect_generic.ps1`、`compare_generic.ps1`）。

### 6.2 基线自复测噪声对照（关键控制）

为区分「代码引入的回归」与「模拟器 fling 落定时点噪声」，把**冻结基线包**在同一模拟器上干净复跑一遍（`verify/perf/retest_base/`），与原始 `verify/before/` 逐节点比对。结果：基线包自身两轮之间，step02 / 05 / 06 同样出现「可见段窗口差约 1 段 + 随之增减的换行 TextView 碎片 + 后续节点索引前移」，step05 仅 bounds 行高抖动。**证明这类段窗口差与 bounds 抖动是 swiftshader 下的固有非确定性，不是改动引入。**
