## 二、为什么删

用户明确要求移除「无界书城（Orbit wujie 30）」私有 BLE GATT 支持。该私有协议是早期为这台
ESP32 双模设备单独写的厂商 GATT 旁路；标准 HID/SPP 通路已具备接住该设备的代码路径，私有 GATT
不再需要保留。历史协议取证记录保留在 `docs/10-无界书城BLE协议与实现.md`（文件开头已加废弃标注，
未重命名、未改编号、未改索引位置）。

## 三、该设备后续走哪条通路

### 代码可判

私有 GATT 只是 `connectBluetooth()` 里排在标准 HID/RFCOMM 之前的一条互斥尝试分支，删除后不独占
设备连接机会。AUTO 路由对该设备：

1. 名字命中 `DeviceFinder` 手写表 SPP 条目（driver code `bm` / Baum，正则 `Orbit\s*wujie|wujie`）。
2. `legacyShouldSkipHidByVendor()` 判定跳过标准 Braille HID（固件 HOGP 只声明输入报告、从不推按键，
   历史真机 onInput 0 次）。
3. 直接起 `ReadThread` 经典串口 RFCOMM，由 brltty `bm` 驱动解析，显示与按键都走串口。

对外连接方式仍是三项：Auto / Bluetooth / Wired USB（模拟器连接页选择器实测三项，无第四项）。

### 需真机验证（代码证据不足，未猜）

- 固件 SPP 是否真应答 `bm`（Baum）序列协议、双向（出点 + 按键回传）是否成立，代码侧无法判定，需真机复验。
- 若改走 HOGP：Android 15+ `BrailleDisplayController` 只枚举系统已注册为 HID 输入的设备，
  需在系统蓝牙删旧配对重新配对；且历史实机 HOGP 按键为 0 次。

真机验证方法（待真机空闲后由验证角色执行，本轮未 adb 真机）：

1. 系统蓝牙删除旧配对，显示器开机可被发现，App 协议选 Auto。
2. 过滤日志：`adb logcat -s DisplayService ReadThread DeviceFinder BrlttyWrapper BluetoothConnection`。
3. 期望：跳过 HID → 起 `ReadThread` → DeviceFinder 命中 `bm`；发文本出点、按按键回传 `BrailleInputEvent`。
4. SPP 不通则记录串口错误码与失败阶段；尝试 HOGP 前先系统蓝牙删配对重配，查 `mInputDevices` 是否注册。
