# 104 - 大文件拆分总则与分层

> 日期：2026-11-26
> 目标：给 :brailleback 生产代码的大文件拆分定一套统一口径——阈值、职责判定、落位规则、本轮切法总览与主动保留清单
> 范围：本轮合入阅读器（refactor/reader）、触觉（refactor/tactile）、点显与服务（refactor/display）、导航与输入法（refactor/nav）四群分支

## 需求

基线 `5ace533` 上 :brailleback 生产 Kotlin 文件里，非空行 ≥ 500 的有 13 个，其中 5 个超过 800 非空行。
四群重构分支按同一套手法把其中四组千行大类拆开，主文件只留生命周期、装配编排与协议内核。
本文把这一轮沉淀下来的判定标准、落位规则和保留理由记下来，供后续批次照着执行，避免每批重新争论边界。

## 硬约束（先说清楚）

- **阈值按非空行 800**：与仓库既有拆分契约（`TutorialViewSplitContractTest`、`TactileStripSplitContractTest`）口径一致，
  契约测试断言的是非空行（去掉纯空白行），不是总行数。总行数只做普查参考。
- **纯重构**：对外行为、语义、无障碍节点结构、模块间 API 一律不变；不引入 DI 框架或第三方依赖。
- **方法体逐字搬运**：包括缩进与注释；需要跨文件访问的宿主成员由 `private` 放宽到 `internal`（模块内可见），不改签名。
- **不 squash**：分支内分步提交保留可追溯；合入用 `--no-ff` 留合并提交。
- 既有基线失败（`BrailleExporterTest#fortyByTwentyFiveMatchesBaselineByteForByte`）不在本轮修复范围，见 105~108 各篇验收记录。

## 判定标准

### 800 行阈值

- 生产 `.kt` 非空行 **≥ 800** 列入待拆；500~800 列入观察，不强行拆。
- 测试源集（`src/test`、`src/androidTest`）不参与生产阈值，单独标注。
- 拆出的协作文件也要给小预算（参照触觉护栏：拆出文件各自 < 500 非空行），防止它自己长成新怪兽。

### 什么算「一个职责」

满足三条才算一类，可以独立成文件：

1. **一句话说得清**：文件名能概括这堆代码干什么（导航、翻译、导出、视口平移……）。
2. **共享同一组宿主状态**：读写的是同一批 Activity/管理器字段，不与其他簇交叉。
3. **可独立命名、独立调用**：搬走后调用处按原方法名接线，不需要先理解另一簇的上下文。

不按行数硬切：结构同构、共享同一套校验或回调的几段，即使偏长也留在同一文件（教程手势组、触觉参数组都是这么留的）。

## 落位规则：哪块该放哪

| 代码形态 | 归属 | 写法 |
|:---|:---|:---|
| Composable 函数、UI 状态数据类、对话框状态与弹窗部件 | `compose/` 包下独立文件 | `internal fun XxxScreen(...)`，纯展示，不碰宿主框架 API |
| Activity / Service 生命周期、回调接线、状态装配与对外 API | 留主文件 | 类本体、`onCreate/onDestroy`、匿名监听对象、SAF 启动器、伴生入口 |
| 只读写宿主内部状态的业务闭环（导航、翻译、IO、推送、导出、目录书签、参数档位、视口导航、命令分发、位置映射、覆盖叠加） | 同包协作文件 | `internal fun Host.xxx()` 同包扩展函数，接收方即宿主 |
| 纯函数 / 常量 / 文案 / 档位表 | 独立小文件 | 顶层 `internal val` / `internal data class` / 纯函数，不持有宿主 |
| 协议内核：点位掩码、Handler 消息码、翻译与刷新主链、连接/输入回调覆写、定时器调度、单例与伴生静态入口 | **留主文件** | 与写入通道、线程模型、协议参数绑死，外拆会牵动时序与契约 |

扩展函数看不到宿主的 `private` 成员，因此被访问的字段/方法/常量按需放宽到 `internal`；
伴生常量在扩展文件内以 `Host.CONST` 限定形式引用，不挪出伴生对象。

## 踩过的坑

- 本轮四次合并均为自动合并、无冲突；编译与单测一次通过，没有出现 baseline 失配类的 detekt 回潮（参照 [24](./24-DisplayService拆分.md)、[27](./27-DefaultNavigationMode拆分.md) 记录的 ReturnCount / 循环跳转拦截）。
- 扩展函数访问伴生常量必须写限定名（`BrailleReaderActivity.X`），裸名在扩展文件里解析不到；`TranslatedChunk` 这类只被搬走代码用的嵌套数据类，转为顶层 `internal data class`，避免到处写宿主限定名。

## 代价（已知、明确的）

- 一批宿主字段/方法/常量从 `private` 放宽到 `internal`：模块内可见性扩大，但不暴露到模块外，不改变模块间 API。
- 同包扩展函数在调用处看起来像宿主方法，跨文件追踪时要按文件名找协作文件；命名沿用 `Host + 职责` 后缀（`ReaderPageNavigator`、`DisplayManagerMapping` 等）。

## 验收方式

- 每组合入后跑 `:brailleback:testDebugUnitTest` 与 `:brailleback:assembleDebug`，除既有基线失败外新增失败为 0。
- 合入后做全仓 `*.kt` 行数普查（`git ls-files '*.kt'`），前 15 名留档；确认 :brailleback 生产文件无单文件超 800 非空行。
