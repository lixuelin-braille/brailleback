# 87 · 正文页按键交给点显器

## 为什么要做

86 号让正文在屏时服务冻结文字输出，屏上只剩这一页点位，好处是不再被文字盖；副作用是
**服务也不再翻译界面**，用户在正文页只剩手机触摸一条路翻页。对盲文用户，读一本书时手
本来就在点显器上，每次翻页都要抬手去找屏幕上的按钮，是整条阅读链里最别扭的一步。

81 号已经把「图片转点位」的视口动作挪到点显器按键上，正文页照同一套路做即可。

## 映射

新增纯查表 `reader/ReaderDisplayKey.kt`（`ReaderDisplayAction` 枚举 + `resolve(command)`）：

| 点显器键 | 命令码 | 正文页动作 |
| --- | --- | --- |
| 平移键左 / 右 | `CMD_NAV_PAN_LEFT`(5) / `CMD_NAV_PAN_RIGHT`(6) | 上一行 / 下一行（一行 = 点显器一屏） |
| 上一行 / 下一行键 | `CMD_NAV_LINE_PREVIOUS`(1) / `CMD_NAV_LINE_NEXT`(2) | 上一屏 / 下一屏（整屏翻页） |
| 顶键 / 底键 | `CMD_NAV_TOP`(7) / `CMD_NAV_BOTTOM`(8) | 文首 / 文末 |
| 回车 | `CMD_KEY_ENTER`(70) | 播报当前页码与首行 |
| 其余 | — | 放过（`NONE`） |

「行」沿用阅读器既有的定义：连接点显器时一行就是点显器一屏，未连接时是屏幕上的一行，
所以同一套键在断连后仍然讲得通。

回车接「播报当前页位置」不是凑数：冻结期间屏上没有服务文字，用户需要一个不靠手机确认
「我现在在哪」的手段；这条动作复用 `showPage()` 里已有的播报文案（页码 + 首行）。

## 接线

- `BrailleReaderActivity` 加 `displayKeyListener`（`object : Display.OnInputEventListener`，
  注意这不是 `fun interface`，不能用 lambda 直接构造），在 `onResume` 里随
  `DisplayClient` 一起 `setOnInputEventListener`。
- 回调统一 `runOnUiThread { onDisplayKey(command) }` 再改状态：`DisplayClient` 现在是在
  主线程 handler 上回调，但这层包一次，换线程实现时也不会静默出错。
- `onDisplayKey()` 只做分派，真正翻页仍走 `moveLine()` / `advance()` / `gotoUnit()`，
  所以每次翻页天然经过 `showPage()` → `sendToDisplay()`，点显器内容与页码同步更新。
  文末用 `gotoUnit(Int.MAX_VALUE)`，越界由它自己钳到末屏，不另算页数。

输入事件是服务向**所有**客户端广播的，所以本页自带监听即可拿到按键，不需要服务额外开通道。

## 验证

- `ReaderDisplayKeyTest` 5 例：平移键逐行、上下行键整屏、顶底键首末、回车播报、无关命令码
  （含 0 与负数）放过。
- `:brailleback:compileDebugKotlin`、`:brailleback:testDebugUnitTest`（931 例 0 失败）、
  `:brailleback:lintDebug`（0 error）、`assembleDebug` 全绿；APK 已 `install -r`，
  `dumpsys accessibility` 确认服务仍在绑定列表里。
- **真机待验**：各设备驱动上报的命令码不同（metec 有线 / 无界 BLE 谁报 5/6、谁报 1/2 要逐台
  确认），本次只验证了「同一命令码在本页被正确解释」这一段。
