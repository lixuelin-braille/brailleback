## 1. 链路还原

### 1.1 按键事件进入：两条入口，同一引擎

**宿主在跑**：`DisplayService.broadcastInputEvent` 遍历客户端回调 `onInput`
（`service/.../display/DisplayService.kt:1300-1314`）→ 宿主客户端 `DisplayManager.onInputEvent`
（`brailleback/.../DisplayManager.kt:422-437`）先过按键映射，命中 `NONE` 直接吞掉
（`:429,440-453`，口径见 `docs/49`），其余交 `sendMappedEvent` 进导航链 →
`IMENavigationMode.onMappedInputEvent`（`brailleback/.../IMENavigationMode.kt:128-150`）：
先 `ime.onHardwareInputEvent(...)`（`:139`），未消费再兜底 `ime.handleBrailleKey(...)`（`:148`）。

**无宿主**：`ImeDisplayBridge.onInputEvent` 收到同一广播（`ime/ImeDisplayBridge.kt:120-127`）：
先判 `hostActive()`，宿主在跑 `return`（`:122-124`）；取不到活跃 IME 丢弃（`:125`）；
否则 `ime.onHardwareInputEvent(command, argument)`（`:126`）。

两条路最终都进 `BrailleIME.onHardwareInputEvent`（`BrailleIME.kt:525-562`）；引擎取不到直接
返回 `null`（`:526`），后续累积、回显都不发生。

### 1.2 点位累积：`pendingDots`

字段 `private var pendingDots = 0`（`BrailleIME.kt:170`）；刻意不做「停顿多久算一格」的计时器
（注释 `:164-169`）。`BrailleInputPolicy.route` 分派后（`:527`）：

| 动作 | 代码行 | 累积行为 |
|:--|:--|:--|
| `APPEND_CELL` | `:534` → `accumulateCell` `:581-596` | 见下 |
| `COMMIT`（空格） | `:535-539` | 先 flush 攒点，再 `engine.commit()` |
| `DELETE` | `:540-548` | 攒点阶段只 `clearLastDot` 撤最后一点（`:542-544,612-617`），不动已上屏内容 |
| `ENTER` | `:549-552` | 先 flush，再 `engine.enter()` |
| 上/下候选 | `:553-560` | 先 flush，再切候选 |
| `LEGACY` | `:529-533` | 离开输入语义前先 flush，避免吞点 |

`accumulateCell`（`:581-596`）：多点 chord `bitCount >= 2`（`:582`）→ `mask = pendingDots or cell`、
清零、回显 `mask`（`:584-586`）、立即 `appendCell`（`:587-590`）；单点 →
`pendingDots |= cell`（`:593`）、回显已攒点（`:594`）、返回 `true` 等结清（`:595`）。

`flushPendingDots`（`:599-609`）：`pendingDots == 0` 返回 `null`；否则取 mask、清零、`appendCell`。
清零在引擎结果之前（`:603-607`），上屏失败时攒点已不在缓冲（见 R6）。

### 1.3 DisplayPressEcho：去抖、内容生成、还原

构造接线（`DisplayManager.kt:268`）：
`DisplayPressEcho(displayScope, { display }, { connected && !frozen }, { refresh() })`。
`displayOf` 取当前 `Display?`（`DisplayManager.kt:124`）；`canEcho` 为已连接且未冻结
（`connected` `:138`、`frozen` `:140`）；`restore` 即 `refresh()`（`DisplayManager.kt:916-935`）；
`displayScope` 绑 display HandlerThread looper（`:262-264`），写帧与还原同线程
（类注释 `DisplayPressEcho.kt:22-23`）。

`show(dots)`（`DisplayPressEcho.kt:35-39`）→ `scope.launch { echo(dots) }`。`echo`（`:45-63`）：

1. `displayOf() ?: return`（`:46`）；`canEcho()` 假则返回（`:47-49`）。
2. 取 `numTextCells`，`cells <= 0` 返回（`:50-53`）。
3. `ByteArray(cells)`（`:54`）；`dots != 0` 时 `pattern[0] = dots.toByte()`（`:55-58`），
   位序 bit0=1 点 … bit5=6 点（`:56`）。**只写第一格，其余格填 0**。
4. `displayDots(pattern, "", null)`（`:59`）；`restoreTimer.schedule(1500) { restore() }`（`:60-62`），
   常量 `RESTORE_DELAY_MILLIS = 1500`（`:67`）。

**去抖**：`restoreTimer` 是 `Debouncer`（`:33`）；每次 `schedule` 先 `job?.cancel()` 再起新 Job
（`DisplayTimers.kt:29-35`），连按期间反复重置 1500 ms，安静满才还原一次。`cancel()` 入口
（`DisplayPressEcho.kt:41-43`）主源码**无调用方**；仅关停时 `displayScope.cancel()` 整域取消
（`DisplayManager.kt:283`）。

### 1.4 回显写回与朗读的分工

归属判定在 `BrailleIME.echoPressedDots`（`BrailleIME.kt:571-579`）：宿主 `DisplayManager` 非空
（`:794-796`）→ `manager.showPressedDots(dots)`（`:573-574`）；否则 `imeDisplay?.showPressedDots(dots)`
（`:576-577`）。**点位键本身不触发朗读**；语音来自 EditBuffer：引擎创建时注入
`BrailleCommonTalkBackSpeaker.getInstance()`（`ime/UnifiedBrailleInput.kt:87`），候选/音节由
EditBuffer 经该 speaker 发出。回显（画点）与朗读（speaker）是两条独立路径。

### 1.5 TTS 兜底接管条件

分发 `BrailleCommonTalkBackSpeaker.speak`（`addon/.../BrailleCommonTalkBackSpeaker.kt:67-78`）：
桥非空 → 走读屏桥返回（`:68-71`）；桥空 → 取 `fallbackSpeaker` 调用（`:72-75`）；都空只记日志（`:77`）。

兜底注册：`BrailleIME.onCreate` 里 `setFallbackSpeaker(ImeSpeech)` + `warmUp(this)`
（`BrailleIME.kt:202-203`）；`ImeSpeech` 为 `object` 单例（`ime/ImeSpeech.kt:38`）。桥注入：

接管条件：宿主桥为空；兜底未被 `shutdown` 置空（`ImeSpeech.kt:100`）；文本非空（`:113-115`）。
兜底行为：冷启动 `!ready` 只留**最后一句** `pendingText`，就绪后补播（`:118-121,89-94`）；
`delayMs > 0` 走 `postDelayed` 否则立即执行（`:123-128`）；`utter` 用 `QUEUE_FLUSH` 打断上一句

## 2. 输入法自连点显器

### 2.1 发起组件与时机

发起组件 `ime/ImeDisplayBridge.kt`，内部持一个 `DisplayClient`（`:56,65`）。触发点：
`onStartInputView` → `reconcileImeDisplay()`（`BrailleIME.kt:287,297-313`），每次弹输入区重对齐
（注释 `:294-295`）。规则（`:298-312`）：`hostPresent = getHost() != null`（`:298`）；宿主在 →
`stop()` 并置 `null`（`:299-304`）；宿主不在且 `imeDisplay == null` →
`new ImeDisplayBridge(applicationContext, { getActiveInstance() }, { getHost() != null })` 后 `start()`
（`:306-312`）。宿主引用：服务初始化 `setSingletonHost(newImeNavMode)`（`BrailleBackService.kt:864`），
关停 `setSingletonHost(null)`（`:919`）；`getHost()` 读 `mHost ?: sHost?.get()`（`BrailleIME.kt:786-788`），
`sHost` 弱引用（`:885,893-895`）。

### 2.2 与 DisplayService 的关系：会不会两个消费者抢同一台

`DisplayService` 是普通前台服务 + `IBrailleService` 绑定（非无障碍服务），事件**广播给所有客户端**
（`DisplayService.kt:1300-1314`；模型见 `docs/02` §4.3、`docs/53` §八）。同一台点显器可同时挂两个
客户端：宿主 `DisplayManager` 一个、bridge 一个。硬件连接（brltty/HID/USB）只有一份在
`DisplayService` 侧；两个客户端争的是**事件处理权**，不是独占设备。防双处理两道：启用侧
`reconcileImeDisplay` 宿主在跑不建 bridge（`BrailleIME.kt:299-304`）；事件侧 `onInputEvent` 再判
`hostActive()` 丢弃（`ImeDisplayBridge.kt:122-124`）。残留窗口：对齐只在 `onStartInputView`
（`BrailleIME.kt:287`），宿主在输入区弹出后才启停，bridge 不会立刻建/拆，要等下一次弹输入区，
窗口内靠事件侧守卫（见 R1/R6）。

### 2.3 单实例约束位置

- IME 侧字段唯一：`private var imeDisplay: ImeDisplayBridge? = null`（`BrailleIME.kt:179`），
  建前判 `if (imeDisplay == null)`（`:306`）。
- Bridge 防重入：`start()` 里 `if (client != null) return`（`ImeDisplayBridge.kt:62-64`）。
- IME 实例单例：`sInstance: WeakReference<BrailleIME>?`（`BrailleIME.kt:884`），
  `getActiveInstance()` 取弱引用（`:887-890`），bridge 回调经此取实例（`:309`）。
- `DisplayClient`：`init { doBindService() }`（`client/.../DisplayClient.kt:68-70`），重连最多 5 次、
  首退避 500 ms（`:41-42`，计数 `:252`）。

### 2.4 连不上的降级路径

- 绑定失败/断连：`DisplayClient` 自带 5 次、500 ms 退避（`DisplayClient.kt:41-42,252`）；bridge 只在
  `onConnectionStateChanged` 刷 `connected`/`cellCount`（`ImeDisplayBridge.kt:110-118`），不另做重试。
- 未连接回显丢弃：`!connected || cellCount <= 0` 直接返回（`ImeDisplayBridge.kt:89-92`）；按键仍进
  `onHardwareInputEvent`，只是点显器看不到点位。
- 输入视图降级：`super.onCreateInputView()` 抛 `RuntimeException` 时捕获、置 `fullInputView = false`，
  退回自带提示条（`BrailleIME.kt:337-345`）。
- 引擎不可用：退 `LegacyEditBuffer`（`UnifiedBrailleInput.kt:64-72,99-105`），动作分发不分叉；
  引擎整体取不到返回 `null`（`BrailleIME.kt:526`）。
- TTS 不可用：`warmUp` 回调失败 `tts = null`（`ImeSpeech.kt:61-65`）；之后 `ready` 恒假，句子进
  `pendingText` 不再补播，表现为静默。

## 3. 双键盘并行

### 3.1 形态判定：`fullInputView` 与 `touchKeyboard` 解耦

`onCreateInputView`（`BrailleIME.kt:328-355`）：`mode = readViewMode()`（`:331`，偏好
`pref_single_ime_view_mode`，`SingleImeViewPolicy.kt:24`）；
`touchKeyboard = resolveTouchKeyboardMode(mode, isBrailleDisplayConnected())`（`:332-333`），策略
`MODE_ON→true`、`MODE_OFF→false`、`auto→!displayConnected`（`SingleImeViewPolicy.kt:35-40`）；
`fullInputView = mode != MODE_OFF`（`BrailleIME.kt:336`）——除显式 off 外都挂满屏输入区
（注释 `:334-335`）；`fullInputView` 真才调 `super.onCreateInputView()`（`:337-341`），异常兜底
`:342-345`。生命周期锚点已换成 `fullInputView`：`onStartInputView`（`:282-284`）、
`onFinishInputView`（`:316-318`）。契约测试反向钉死：必须含 `if (fullInputView)`，不许再出现
`if (touchKeyboardEnabled())`（`brailleback/src/test/.../ime/SingleImeRegistrationTest.kt:117-121`）。
注意 `touchKeyboard` 字段现在只喂日志（`BrailleIME.kt:285,358`），真正决定父类生命周期的是
`fullInputView`（`:316,336,361`）。

### 3.2 写入与回显归属

- 引擎归属：两条输入源共用同一 `UnifiedBrailleInput`（`BrailleIME.kt:162,511-516`），同一份
  EditBuffer、同一份候选（注释 `:279-281`；链路图 `UnifiedBrailleInput.kt:4-15`）。
- 硬件写入：宿主路径走 `DisplayManager`，自连路径走 `ImeDisplayBridge`，选择条件即
  `getCurrentDisplayManager() != null`（`BrailleIME.kt:571-579`）。
- 回显归属：`echoPressedDots` 只在硬件事件链路被调（`:574,577`）；屏幕触摸键盘点击**不经过**
  `showPressedDots`，触摸路径没有第一格点位回显。
- 正文写入：宿主侧由 `DisplayManager.setContent/refresh` 管（`DisplayManager.kt:916-935`）；自连侧
  bridge 只在回显/清屏时 `displayDots`，不负责正文排版。

### 3.3 切换时会不会丢回显或串台

- 宿主 ↔ 自连切换：对齐只在 `onStartInputView`（`BrailleIME.kt:287`）；`onFinishInputView` 不 reconcile
  （`:315-322`）。宿主中途出现时旧 bridge 要等下次弹输入区才 `stop()`；反之亦然。窗口内事件由
  `hostActive()` 守卫（`ImeDisplayBridge.kt:122-124`），但回显/写入通道未主动切换。
- 攒点状态：`pendingDots` 在 `onFinishInput`（`BrailleIME.kt:268`）与 `onDestroy`（`:217`）清零；
  切输入框先 `unifiedBraille?.finish()` 落定 composing（`:267`）。切走输入视图本身不清 `pendingDots`。
- 串台面：正文只有一份 EditBuffer，两条键盘不会各上屏一份；串台风险集中在点显器写入通道
  （host DisplayManager 与 bridge 各持一个客户端），见 R1/R4。

## 4. 风险清单

> 成本：**S** ≤1 天；**M** 2–4 天；**L** 1–2 周。「阻塞发布」指不处理不建议出正式包。

### R1 回显重复 / 两套客户端各画一遍 —— M，不阻塞（竞态窗口）

- 行号：广播 `DisplayService.kt:1300-1314`；bridge 守卫 `ImeDisplayBridge.kt:122-124`；对齐时机
  `BrailleIME.kt:287,297-313`；回显分发 `BrailleIME.kt:571-579`。
- 成因：宿主在输入区弹出后才启动，或 `sHost` 弱引用未清理/已回收窗口内，host 与 bridge 客户端同时
  收广播。事件侧 bridge 判 `hostActive()` 丢弃；但若 `getHost()` 瞬时为 `null`
  （`BrailleIME.kt:786-788,885`），`echoPressedDots` 落到 `imeDisplay` 分支（`:577`），与宿主回显并存。
- 盲用户视角：第一格被两套客户端先后写，点位闪烁或刚摸到的点被另一路覆盖；极端情况一个按键在
  引擎进两次（候选/上屏重复）。
- 方向：宿主出现时立即主动 `stop()` bridge，不必等下一次 `onStartInputView`。

### R2 回显丢失 —— S，不阻塞

- 行号：空连接 `DisplayPressEcho.kt:46`；`canEcho` 假 `:47-49`；`cells <= 0` `:50-53`；bridge 未连接
  `ImeDisplayBridge.kt:89-92`；引擎为空 `BrailleIME.kt:526`；LEGACY 不回显 `:529-533`。
- 成因与视角：冻结（暂停态）回显被跳过（`connected && !frozen`，`DisplayManager.kt:268`），按键后
  第一格无触感反馈，误以为没进去；自连侧 `cellCount` 只在状态回调读一次（`ImeDisplayBridge.kt:112-116`），
  设备后报属性/换设备后宽度陈旧，`cells <= 0` 整段静默丢弃；触摸键盘点击从不走回显（§3.2）。
- 方向：被 `canEcho`/`cells` 拒绝时留 VERBOSE 日志便于真机排查。

### R3 回显与光标错位 —— M，不阻塞（建议发版前修）

- 行号：固定写第一格 `DisplayPressEcho.kt:54-58`；bridge 同 `ImeDisplayBridge.kt:93-97`；正文光标排版
  `BrailleIME.kt:625-676`，holdings 区间 `:663-669`。
- 成因：回显永远落第一格，不跟随平移位置与光标格。屏幕已平移（`PAN_CURSOR`，`:671-675`）或编辑格
  不在第一格时，摸到的点在第一格、实际光标在别处；攒点期间 `pendingDots` 画第一格，EditBuffer holdings
  可能落在 composing 区间其他格（`:663-669`）。
- 盲用户视角：摸到的点位位置与光标格不一致，选字/退格按错位次判断。
- 方向：回显格位取光标所在格而非固定格 0；平移态下提示当前格位。

### R4 回显残留（松手后停在旧内容）—— M，**阻塞发布候选**

- 行号：宿主还原 `DisplayPressEcho.kt:60-62` → `refresh()`（`DisplayManager.kt:268,916-935`）；自连还原
  `ImeDisplayBridge.kt:99-107`；`pressEcho.cancel()` 无调用方 `DisplayPressEcho.kt:41-43`；关停
  `DisplayManager.kt:283`。
- 成因（两路）：宿主侧 1500 ms 后 `restore()` 调 `refresh()`，但裁决 `Blocked`（未连接/冻结/运动模式，
  `DisplayManager.kt:919-933`）时不 `doRefresh()`，第一格回显点位留到下次正文变化；自连侧超时 Runnable
  下发全 0 清屏（`ImeDisplayBridge.kt:100-105`），**不还原上一帧正文**——bridge 不持有正文，1.5 秒后
  点显器变空白；`stop()` 只移除 `restoreTask`（`:77-78`）不清屏，最后一组回显点可能留在硬件上。
- 盲用户视角：松手 1.5 秒后旧点位一直压第一格，或整屏空白；再次按键前摸不到正文与光标。
- 方向：自连侧还原回送上一帧缓冲（或触发一次正文刷新）；宿主侧 `Blocked` 解除后补还原；`stop()` 补清屏。

### R5 与 TalkBack 朗读重复或抢话 —— M，**阻塞发布候选**

- 行号：分发 `BrailleCommonTalkBackSpeaker.kt:67-78`；兜底注册 `BrailleIME.kt:202`；兜底打断
  `ImeSpeech.kt:131-135`；宿主桥公告/自带 TTS 降级 `BrailleImeHostBridge.kt:160-194`；桥注入
  `BrailleBackService.kt:634-639`、`addon/.../BrailleIme.kt:226`。
- 成因：兜底只看「本应用桥是否为空」，不看系统里是否真有其他读屏在跑。系统 TalkBack/天坦等在前台公告
  输入框与候选，但本应用桥因初始化异常未注入（`BrailleBackService.kt:641-644` catch 跳过），`ImeSpeech`
  再念一遍 → 两路重叠；`QUEUE_FLUSH` 只打断本引擎（`ImeSpeech.kt:134`），打断不了系统读屏，两引擎并发
  互相覆盖；宿主桥公告投递失败才退自带 TTS（`BrailleImeHostBridge.kt:171-177`），成功与降级间无互斥计数，
  快速连续候选有窄窗口两路出声。
- 盲用户视角：同一候选听两遍，或本应用 TTS 念一半被读屏切断、内容残缺；选字靠听编号，串音直接选错字。
- 方向：兜底前探测外部读屏/触摸探索状态（对照 `docs/53` §一 `AccessibilityMonitor` 思路）；公告与自带
  TTS 路径加互斥。

### R6 断连/重连后回显与攒点状态未清 —— M，不阻塞（需真机回归）

- 行号：bridge 状态回调 `ImeDisplayBridge.kt:110-118`；停止清理 `:72-83`；`pendingDots` 清零点
  `BrailleIME.kt:217,268`；flush 先清零后上屏 `:599-608`；客户端重连 `DisplayClient.kt:41-42,252`。
- 成因：断连时 bridge 除 `restoreTask` 外不清点位状态；`connected=false` 后旧 `cellCount` 保留到下次回调
  （`:112-116`），重连瞬间可能用旧宽度发帧；`pendingDots` 只在 `onFinishInput`/`onDestroy` 清，断连重连、
  切焦点不触发清零；`flushPendingDots` 先清零再调引擎（`:603-607`），`appendCell` 失败时点已从攒点缓冲
  消失，回显却画过这组点，重连后手感与缓冲不一致。
- 盲用户视角：拔插/关机重开后第一格压着断连前旧点；或攒了几个点没上屏，重连后无声丢失。
- 方向：断连回调清 `pendingDots` 与在排回显；flush 改引擎成功后再清缓冲。

### R7 单元格数不足时的截断行为 —— S，不阻塞

- 行号：宽度取自 `numTextCells` `DisplayPressEcho.kt:50-54`；bridge 同 `ImeDisplayBridge.kt:90-93`；
  宽度缓存 `:112-116`。
- 成因：回显只占第一格，自身无多格截断；但回显帧是整屏 `ByteArray(cells)`、其余格填 0
  （`DisplayPressEcho.kt:54-58`）。小格数设备 1500 ms 内看不到上一帧正文；`cells <= 0` 直接放弃回显
  （`:51-53`、`ImeDisplayBridge.kt:90-92`）；bridge 宽度缓存，属性后报不刷新，数组长度与驱动期望格数
  可能不一致。
- 盲用户视角：窄屏设备按键期间正文被回显帧盖住，松手才恢复；异常宽度下无反馈。
- 方向：回显只叠加第一格、保留其余格旧值，不整屏填 0；`cellCount` 跟随属性变化回调刷新。

## 6. 手工回归清单（盲人用户 / 测试者按步骤操作）

> 环境：已配对开机的点显器一台；可开关无障碍服务的测试机。每条写步骤、预期触感（点显器）、预期朗读。

### A. 宿主在跑（无障碍服务开启）

**A1 单点回显**：打开输入框唤起盲文输入区，单独按 1 点。
- 触感：第一格立即抬 1 点；安静约 1.5 秒后回到输入前正文格。
- 朗读：不报点号；候选/音节按既有节奏由读屏播报。

**A2 多点 chord 上屏**：同一输入框同时按 1、2、5 点。
- 触感：第一格显示 125，随即进引擎，1.5 秒内还原。
- 朗读：候选/音节按 EditBuffer 既有播报，无第二路重复念白。

**A3 攒点与攒点阶段退格**：依次按 1 点、2 点（两次单点，不按空格），再按退格一次。
- 触感：第一格先 1 点、再 12 点，不上屏；退格后从 12 撤最后一点剩 1 点，已上屏文字不变。
- 朗读：无点位播报；仅引擎拒绝时出失败提示音。

**A4 空格结清**：接 A3 再按 5 点，然后按空格。
- 触感：攒点 125 作为一格上屏；回显在空格后 1.5 秒内还原。
- 朗读：候选/上屏反馈只念一遍。

**A5 空闲还原**：按一组点位后手离开静置。
- 触感：1.5 秒后回到按键前正文与光标，第一格不留旧点。
- 朗读：静默。

**A6 冻结/暂停态按键**：用既有暂停快捷键冻结点显器，再按 1 点。
- 触感：第一格不叠加 1 点（`canEcho` 拒绝）；解除冻结后正文正常刷新。
- 朗读：无异常报错音。

### B. 无宿主（关闭无障碍服务，输入法单独运行）

**B1 自连建立**：关闭无障碍，回桌面点开输入框唤起本输入法。
- 触感：日志出现「已建立输入法侧点显器连接」（`ImeDisplayBridge` TAG），点显器被 bridge 接管。
- 朗读：候选由系统 TTS（`BrailleImeSpeech` TAG）播报；冷启动首句可能延迟，之后正常。

**B2 自连回显与超时**：按 1 点、3 点两次单点，静置 1.5 秒以上。
- 触感：第一格依次 1 点、13 点；超时后**当前实现为整屏清 0**（`ImeDisplayBridge.kt:100-105`），
  记录与宿主侧「还原正文」的差异（R4），确认旧点不留存。
- 朗读：候选切换有 TTS 播报，不与其他读屏重叠。

**B3 连不上点显器**：关点显器电源，唤起输入框按点位键。
- 触感：点显器无反应（回显在 `!connected` 丢弃，`ImeDisplayBridge.kt:89-92`）；触摸键盘仍可输入。
- 朗读：TTS 候选不受影响；无崩溃、无 ANR。

**B4 冷启动首句**：强停应用后重进输入框，立刻连按出一个候选。
- 触感：点位回显正常。
- 朗读：TTS 未就绪只补播最后一句（`ImeSpeech.kt:118-121`）；记录中间候选句是否丢失。

### C. 双键盘并行

**C1 屏幕键盘 + 点显器同时输入**：偏好 auto、点显器已连接，唤起输入区；先在触摸键盘点按几个点位，再用点显器按一组点位。
- 触感：触摸路径不触发第一格硬件回显；点显器显示正文/候选；硬件回显出现在第一格；两路进同一份候选，
  不两份并行上屏。
- 朗读：候选只由一路播报，无重复。

**C2 宿主中途启动**：先在关闭无障碍状态下唤起输入框（bridge 已连），再从设置开启无障碍。
- 触感：观察 bridge 是否在下一次 `onStartInputView` 让出；窗口期内按键只被宿主处理，不重复上屏
  （记录让位延迟是否可感知，R1）。
- 朗读：桥注入后播报回到读屏通道，兜底 TTS 不再出声。

### D. 断连重连与窄屏

**D1 拔插重连**：输入中拔点显器 USB/蓝牙，5 秒后接回。
- 触感：重连后不残留拔插前旧点；攒点与 EditBuffer 一致（核对 R6）。
- 朗读：重连后候选播报恢复；无旧句堆积重播。

**D2 窄格数设备**：单格/两格机上重复 A1。
- 触感：按键期间回显帧盖住其余格，松手恢复正文；宽度异常时不崩溃（R7）。

**D3 日志核对**：全程 `adb logcat` 过滤 `ImeDisplayBridge`、`BrailleImeSpeech`、`DisplayService`、`BBSpeech`。
- 预期：宿主在跑时 bridge 日志无事件处理记录；TTS 兜底只在桥为空时发声；无 `FATAL EXCEPTION`；
  `onDestroy` 后 `BrailleImeSpeech` 已 shutdown，无引擎泄漏。
