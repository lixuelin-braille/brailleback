## 协议内核主动保留的段落与理由

下列段落与写入通道、刷新闸门、定时器调度或协议参数绑死，外拆会牵动时序与既有契约，因此**留在主文件**：

### `DisplayManager.kt` 保留段落

| 保留段落 | 代表成员 | 保留理由 |
|:---|:---|:---|
| 构造与依赖装配 | 构造参数 `translatorManager`、`context`、各监听回调引用 | 管理器实例化顺序与回调衔接是协议入口，外拆要改构造传参 |
| 连接/输入/表变更回调覆写 | `onConnectionStateChanged`、`onInputEvent`、`onTablesChanged` | 系统/点显器回调覆写必须挂在管理器本体上 |
| DisplayHandler 消息队列 | `MSG_SET_CONTENT/RETRANSLATE/STOP`、`handleMessage`、`pendingContent`、`coalescePending`、`refreshGate` | 消息码、合并闸门与 HandlerThread looper 是刷新时序核心 |
| 翻译与刷新主链 | `handleSetContent`、`handleRetranslate`、`translateCurrentContent`、`updateDisplayedContent`、`refresh`、`doRefresh` | 从内容指纹到点位上屏的主路径，跨多组状态，不宜外拆 |
| 运行时状态与快照 | `runtimeState`、`brailleContent`、`currentContent`、游标/选择集合、`pressEcho`、`wrapStrategy` 状态、`displayed*` 快照 | 刷新主链直接读写，拆分要连带搬状态 |
| 状态入口对外方法 | `setFrozen`/`toggleFrozen`、`setMotionMode`、`setCursorDotsEnabled`、`setPauseClear`、`setIdleClearTimeoutMs`、`sendEmptyCommand`、`showPressedDots`、`isDisplayConnected`、`isSimulatedDisplay`、`toggleBluetoothConnection` | 对外公开签名，调用方按原名引用 |
| 自定义键表 | `applyCustomKeyMap`、`reloadCustomKeyMap`、`customKeyMap` | 事件改写发生在输入汇聚处，与 `onInputEvent` 同层 |
| 遥测线程与统计 | `telemetryThread`、`stats`（`DisplayRefreshStats`）、`refreshGate` | 驱动线程与遥测周期属运行时调度（对照 [34-线程与Handler盘点](./34-线程与Handler盘点.md)） |
| 伴生常量 | 闪烁/防抖/最小间隔/消息码常量 | 与消息队列和刷新时序同文件，避免跨文件限定引用 |

## 调用方怎么接

- **服务侧**：三个接口回调（`onMappedInputEvent`、`onPanLeftOverflow`、`onPanRightOverflow`）仍在服务类内声明，方法体一行转发到对应扩展；公开入口 `runHelp`、`getLabelManager`、`invalidateNode`、`startSearchMode` 与伴生静态入口签名不变。
- **管理器侧**：对外公开签名（`setContent`、`setFrozen`、`toggleFrozen`、`setMotionMode`、`setCursorDotsEnabled`、`setPauseClear`、`setIdleClearTimeoutMs`、`sendEmptyCommand`、`showPressedDots`、`isDisplayConnected`、`isSimulatedDisplay`、`toggleBluetoothConnection`、`shutdown`）与内部监听回调名不变；构造传参与回调衔接方式不变。
- 同包其他文件经放宽后的 `internal` 成员继续可调用；未引入 DI 或第三方依赖。

## 踩过的坑

- 本轮合并自动完成、无冲突；编译与单测一次通过。
- 被搬出函数只做命令路由、协作对象构造释放或文本裁剪，不碰音量手势判定、前台保活、协议参数与无障碍节点结构——边界以「是否读写翻译结果位置表/覆盖帧字节/策略偏好」为准，避免把主链函数误搬到协作文件。

## 代价（已知、明确的）

- 一批依赖引用与字段由 `private` 放宽到 `internal`，模块内可见性扩大，不暴露到模块外。
- 命令分发、依赖装配、事件摘要分属三个服务协作文件；改启动顺序先看 `Assembler`，改按键路由先看 `Dispatcher`。
