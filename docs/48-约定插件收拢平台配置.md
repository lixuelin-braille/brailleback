# 48 · 约定插件：把 11 个模块重复的平台配置收成一份

## 改前

11 个模块的 `build.gradle` 里，同样三行抄了 11 遍：

```groovy
compileSdk = libs.versions.android.compileSdk.get().toInteger()
defaultConfig {
    minSdk = libs.versions.android.minSdk.get().toInteger()
    targetSdk = libs.versions.android.targetSdk.get().toInteger()
}
```

这已经比更早的「裸写 37 / 29」好——版本值集中在 `gradle/libs.versions.toml`。但**读取动作**仍散在 11 处：谁漏抄一次，那个模块就悄悄退回 AGP 默认值，构建照样成功，问题只在运行期或上架时暴露。这正是 `DependencyCatalogContractTest` 当初要挡的事。

## 改后

新增复合构建 `build-logic/`，两个约定插件：

| 插件 id | 文件 | 作用 |
| --- | --- | --- |
| `brailleback.android.library` | `build-logic/src/main/groovy/brailleback.android.library.gradle` | 应用 `com.android.library` + 读目录设三档 SDK |
| `brailleback.android.application` | `build-logic/src/main/groovy/brailleback.android.application.gradle` | 同上，换成 `com.android.application` |

模块脚本里只剩一行：

```groovy
plugins {
    id 'brailleback.android.library'
}

android {
    namespace = 'com.googlecode.eyesfree.utils'
    ...
}
```

`settings.gradle` 加一行 `includeBuild('build-logic')`。删掉的重复行：11 个模块 × 3 行 = **33 行**。

**刻意没有收进约定的**（它们是模块差异，不是约定）：

| 留在模块里 | 为什么 |
| --- | --- |
| `namespace` | 每模块一个，无从统一 |
| `lint { abortOnError }` | 分两档：`brailleback`/`service` 为 `true`（error 即失败），6 个 addon 移植模块为 `false`（只报不拦） |
| `compileOptions` | 只有 6 个模块有；统一加会改变其余模块的字节码目标，属于行为变更 |
| `buildTypes` / `proguardFiles` | proguard 文件名各模块不同（`proguard-rules.pro` / `lib-proguard-rules.txt` / `proguard-project.txt`），是否 minify 也不同 |
| `ndk` / `abiFilters` / `externalNativeBuild` | 只有 `brailleback`、`addon/brailletranslate` 需要 |
| 签名、`applicationId`、版本号、Compose | 只有一个应用模块，收进约定没有意义 |

## 三个必须记住的坑

### 1. 约定插件里不能 `import com.android.build.api.dsl.*`

第一版按 Kotlin DSL 习惯写了 `import com.android.build.api.dsl.LibraryExtension`，并在 `build-logic/build.gradle` 里加了 `implementation libs.android.gradlePlugin`。结果：

```
Could not resolve org.jetbrains.kotlin:kotlin-gradle-plugin-api:2.2.10
> No cached version ... available for offline mode
```

AGP 的 `gradle-api` 传递依赖 `kotlin-gradle-plugin-api:2.2.10`，而本机离线缓存里**没有**这个包（主构建用 AGP 时不需要它，因为插件是运行期解析，不参与编译类路径）。一旦 import，`build-logic` 的编译类路径就要它，整条离线构建直接失败。

解法：**用动态 Groovy**，不引用任何 AGP 类型，`build-logic` 零依赖：

```groovy
def android = extensions.getByName('android')
android.compileSdk = versionOf('android-compileSdk')
android.defaultConfig.minSdk = versionOf('android-minSdk')
```

运行期 AGP 由主构建的 classpath 提供（根脚本 `plugins { alias(...) apply false }` 已经把它挂上了）。

### 2. 约定插件也用 Groovy，不用 Kotlin DSL

主构建 11 个脚本都是 Groovy。为了 3 行配置再引入 `kotlin-dsl` 编译链（Gradle 内嵌 Kotlin 编译、离线包缺失风险、构建变慢）不划算。**约定插件用 Groovy 与模块脚本同语言，DSL 迁移留作独立一批。**

### 3. `service/build.gradle` 是「import 在前、plugins 在后」

`service` 脚本顶部有 9 行 `import org.gradle.api.*`（给自定义任务类 `VerifyNativeLibsUpdated` 用）。Gradle 的规则是 **`plugins {}` 之前不能有其他语句**，但 **`import` 不算语句**——实测写成「import 块 → 注释 → `plugins {}` → `android {}`」可以正常构建。这一点没有官方明文，靠实测确认，写在这里免得下次有人以为必须把 import 挪到后面。

## 契约测试跟着改了两条

改实现不改断言是不行的，但也不能为了让测试变绿而弱化它。两条断言的**语义**做了平移：

| 测试 | 改前 | 改后 |
| --- | --- | --- |
| `DependencyCatalogContractTest.everyModuleTakesSdkLevelsFromTheCatalog` | 每个模块脚本必须含 `libs.versions.android.compileSdk` | 每个模块必须 `id '<约定插件>'`，且**不得**再含三个目录别名、不得出现裸数字 |
| 新增 `sdkLevelsAreDeclaredOnceInTheConventionPlugin` | — | 两个约定脚本都必须读三个目录别名；目录里三档必须是 37 / 37 / 29 |
| `ComposeMigrationContractTest.composeCompilerPluginMatchesBuiltInKotlin` | 断言 `apply plugin: 'org.jetbrains.kotlin.plugin.compose'` | 断言 `id 'org.jetbrains.kotlin.plugin.compose'`（迁到 `plugins {}` 块后的等价写法） |

净效果：不变量从「11 处都必须抄对」收紧成「只有 1 处能定义，其余 11 个模块不许再定义」。
