# 82 - 细节态独占点显器（文字不再盖点位）

- 日期：2026-11-25
- 对应提交：`41505b5`
- 前置：[81](./81-视口按键交给点显器.md)（视口按键交给点显器）

## 1. 现象

点进「查看细节」后，点显器上的点位被文字盖住：每换一屏、每报一次状态，屏上就变成一段字。

## 2. 为什么会有文字

点显器这一屏有两个写入方：

1. **本页**：`TactileStripDisplay` 直接把点位字节下发到 `DisplayClient`；
2. **无障碍服务**：`DisplayManager` 把前台界面的无障碍文本（状态行、设置项、按钮名）翻译成
   盲文往下发。

第 2 条是主路径、随时会触发（Compose 重组、焦点变化、播报都算），一触发就把第 1 条的点位压掉。
所以本质不是「界面不够独立」，而是**两个写入方在抢同一块屏**。

## 3. 为什么不做独立 Activity

独立界面只能减少文本节点，挡不住服务继续写；而且跨界面要重新传图、重新解码、重建视口状态，
返回栈还会断。所以选「同页收屏 + 独占点显器」两手一起做，代价小得多。

## 4. 改动

- `DisplayManager.setFrozen(frozen, clear = mPauseClear)`：新增 `clear` 形参。默认取 `mPauseClear`，
  长按音量键暂停的既有行为完全不变；界面申请独占时传 `clear = false`，避免「冻结顺带清屏」
  把刚画上的点位擦掉。
- `BrailleBackService`：
  - `holdDisplayForApp()`：取 `getActiveInstance()` 的 `DisplayManager`，`setFrozen(true, clear=false)`；
    服务没起、点显器没连返回 false，调用方按「没冻上」处理，不报错。
  - `releaseDisplayForApp()`：`setFrozen(false)`，解冻并让服务按当前焦点重画。
- `TactileStripActivity`：
  - `vpEnterDetail()` 申请独占；`vpBackOverview()` 交还；
  - `onStop()` / `onDestroy()` 兜底交还（否则退到后台服务一直冻着，别的应用摸不到字）；
  - 断线清 `holdingDisplay`，重连时若人还在细节态就重新申请一次；
  - 细节态收成单屏：选图、方数、行数、点数、高级设置整块隐去（`detailMode` 参数），
    只留状态行、返回总览、图例与四个平移按钮。

## 5. 边界

- 只在本应用进程内调服务（同一个包、同一个进程），没有新增跨进程通道。
- 冻结只挡服务侧输出；本页自己的 `displayDots` 照常下发，音量键 / 点显器按键照常可用。
- 解冻会让服务按当前焦点重画一次——回到总览时本来就该看到文字，符合预期。

## 6. 待真机

- 未真机验证：进入细节时点位是否稳定不再被盖；退出后文字是否正常回来。
- 若发现还有第三方应用或通知播报抢屏，可再加一层：细节态期间把本页的 `announce()` 静音，
  只留点显器按键反馈。

## 7. 扩展：整块图形页都独占，不只细节

细节独占做完后回头看，问题不是「细节」这一个态：**只要屏上是点位，文字就会来盖**。
于是把独占面扩到整块图形页：

- 视口三态（总览 / 细节 / 图例）——都是点位；
- 三段式的图形页 —— 也是点位（页签只走 TTS，不写点位字节）。

规则收成一句 `syncDisplayHold()`：`(viewport != null || pager != null) && 连上` 就冻结服务输出，
否则交还。调用点放在 `renderCurrent()` / `renderViewport()` 开头、连接状态回调、`onStop` /
`onDestroy`，避免漏掉某条路径。`vpEnterDetail` / `vpBackOverview` 不再各自申请 / 交还——
申请与交还只跟着「图形页在不在」走，减少两处状态机。

好处：总览态摸图时也不会被状态行文字顶掉；坏处（已知）：冻结期间服务不再翻字，
用户在这页里本来就只摸图，属于预期。
