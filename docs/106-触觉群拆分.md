## 为什么这么切

两条浏览路径（多行三段式、单行视口）各自成体系，状态仍由 Activity 持有：

- **先搬最干净的缝**：纯展示 Composable 与文案收集不碰 Activity 状态和框架 API，先落 `Screen`/`Labels`；
- **再分后台链路**：转换管线与参数变更各自成体系，落 `Pipeline`/`Params`；
- **最后分控制器**：三段式翻页与视口导航分别落 `PagerController`/`ViewportController`，播报文案与点位下发顺序逐字未改。

沿用仓库既有同包 `internal` 扩展函数手法，不引入持有宿主引用的包装类；跨文件访问的字段/辅助方法由 `private` 放宽为 `internal`（模块内可见，不新增对外 API）。

主文件保留：浏览状态字段（`cellsPerLine`、`linesPerScreen`、`dotsPerCell`、`normalizerMode`、`g1SplitCover`、`book`、`pager`、`viewport`、`holdingDisplay` 等）、点显输入监听匿名对象、选图启动器、`onCreate/onStop/onDestroy`、`onConnectionStateChanged`、`onKeyDown`、`showStatus`/`announce`。

## 调用方怎么接

- `onCreate` 的 DEBUG 注入、选图回调与参数回调接线不变；`onKeyDown`、`onConnectionStateChanged` 里的调用不变。
- 被搬走的方法改为同包 `internal` 扩展函数；`onCreate` 的 `setContent` 仍调 `labels()` 与 `StripScreen(...)`。
- Activity 类名、对外签名与 Manifest 注册均不变；同包其他文件经 `internal` 成员继续可调用。
